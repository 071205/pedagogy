# HWP 조판 실험 (베타 — 제품에 연결되어 있지 않음)

## 이게 뭔가

모의고사를 **한글(HWP) 파일로 조판**해 낼 수 있는지 확인하는 실험이다.
`index.html`·`mock-exam-editor.html`·`serve.py` 는 **전혀 건드리지 않는다.**
이 폴더를 통째로 지워도 제품은 그대로 돌아간다.

## 왜 하는가

지금 모의고사 정본은 Typst 로 조판하는데, 실제 시험지 서체(신명 중명조·한양신명조 등)가
상용 글꼴이라 `FONT-LICENSE.md` 의 라이선스 문제가 남아 있다.

한글 파일로 내보내면 이 문제가 **구조적으로** 사라진다:

- 실물 시험지 파일을 조사한 결과 **글꼴이 파일에 포함돼 있지 않다.** 이름으로만 참조한다
  (`신명 중명조`, `한양신명조` …). 글꼴 스트림이 아예 없다.
- 따라서 우리가 만든 `.hwp` 도 글꼴 파일을 담지 않는다. 사용자가 자기 한글로 열면
  자기 컴퓨터에 설치된 글꼴로 조판된다 — **우리는 글꼴을 배포하지 않는다.**
- 덤으로, 줄 나눔·단 나눔을 우리가 계산하지 않고 한글의 조판 엔진에 맡길 수 있다.
  지금 `measureCh()` 로 글자 수를 세어 흉내 내는 근사 조판보다 정확할 여지가 있다.

## 지금까지 확인된 것

실물 시험지(`평가원 국어 양식.hwp`, 3구역·749문단)로 검증했다.

| 항목 | 결과 |
|---|---|
| 레코드 분해 → 재조립이 원본과 바이트까지 동일 | ✅ 3개 구역 전부 |
| 문단 불변식(글자수·구간수·줄수) 이 원본에서 성립 | ✅ 749문단 전부 |
| 길이가 **다른** 글로 문단 바꿔 쓰기 | ✅ 앞뒤 문단·개수 보존 |
| 본문을 통째로 새로 조판 (문항 수가 다른 시험지) | ✅ 용지·단·머리말 틀 보존 |
| 일부러 깨뜨렸을 때 검사가 실제로 실패 | ✅ |

핵심 발견 — `PARA_HEADER` 는 12바이트가 아니라 **24바이트**이고, 뒤쪽에
**직계 자식 레코드의 개수**가 들어 있다:

```
b[12:14] = 직계 PARA_CHAR_SHAPE 구간 수
b[16:18] = 직계 PARA_LINE_SEG   줄 수
```

'직계' 가 핵심이다. 표 안 문단의 레코드는 세지 않는다. 이 개수를 갱신하지 않고
문단을 고치면 한글이 문단을 잘못 읽는다. 실물 749문단 전부에서 이 규칙이 성립하는 것을
확인했고, `selfcheck.py` 가 이걸 불변식으로 검사한다.

## 방향 전환 — HWP(바이너리) 대신 HWPX 를 쓴다

`make_probe.py` 가 만든 `.hwp` 는 **한글에서 깨졌다**(사용자 확인). 바이너리 HWP 는
레코드마다 크기·개수 필드가 있어 하나만 어긋나도 문서 전체가 못 열린다. 위 불변식
검사를 통과해도 그건 '내가 아는 규칙' 만 지킨 것이지, 규격 전체를 지켰다는 뜻이 아니다.

그래서 **HWPX(ZIP + XML)** 로 옮겼다(`make_probe_hwpx.py`).

- 크기·개수 카운터가 없어 조용히 깨질 여지가 적다.
- jakal-hwpx 의 검증기가 HWPX 쪽에 훨씬 두껍다 —
  `strict_validate`, `xml_validation_errors`, `reference_validation_errors`,
  `stale_paragraph_layout_validation_errors`, `strict_lint_errors`.
- 파일이 작다: 같은 내용이 HWP 10MB → **HWPX 5KB**
  (HWP 쪽은 원본 틀·그림을 통째로 안고 갔기 때문이다. HWPX 는 빈 문서에서 새로 만든다.)
- 원본 파일에서 파생되지 않으므로 **저작물 문제도 함께 사라진다.** 가져오는 것은
  글꼴 '이름' 과 용지 치수뿐이고, 둘 다 저작 대상이 아니다.

### 줄 나눔 캐시 — 답이 나왔다

jakal-hwpx 의 진단 문구가 답을 알려 준다:

> "Plain-text paragraph carries linesegarray text positions beyond the text length;
> **Hancom may drop following content.**"

즉 **한글은 낡은 줄 나눔 캐시가 남아 있으면 뒤 내용을 버린다.** 해결책은 캐시를 맞게
고치는 것이 아니라 **아예 넣지 않는 것**이다 — 라이브러리의 `repair_stale_paragraph_layout()`
도 정확히 그렇게 한다(`linesegarray` 를 제거). `make_probe_hwpx.py` 는 처음부터 만들지
않고, 저장 전에 `stale_paragraph_layout_validation_errors()` 로 남은 것이 없는지 확인한다.

`한컴오피스 한글 12.30` 에서 `out/probe.hwpx` 를 열어 눈으로 확인했다.

| 양끝맞춤 조판 | 정상. 실제 시험지처럼 단 폭에 맞춰 줄이 나뉜다 |
| 마지막 문단까지 보존 | 정상 |

| 글꼴 이름 참조 | **작동함** — 서식 도구모음이 지정한 글꼴 이름을 그대로 보여 준다 |

**즉 이 방향은 성립한다.** 우리가 만든 HWPX 를 한글이 정상적으로 열고, 스스로 조판한다.

### 글꼴에 대해 알아낸 것 (중요)

실물 시험지가 쓰는 **`신명 중명조`·`한양신명조` 는 한컴오피스에도 없다.**
한컴 번들 글꼴 110종을 전부 뽑아 확인했고, 한글에서 열면 글꼴 이름 앞에 **빨간 `T`**
(= 이 시스템에 없는 글꼴) 가 붙는다. 신명시스템즈의 별매 상용 글꼴이기 때문이다.

한글은 그런 경우 **문서에는 이름을 그대로 보존한 채 화면 표시만 대체**한다. 이 동작이
우리에게 정확히 유리하다:

- 글꼴을 가진 컴퓨터에서 열면 → 실물과 같은 서체로 조판된다
- 없는 컴퓨터에서 열면 → 한글이 알아서 비슷한 글꼴로 대체해 보여 준다
- **어느 쪽이든 우리는 글꼴 파일을 배포하지 않는다** → 라이선스 문제가 생기지 않는다

기본값은 한컴에 반드시 들어 있는 `함초롬바탕` 으로 두었다
(`mock-exam-editor.html` 도 같은 이유로 함초롬을 폴백으로 쓴다).
신명 글꼴을 구매한 사용자는 `EXAM_FONT` 한 줄만 바꾸면 된다.

```bash
python3 make_probe_hwpx.py    # out/probe.hwpx
```

## 수학 시험지 (2026-08-30 추가)

`2025학년도 수능 수학 문제.hwp` 를 해독해 `make_math_probe.py` 로 재현했고,
**한글에서 열어 확인까지 마쳤다.**

### 해독한 값

| 항목 | 값 |
|---|---|
| 용지 | 272 × 394 mm (국배판) |
| 여백 | 좌 19 · 우 19 · 상 15 · 하 25 · 꼬리말 9 mm |
| 단 | **2단 · 같은 너비 · 단 사이 11.7mm** (구역당 `cold` 1개) |
| 단 폭 | (272 − 19 − 19 − 11.7) ÷ 2 = **111.15mm** |
| 수식 | `eqed` 컨트롤 522개 |
| 글꼴 | 신명·한양 계열 16종 (전부 별매 상용) |

### 수식 — LaTeX 와 개념이 거의 1:1

실물 522개에서 뽑은 어휘:

| HWP 수식 | 뜻 | LaTeX |
|---|---|---|
| `{a} over {b}` | 분수 | `\frac{a}{b}` |
| `sqrt {3} of {5}` | 세제곱근 | `\sqrt[3]{5}` |
| `left ( … right )` | 크기 맞춤 괄호 | `\left( … \right)` |
| `leq` `geq` | ≤ ≥ | `\leq` `\geq` |
| `cases{ A # B }` | 경우 나눔 (`#` 행, `&&` 열) | `\begin{cases}` |
| `sum_{k=1}^{n}` | 합 | `\sum_{k=1}^{n}` |
| `lim _{n rarrow inf }` | 극한 | `\lim_{n \to \infty}` |
| `` ` `` `~` | 공백 | `\,` `\;` |

`HwpxDocument.append_equation(script)` 가 이 스크립트를 그대로 받는다.

### ✅ 한글에서 확인한 결과

`out/math-probe.hwpx` 를 한컴오피스 한글 12.30 에서 열어 눈으로 확인했다.

- **수식 4종 모두 정확히 조판됨** — 거듭제곱근·지수 분수(∛5 × 25^⅓), 부등식 사슬,
  `cases` 의 중괄호 두 줄, `lim`·`Σ` 의 위아래 첨자까지 실물과 같은 모양으로 나온다.
- **2단 조판 적용됨** — `쪽 > 단` 메뉴에 '둘' 체크, 본문이 계산값(111mm)대로 줄바꿈된다.
  ⚠️ 상태표시줄의 `1단` 은 *문서가 1단* 이라는 뜻이 아니라 **커서가 첫째 단에 있다**는 뜻이다.
  이걸 오해해서 한동안 단이 안 먹은 줄 알았다.
- 용지·여백·글꼴 모두 지정한 대로 적용됨.

### ⚠️ 단 정의를 넣을 때 지켜야 하는 것

`<hp:colPr>` 는 `<hp:ctrl>` 로 감싸 **첫 문단의 `<hp:secPr>` 뒤에** 넣어야 한다.
앞에 넣으면 스키마 순서가 어긋나 한글이 조용히 무시한다(실제로 그랬다).

또한 **jakal 의 `.hwp → .hwpx` 변환기는 단 정의를 통째로 잃어버린다.**
변환 결과에는 `colPr` 이 하나도 남지 않으므로, 변환본을 구조 참고용 정본으로 삼으면 안 된다.

## LaTeX → HWP 수식 변환기 (`tex_to_hwp.py`)

모의고사 편집기는 문항을 LaTeX 로 쓰므로, 한글로 내보내려면 변환이 필요하다.
웹 변환기(foreducator 등)가 있지만 외부 서비스에 기대지 않는다 — 오프라인에서도 되어야 하고,
서비스가 사라지면 내보내기가 죽는다.

대응표는 **실물 522개 수식에서 유도**했다(추측이 아니다). `make_e2e_probe.py` 가
LaTeX 로만 쓴 문항 5개를 변환해 시험지를 만들고, 한글에서 다섯 개 모두 정상 조판됨을 확인했다.

```bash
python3 test_tex_to_hwp.py    # 14건 — 실물 수식과 직접 대조
python3 make_e2e_probe.py     # LaTeX → HWPX 끝에서 끝까지
```

### ⚠️ 위·아래 첨자는 반드시 중괄호로 묶어 낸다

LaTeX 의 `x^2-a` 는 x²−a 지만, 그대로 옮기면 HWP 는 `^` 가 뒤를 더 먹어 **x^(2−a)** 로
조판한다. 한글에서 실제로 그렇게 나왔다. 수식이 조용히 다른 뜻이 되는 종류의 버그라
(시험지에서는 곧 오답이다) 예외 없이 `x^{2}-a` 로 묶어 낸다.

### ⚠️ `\left` · `\right` 앞뒤에 공백을 준다

`f\left(` 를 `fleft(` 로 붙여 내면 HWP 가 `fleft` 를 식별자 하나로 읽어 괄호가 사라진다.

### ⚠️ 모르는 명령은 조용히 버리지 않는다

`UnsupportedTex` 를 던진다. 조용히 버리면 시험지에 수식이 **빠진 채로** 인쇄된다.
지원 범위는 모의고사에 실제로 쓰이는 만큼이고, LaTeX 전체가 아니다.

## 검증할 때 알아 둘 것 — 한글은 열려 있는 파일을 다시 읽지 않는다

같은 경로의 파일을 고쳐 다시 `open` 해도, 그 문서가 이미 열려 있으면 **한글은 예전 내용을
그대로 보여 준다.** 이것 때문에 위 첨자 버그를 고치고도 "안 고쳐졌다" 고 한참 오판했다.
확인할 때는 **새 파일 이름으로 저장해서** 열 것.

## 조판 규격은 '적어 두지' 않고 '읽어 온다' (`exam_profile.py`)

처음에는 분석 결과를 손으로 옮겨 상수로 박아 뒀다. 그러다 **발문과 선지의 문단 모양을
서로 바꿔 적었다** — 쓰인 횟수만 보고 배정했는데 실물은 반대였다. 숫자를 사람이 옮기는 한
그런 실수는 또 난다. 그래서 상수를 버리고 **실물 파일에서 그때그때 읽는다.**

```bash
python3 exam_profile.py "2025학년도 수능 수학 문제.hwp"
```
```
조판 규격 출처: 2025학년도 수능 수학 문제.hwp
  문항 번호: 13.5pt 장평95% 자간-5%              (글자 23, 33회)
  발문:      11.5pt 장평95% 자간-4% · LEFT 165% 왼0.00 들여-8.25 아래7.76mm
  선지:      11.5pt 장평95% 자간-5% · JUSTIFY 165% 왼7.76 들여-7.97 아래0.00mm
  이어지는 줄: 11.5pt 장평95% 자간-5% · LEFT 165% 왼8.11 들여0.00 아래8.11mm
```

역할은 **문단의 실제 내용**으로 가린다(사람이 id 를 지정하지 않는다).
`1.` 로 시작하면 발문, `①` 이 있으면 선지, 나머지는 이어지는 줄.

이렇게 하니 좋은 점:

- 옮겨 적다 틀릴 일이 없다 (위의 바꿔 적은 실수가 자동으로 잡혔다)
- **국어·영어·다른 연도 시험지를 넣으면 그 규격이 그대로 따라온다**
- 규격의 출처가 하나뿐이다 — 실물 파일
- 덤으로 **문항 번호가 본문과 다른 서식(13.5pt)** 이라는 것도 저절로 드러났다

참고 파일이 없으면 `exam_profile.FALLBACK` 의 임시값으로 내려가고, 출처에 그렇게 표시한다.
저작물인 실물 `.hwp` 없이도 동작해야 하기 때문이다.

### ⚠️ 문단의 '첫' 글자 모양을 규격으로 삼으면 안 된다

발문의 첫 조각은 **문항 번호**라 본문과 크기가 다르다(13.5pt vs 11.5pt).
첫 조각을 집으면 본문 전체가 번호 크기로 조판된다 — 처음에 실제로 그렇게 뽑혔다.
`_dominant()` 가 문단에서 **가장 넓게 쓰인** 글자 모양을 고른다.

### ⚠️ 레코드 필드 배치 함정

`CHAR_SHAPE` 의 `relSizes` 는 규격서 통념(UINT16×7)과 달리 **UINT8×7** 이다.
UINT16 으로 읽으면 그 뒤 글자 크기가 7바이트 밀려 **6579pt** 같은 값이 나온다(실제로 그랬다).
글자 크기는 offset 42 의 INT32(1/100pt), 줄간격은 `PARA_SHAPE` offset 50 의 UINT32(%) 다.

## 가장 좋은 방법 — 실물 HWPX 를 '틀' 로 쓴다 (`template.py`)

한글에서 **직접 저장한 `.hwpx`** 가 있으면 그것을 통째로 틀로 쓴다. 서식을 우리가 다시
만들지 않으므로, **분석하지 않은 것까지 전부 따라온다.**

```
글자 모양 108 · 문단 모양 52 · 테두리 16 · 탭 12 · 스타일 30 · 머리말(masterpage) 4
```

빈 문서에서 시작하던 예전 방식은 우리가 만든 것만 있었다 — 조건 상자 테두리·머리말·탭
정의가 그래서 빠져 있었다. 틀을 쓰면 그것들이 그냥 있다.

역할(발문·선지·이어지는 줄)은 **틀의 본문 내용으로 판별**한다. 사람이 id 를 지정하지 않는다.

```bash
python3 template.py "평가원 수학 양식.hwpx"
```
```
틀: 평가원 수학 양식.hwpx
  문항 번호: 글자 23  (18회)
  발문: 문단 40·글자 12  (18회)
  선지: 문단 12·글자 0  (14회)
  이어지는 줄: 문단 13·글자 0  (14회)
```

바이너리 `.hwp` 에서 읽은 값과 정확히 같게 나왔다 — 서로 다른 두 경로가 같은 답을 준다.

### ⚠️ 틀은 한글이 직접 저장한 것이어야 한다

프로그램으로 변환하면 **단 정의(`colPr`)가 통째로 사라진다**(jakal 변환에서 실제로 그랬다).
한글이 저장한 것에는 `colCount="2" sameGap="3316"` 이 그대로 있다.

### ⚠️ 틀의 실물 내용은 반드시 지운다 (저작물)

틀에는 실물 문항과 그림이 들어 있다. `clear_body()`·`strip_bindata()` 가 비운다.
여기서 두 번 걸렸다:

- **구역이 여럿이다**(공통·선택). `section0` 만 비우면 `section1` 이 실물 문항과 그림을
  그대로 안고 있어, 지운 그림을 참조하는 깨진 문서가 된다.
- **그림 파일만 지우면 안 된다.** `content.hpf` 의 목록에 참조가 남아
  `manifest references missing part` 로 깨진다. 목록에서도 지워야 한다.

둘 다 라이브러리 검증기가 잡아 줬다(`strict_validate`).

### 틀이 없으면

`exam_profile.py` 가 `.hwp` 에서 값만 읽어 빈 문서에 심는 예전 경로로 내려간다.
그것도 없으면 임시 기본값을 쓰고 출처에 그렇게 표시한다 — 저작물 없이도 동작해야 한다.

## ✅ 완성된 흐름 — 편집기 JSON → 한글 시험지

`mock-exam-editor.html` 의 저장 버튼이 내보내는 `.json` 을 그대로 시험지로 만든다.
**편집기는 한 줄도 고치지 않았다** — 저장한 파일을 넘기기만 하면 된다.

```bash
python3 mock_to_hwpx.py 시험지.json out.hwpx
```

편집기의 예제 문항 6개(`samples/editor-seed.json`, 편집기에서 그대로 뽑은 것)로 확인했다.
문항 6개·수식 59개가 경고 없이 변환되고, 한글에서 열어 확인한 결과:

- 문장 중간 수식(`함수 $f(x)=x^3-8x+7$에 대하여 …`)이 한 줄로 자연스럽게 이어진다
- 별행 수식, 선지 `① ② ③ ④ ⑤`, 배점 `[4점]`, 조건 `(가)(나)`, 선분 윗줄 `AD:DB=3:2`
- 미지원 표기는 **경고로 보고**하고 자리를 남긴다(조용히 빠지지 않는다)

### 이 과정에서 잡은 함정 셋

1. **`append_run_xml()` 은 넘긴 XML 을 `<hp:run>` 으로 한 번 더 감싼다.**
   `<hp:run>…</hp:run>` 을 통째로 넘기면 run 이 중첩되고, 한글은 그 문단의 **뒤쪽 글자를
   통째로 그리지 않는다.** 수식 뒤 한글이 사라지고 선지가 `① 12345` 로 뭉개졌다.
   안쪽 `<hp:t>` 만 넘겨야 한다.
2. **`\{a_n\}` 의 중괄호가 사라진다.** HWP 에서 `{}` 는 묶음 기호라 화면에 안 보인다.
   글자로 찍히는 것은 `lbrace`/`rbrace` 다.
3. **`\displaystyle`·`\limits` 는 무시해야 한다.** LaTeX 의 조판 힌트일 뿐 HWP 에는
   대응물이 없다. 다만 **뜻이 있는 명령을 무시 목록에 넣으면 수식이 조용히 틀려지므로**,
   넣기 전에 '없어도 뜻이 같은가' 를 반드시 확인할 것.

## 아직 손대지 않은 것

- **그림** — 지금은 `[그림 14 · 너비 58mm]` 자리표시만 넣는다. 편집기의 그림 파일을
  Storage 에서 받아 HWPX 안에 넣는 경로가 필요하다.
- **조건 상자 테두리** — `(가)(나)` 가 글로만 나오고 실물처럼 테두리 상자에 들어가지 않는다.
  한 칸짜리 표로 감싸면 될 것으로 보이나 확인하지 않았다.
- **쪽 머리말·꼬리말** (`수학 영역`, 쪽 번호) 과 문항 자동 배치(`breakAfter`, `layout`).
- **제품 UI 연결** — 편집기에 '한글로 내보내기' 단추를 붙이는 일. 파이썬 변환기이므로
  `serve.py` 에 엔드포인트를 두는 방식이 기존 `/render` 와 결이 같다.
- 한 문단 안에 굵게/밑줄이 섞인 경우의 글자모양 구간 경계 (`hwpdoc.py` 쪽)

실물 시험지는 양끝맞춤을 위해 한 문단에 글자모양 구간을 8개까지 나눠 자간을 손으로
조정해 두었다. 우리는 문단 전체를 한 구간으로 두고 한글의 양끝맞춤에 맡긴다.

## 실행

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

python3 selfcheck.py    # 구조 자체 검사 (원본 HWP 가 있어야 함)
python3 make_probe.py   # 한글로 열어 볼 실험 파일 생성
```

실물 시험지 `.hwp` 는 저작물이라 저장소에 넣지 않는다(`.gitignore`). 없으면 검사를
건너뛴다. 생성물(`out/`)도 원본의 틀·그림을 그대로 품으므로 함께 무시한다.
