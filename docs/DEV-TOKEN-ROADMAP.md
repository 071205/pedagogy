## 이전 위치 — R3 왕복 2회

- **R3 1차(크기)·2차(충돌·부분 실패) 합의**는 [문제 투입 설계 §20·§21](PROBLEM-INTAKE-DESIGN.md).

  ⚠️ **재현하지 않았다**(코드 확인) — 그래서 이슈로 등록하지 않았다. 재현 절차가 다음 몫이다.

  없으므로 **owner 별 로컬 동기화 메타데이터가 새로 필요하다.**

  필요하고 구 규칙은 새 필드를 거부한다. **`libraryCloudSchema`·`mockCloudSchema` 선례**대로
  전환 규칙 → 클라이언트 배포 → 엄격 규칙 순서로 간다.
- ⚠️ **미합의 하나**: **서버 attempt ledger 없이 "성공한 쪽을 재호출하지 않음" 을 보장할 수 없다.**

## 모델 전환과 토큰 사용 규칙

배정은 이 저장소의 위험과 작업 크기에 대한 판단이다. 공식 모델 설명의 비용·성능 구분을 참고했으며
API 가격 비율을 Codex 구독 사용량 절감률로 환산하지 않는다.
[OpenAI 모델 안내](https://developers.openai.com/api/docs/models).

| 모델·추론 | 맡길 일 | 맡기지 않을 판단 |
| --- | --- | --- |
| GPT-5.6 Luna / high | 이미 판정된 스타일 수정, 링크·표·결과 집계, 수정 전후 finding ID 대조 | 오탐 판정, 인증·저장·CSP 의미 변경, 복잡도 일괄 분해 |
| GPT-5.6 Terra / medium | 확정 계약의 보통 구현, 기존 검사 실행·실패 분류, 환경 준비·관측 자료 정리 | 근거 없는 공급자 채택·충돌 정책·출시 승인 |
| GPT-5.6 Sol / high | 보안 경계 진단·수정, 저장·결제의 까다로운 구현 | 제품 정책·가격·외부 계정 결정을 사용자 대신 확정 |
| GPT-5.6 Sol / medium | 다른 구현자의 diff와 증거를 독립 검토 | 같은 작업을 모델만 바꿔 독립 검토했다고 표시 |
| GPT-6 Astra / high | 저장 계약·제품 범위·비용 정책·상충하는 설계 결정 | 반복 집계·일괄 스타일 정리·통과한 검사 재실행 |

- 사용자가 모델을 전환한다. 자동으로 다른 작업/에이전트를 만들지 않는다.
- 한 요청의 기본 단위는 **현재 단계의 한 작업 묶음**이다. 권장 모델 차이만으로 진행을 막지는 않되,
  다음 단계에서 더 싼 모델로 충분하면 현재 단계 인계를 끝내고 전환 문구를 준다.
- 먼저 현재 위치·해당 행·연결된 코드만 읽는다. 이전 인계 전체, archive, 다른 단계 문서를 매번 읽지 않는다.
- 관련 검사는 변경 묶음 뒤 1회. 성공 결과에는 커밋·환경·실행/skip을 기록하고 변경 없는 검사는 재사용한다.
  같은 실패를 새 가설 없이 재시도하지 않는다. 출력은 로그에서 종료 코드·실패 주변만 읽는다.
- 필요 이상의 테스트를 새로 만들지 않는다. 기능 수정은 AGENTS의 regression-test.html 의무를 지키고,
  추가·수정 회귀에는 실제 실패 주입을 수행한다.
- 계정 사용량을 시작과 단계 경계에서 확인한다. **잔여 20%부터 범위를 고정, 10%부터 기록·검증 정리,
  5% 도달 전 종료**를 목표로 한다. 소진을 기다리거나 실패한 외부 상태를 반복 조회하지 않는다.
  이는 운영 기준이며 토큰 소모를 정확히 보장하는 한도 장치는 아니다.
- 독립 검토는 구현자와 다른 검토 주체가 맡는다. 사용자에게 다른 검토 작업을 넘길 문구를 제공하고,
  승인한 동일 diff를 다시 심사하지 않는다. 자기검증은 자기검증으로 기록한다.

### R1 — 지금 바로 할 일

시작 자료: HANDOFF-150·151, `serve.py`, `.sonarcloud.properties`,
`scripts/build-public.mjs`, CSP 관련 HTML·검사. 전체 저장소 재감사는 하지 않는다.

1. 최신 Sonar 분석의 revision·미해결 ID·Quality Gate 실패 조건을 확보한다.
   Standard BUG/CODE_SMELL과 MQR 품질 impact를 같은 감소율로 비교하지 않는다.
2. 실제 Pages/호스트의 배포 source와 응답 정책을 확인한다. 루트 HTML을 서비스하면
   `dist/public`의 강화된 script CSP가 적용됐다고 주장할 수 없다.
3. `Handler._send`의 모든 호출부와 taint flow에서 MIME·헤더·응답 종류를 대조한다.
   ZIP 응답에는 attachment와 nosniff를 보존하며, HTML 문자열 escape로 바이너리를 손상시키지 않는다.
4. CSP 7건의 unsafe-inline과 wildcard를 실제 필요한 script/style/connect 출처와 대조한다.
   script와 style, 로컬 HTML과 공개 산출물을 구분하고 로그인·App Check·iframe·인쇄를 보존한다.
5. HTTP 3건은 loopback과 LAN을 나눠 전제·노출·실제 사용 경로를 평가한다.
   위험을 확인하면 수정하고 의도된 설계는 근거를 기록한다.
6. `experiments/hwp-export` 중 `serve.py`가 실행하는 변환기와 로컬 CLI/test를 구분해
   분석 범위를 보완한다. 새 이슈가 생기면 중요도별로 이 레일에 반영한다.
7. 완료: 각 보안 finding이 수정/근거 있는 오탐/수용 위험/미해결 중 어디에 속하는지
   코드·검증 근거를 갖춘다. 전수 재현 없이 ‘93% 오탐 제거’라고 쓰지 않는다.
   Sonar 상태 변경은 근거와 대상 ID를 기록하며 `NOSONAR`나 폴더 제외로 해결을 대신하지 않는다.

관련 검증은 보안 표적·public/CSP·필수 회귀를 선택한다. 변경 없으면 기존 성공 검사를 재사용한다.
원격 반영은 하나의 변경 묶음으로 마친 뒤 분석 완료를 확인한다. 반복 push로 분석을 다시 시작하지 않는다.
이미 push한 커밋의 문서 후속은 **새 커밋**으로 남긴다. published commit amend/force push를 기본 절차로 삼지 않는다.

### R2·R3·R4 — 제품 범위와 데이터 안전성

- [문제 투입 설계](PROBLEM-INTAKE-DESIGN.md)의 네 가지 요구(여러 파일·PDF·사용자 지시·배치)를

  권장 출발점은 현 편집/출력의 안전성을 먼저 완성하고, 다중 입력은 별도 승인된 범위로 추가하는 것이다.
- PDF/다중 입력을 이번 출시 필수로 사용자가 선택하면 R2에서 파일·쪽/크기 상한, 검토 후 채택,
  취소·부분 성공·중복/재시도 비용, 권리 확보 자료 조건을 고정하고 C3·R9의 한도 정책을 다시 맞춘다.
  원본 비용 문서의 ‘1회 약 10원’은 일반 단가나 새 경로의 예산으로 사용하지 않는다.
- R3는 기존 owner별 캐시·tombstone·불변 ACK·epoch와 900KiB 모의고사 방어를 재사용한다.
  문제집 크기 사전 방어, 서버 revision/CAS 등 최소 충돌 검출, 충돌 사본·export를 설계한다.
  시각만 서버 시각으로 바꾸는 것은 충돌 해결이 아니다.
- R4는 저장 완료 표시를 실제 성공/ACK와 연결하고, 실패 시 원본과 복구본을 보존한다.
  백업 복구는 격리 자료로 확인하고 담당자·RPO/RTO·복구 절차를 남긴다.
- IndexedDB/PWA/CRDT/subcollection 일괄 전환은 필수 선결정이 아니다.
  대표 자료의 실제 제약으로 필요성이 확인될 때만 R3의 별도 설계로 채택한다.

### R6·R7·R8 — 필요한 검증과 운영 증거

- R6: 같은 커밋의 CI 결과가 있으면 먼저 재사용한다. git 전체 이력 secret scanner는 최초 기준선 1회,
  이후 변경분 위주로 실행하고 원문 대신 redacted 위치·종류만 기록한다.
  npm audit뿐 아니라 실제 Python 변환기 의존성·CDN/SRI·firebase-tools/wrangler 고정 상태를 확인한다.
  ‘npm audit 0’은 전체 공급망 안전 증명이 아니다.
- R7: [보안 설계](SECURITY-ARCHITECTURE.md)와 [운영 체크리스트](SECURITY-OPERATIONS-CHECKLIST.md)에
  실제 자원별 증적을 남긴다. 새 호스트 정상·동일 public 산출물·구 origin export/import 확인 후
  Pages/private source 이전을 진행한다. 현재 무료 Pages/private 조합의 과거 404 사고를 보존한다.
  Worker와 Firestore/Storage App Check 각각 정상 발급·거절·monitor→enforce·rollback을 확인한다.
- R8: 로그인→가져오기/편집→저장→승인된 AI→인쇄/HWPX→재로그인/복구 여정을 검증한다.
  REV-075 실계정 복귀 문제를 여기서 재현/미재현 증거로 처리한다. REV-074는 실제 Git/CI를 막을 때만 재조사한다.
  로컬 deterministic 실패 주입으로 오프라인·저장 거절·큰 입력·취소·quota 경합을 우선 확인한다.
- 실제 DO 동시성·자정/재시작·kill switch는 격리 staging에서 AI 공급자 stub/차단을 이용해 검사한다.
  운영 50~100명 부하를 기본 실행하지 않는다. 필요한 용량 목표·측정 항목·중단 기준이 있을 때만 확대한다.
- ZAP 등 능동 스캔은 소유·승인된 대상/경로/요청량으로 제한한다. 외부 유료 호출과 실사용자 쓰기를
  유발할 수 있는 검사는 별도 범위가 필요하다. 이번 레일 작성은 실제 공격·부하 실행 승인이 아니다.
- 제품 관측은 저장 실패/충돌·AI·내보내기 성공을 최소 메타데이터로 확인한다.
  원문·UID·토큰을 수집하지 않으며 기존 ai_usage만으로 리텐션을 추정하지 않는다.
