# 법정 기재사항 대조표

⚠️ **이 문서는 법률 자문이 아니다.** 법령이 요구하는 항목이 문서에 **있는지**를 대조한
체크리스트이고, 그 표현이 개별 분쟁에서 충분한지는 판단하지 않는다. 실제 요금을 받기
시작하면 전문가 검토를 한 번은 받는 것이 맞다. 특히 운영자 정보와 Firebase·Cloudflare의
실제 계약·처리 위치는 코드만으로 확정할 수 없어 출시 전 확인이 남아 있다.

## 3. 아직 사람이 해야 하는 것 (코드로 못 끝낸다)

1. **`legal.html` 의 노란 항목** — 상호·대표자·주소·이메일·개인정보 보호책임자.
2. **유료화 시점에 확인할 것** — 운영 형태·매출·판매 방식에 따른 사업자등록·통신판매업
   신고 및 표시 의무, 결제 화면의 청약철회·환불 기준 사전 고지.
   `legal.html#operator` 에 자리를 만들어 두었다.
3. **개인정보 보호책임자 지정** — 실제 사업자 형태에 맞는 책임자·연락처를 확정한다.
4. `service-config.js` 의 `legalVersion`·`supportEmail`.

## 4. 검사가 지키는 것

`check:static` 이 세 가지를 본다 — **사람이 지우거나 잊는 것을 막는 장치다.**

1. 방침에 위 표의 **법정 항목이 전부 있는가**(제목 문구로 확인).
2. `index.html` 의 `CONSENT_VERSION` 과 `legal.html` 의 문서 버전이 **같은가** —
   약관을 고치고 동의 버전을 안 올리면 "무엇에 동의했는지" 를 말할 수 없다.
3. 동의 창이 **필수 항목 네 개를 모두** 받고, 로그인 국외이전과 선택적 AI 전송을
   한 항목으로 묶지 않는가.

현재 Firestore의 동의 문서는 이용자 본인이 수정할 수 있고 클라이언트 시각을 사용한다.
따라서 이는 이용자 선택을 복원하는 운영 기록이지 불변의 법적 증적이 아니다. 유료 출시 전에는
서버 시각, 정책 원문 또는 해시, 동의 철회 이력을 조작 방지 저장소에 남기는 방식을 별도로 설계한다.
