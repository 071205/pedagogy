# PEDAGOGY AI 비용 개선 진행 기준

이 문서는 사용자가 승인한 진행 기준 설계다. 실제 코드·검사 결과와 함께 사용하며,
AGENTS.md와 공동 리뷰 의무를 대체하지 않는다. 작성: 2026-09-13, 검토 기준 커밋: `eb120d2`.
모델을 바꾼 뒤 사용자는 **“비용 개선 레일대로 다음 단계 진행해”**라고만 요청하면 된다.

## 현재 위치 — 다음 작업자는 여기부터

- 현재 단계: **B / 시작 가능**. A의 로그 회귀 보강을 독립 검토한다.
- 추천 실행 모델: **GPT-5.6 Sol · medium**. 재현되는 결함만 A로 돌려보낸다.
- 원래 6번: AGENTS.md 효율 규칙 완료·검토 완료(HANDOFF-123).
- 원래 1번: 측정 코드 구현 및 누락 수정 완료(HANDOFF-124·125). 재검토의 20개 가짜 공급자
  응답에서 토큰 보존·이벤트 1회·원문 비노출 통과. A에서 문서 프롬프트 누출 검사를 보강했다.
- 현재 배포/실호출 승인: **없음**. 운영 측정 시작·추가 API 비용 발생으로 표시하지 않는다.
- 새 공급자 연결, 출력 한도 조정, 프런트 분리는 미착수. 이 문서 작성은 착수 승인이 아니다.
- 기준 워킹 트리의 `transcript.txt`는 사용자 미추적 파일이다. 커밋·삭제하지 않는다.

## 이어받는 방법

1. AGENTS.md, reviews/README.md, 이 문서의 현재 위치, INDEX의 열린 이슈를 확인한다.
   전체 과거 인계 대신 현재 단계의 연결 문서와 실제 관련 diff만 읽는다.
2. 사용자가 레일 진행을 요청하면 현재의 시작 가능한 **한 단계**를 완료한다. 단계의 구현·관련
   회귀·실패 주입·기록을 하나로 묶고, 모델 변경이 필요하면 완료한 경계에서 인계한다.
   코드 자체 결함이 재현되지 않으면 검토를 이유로 제품 코드를 고치지 않는다.
3. 이미 통과한 검사는 코드·관련 환경·의존성 변경이나 새로운 실패 근거가 없으면 반복하지 않는다.
   결함 검토는 재현 가능한 근거로 판정한다. 자신이 만든 수정의 자체 검사를 독립 승인으로 쓰지 않는다.
4. 완료 시 아래 진행표, 현재 위치와 마지막 인계 링크를 함께 갱신한다. 구현이면 새 인계 작성,
   리뷰만이면 대상 인계에 결과 추가. 재현 이슈는 같은 파일에 해결 근거를 기록한다.
5. 외부 승인이 필요하면 대상 환경·변경 diff·검증 결과·롤백·최대 호출/비용을 먼저 구체화해
   한 번에 요청한다. 이미 받은 해당 승인은 재사용한다. 키와 사용자 원문은 기록에 복사하지 않는다.
6. 표본이나 접근권한이 없어 막힌 단계는 `대기`와 조건을 적는다. 같은 검사·유료 호출을 반복하지
   않는다. 매번 “다음에 무엇을 할까요” 대신 **다음 단계 ID·추천 모델·실행 또는 대기 이유**를 보고한다.
   사용자 요청 없이 작업 예약·모델 자동 전환·하위 에이전트 생성은 하지 않는다.

## A — 완료 기록

관련: [090 이슈](../reviews/issues/2026-09/2026-09-13-tests-ai-console-coverage-gap.md),
[125 인계](../reviews/handoffs/2026-09/2026-09-13-worker-ai-usage-observability-followup.md),
[재현 도구](../reviews/audits/2026-09-13/worker-telemetry-review.mjs).

주 대상은 `worker/worker-contract.test.mjs`였고 제품 로직은 바꾸지 않았다. 현재 문제는 제품에서
개인정보가 실제로 유출된 것이 아니라 그 유출을 가정한 코드 변이를 검사가 놓친다는 점이었다.

- 문항·문서 20개 가짜 공급자 경계와 기본 createWorker/console 경계를 연결했다. 사용량 있는 응답은
  토큰·stop_reason을 보존하고, 없는 응답은 null, 이벤트 1회와 reserve→consume를 단언한다.
- 이미지·문서 프롬프트·AI 본문·UID·인증 토큰·오류 표식을 전체 console 메서드에서 제외하고,
  logger 실패가 성공 응답을 502로 바꾸지 않는지 확인한다.
- 메모리 소스 변이의 문서 prompt, 이미지, 공급자 응답, UID 로그가 모두 AssertionError로 실패하며
  baseline은 통과한다. import·문법 실패를 검출로 인정하지 않는다.
- `npm run test:worker`에 검사를 연결했고 090을 resolved로 닫았다. 결과: HANDOFF-127.

## B — 검토 반복을 끝내는 조건

A의 변경 diff와 증거만 독립 확인한다. 원문 표식이 실제 제품 입력/응답에 전달되는지, default logger를
테스트가 우회하지 않는지, 누출 변이로 정말 실패하는지 확인한다. 기준 충족이면 승인하고 C로 이동한다.
승인된 동일 diff를 모델만 바꾸어 계속 재검토하지 않는다. 새 재현 결함이면 해당 항목만 A로 반환한다.

## C·D — 실제 수집까지의 경계

C에서는 [운영 런북](OPERATIONS-RUNBOOK.md)과 [운영 증적](SECURITY-OPERATIONS-CHECKLIST.md)의
배포 요구를 먼저 확인한다. 기존 검사 결과는 해당 커밋·환경에 유효한지 확인해 재사용한다.
실제 배포본과 로컬 코드의 차이를 확인하고, 과거 보안 변경 전체가 함께 나가는지 숨기지 않는다.
staging/production 대상, bindings·모델·현재 샘플률, 테스트 자료, 롤백 버전, 실행할 유료 호출 수와
예상 최대 비용을 제시한다. 실제 키 값을 읽어 출력하거나 테스트 환경을 임의 생성하지 않는다.

D는 해당 배포/실호출 승인이 있을 때만 진행한다. 개인정보 없는 합성 이미지·문서로 두 경로를
확인하고 승인된 횟수 내에서 끝낸다. 운영 로그는 기존 설정상 10% 요청 표본이다. 한두 번의 성공 호출에
로그가 없을 수 있으므로 추가 호출을 무한 반복하지 않는다. staging의 일시적 샘플률 조정이나 실시간
로그 사용은 실제 도구 경계·원문 포함 여부를 확인해 승인 묶음에 명시한다. 운영 100% 수집으로 몰래 올리지 않는다.
로컬 단언이 보장하는 이벤트 1회와 플랫폼이 저장하는 표본을 구별한다. 생산 배포는 별도 대상 승인 후 실행한다.
표본 설정 복원·버전·확인 결과를 기록해야 D 완료다. 전체 서비스 출시 완료 선언은 이 레일의 범위가 아니다.

## E·F — 데이터가 실제 절약 판단을 뒷받침할 때

E는 개인 식별자가 없는 메타데이터로 작업별 총 표본 수·성공/실패 수·토큰 미확인 건수,
입출력 토큰 중앙값/p95, max_tokens 중단 비율, 응답 시간과 관찰 기간·모델·샘플률을 보고한다.
성공 표본만 모으면 실패 비용이 빠지므로 실패도 포함한다. 이전 답변의 30~50건은 탐색 시작 정도이며
신뢰할 만한 p95나 낮은 실패율을 보장하는 기준이 아니다. 불확실하면 자료 부족으로 유지한다.
표본 총합을 청구액으로 쓰거나 누락 토큰을 0으로 간주하지 않는다. 현재 이벤트에는 재시도 연결 ID가
없고 Worker가 자동 재시도하지 않으므로 사용자 재시도별 비용은 직접 계산할 수 없다. 추적 기능을 임의 추가하지 않는다.

F는 max_tokens를 낮추기 자체가 목표가 아니다. 출력 상한은 선결제량이 아니므로 같은 응답 길이면
절약이 없을 수 있고, 잘림으로 재시도가 늘면 손해일 수 있다. 대표 합성 표본의 전후 출력 완전성·문항
정확도·JSON 성공률·실패 포함 비용을 함께 본다. 관측 근거가 없거나 순이익이 없으면 **4096 유지**로
판단 단계를 완료한다. 변경이 정당하면 두 작업의 상한만 분리하고 quota·프롬프트·공급자를 동시에 바꾸지 않는다.
실호출 검증은 별도 예산 승인 범위에서 진행한다.

## G·H — 필요성이 입증된 경우만 공급자 확대

G의 실행 전에 현재 계약·입력 보존·학습 이용·삭제·처리 위치 등 프로젝트의 개인정보 조건을 후보별로
확인한다. 개인 데이터는 적격 판정 이전에 전송하지 않는다. 비교용 시험지는 합성/권리 확보된 동일
표본으로 하고, 이미지 입력 지원·문항/수식 정확도·JSON 성공률·속도·실패/재시도 포함 비용을 비교한다.
기준 정답과 채점법을 먼저 고정하고 모델 ID·가격·시점을 남긴다. 가입·계약·키 발급·유료 호출은 승인된
후보/예산에 한정한다. 이름이나 과거 가격만으로 Gemini·DeepSeek를 채택하지 않는다.

H는 개인정보 적격성과 순이익이 입증되고 사용자가 연결을 승인한 후보 하나만 Worker 내부에 붙인다.
외부 반환 JSON·인증·quota·안전 로그 계약을 유지하며 기존 Anthropic으로 복귀할 수 있게 한다.
자동 재시도·자동 fallback으로 두 공급자 비용이 동시에 발생하는 기능은 별도 판단 없이 넣지 않는다.
이득이 없으면 G에서 현 공급자 유지로 종료하고 H는 생략한다.

## I — 개발 작업량 절약은 별도 판단

이 레일의 1~4번은 **사이트 내부 API 비용**을 다룬다. Codex 사용량은 6번 규칙·작업 범위·모델 배정에
영향받으며, Worker 토큰 계측으로 Codex 사용량을 측정하거나 절약했다고 주장하지 않는다.
프런트 분리는 공급자 변경과 독립적이다. 필요하면 사용자가 I를 선택한 후 현재 저장·인증·렌더 경계와
전역/로딩 순서를 조사해 작은 추출 하나로 설계한다. file:// 제약을 확인하기 전 ESM을 강제하지 않는다.
단계마다 Chromium·Firefox·WebKit, file://, 저장·인증·편집·인쇄 중 영향 경로의 회귀와 실패 주입을 유지한다.
검사 근거가 없으면 다음 파일 분리로 넘어가지 않는다. 분리만으로 토큰 90% 절감을 보장하지 않는다.
