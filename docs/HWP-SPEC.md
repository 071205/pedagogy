# 한글 문서 파일 형식 — 규격서 출처와 우리가 쓰는 범위

## 왜 이 문서가 있나

HWPX 조판을 오래 **추측으로** 만들었다. `tex_to_hwp.py` 의 LaTeX→한글 수식 대응표는
실물 시험지 522개 수식에서 역으로 유도한 것이었고, 빈 문서 골격은 다른 라이브러리 구조를
보고 흉내 낸 것이었다. 둘 다 실제로 틀린 곳이 있었다(아래 '규격서로 잡은 오류').

**규격이 공개돼 있다.** 추측할 이유가 없다.

### HWPX(OWPML) 문서 구조 자체 — **확보함**

**KS X 6101 국가표준**이다(한컴 독자 포맷이 아니다).
제정 2011-12-30 · 최종개정 **2024-10-30** · 담당 과학기술정보통신부 국립전파연구원.

e-나라표준인증의 **'기계가독 원문'** 을 무료로 볼 수 있다. 화면은 JS 로 비동기 로드하므로
데이터 API 를 직접 부르는 편이 빠르다:

```bash
curl -X POST 'https://standard.go.kr/KSCI/api/std/viewMachineNextPage.do?format=json'      --data 'tmprKsNo=KSX6101&reformNo=03&formType=STD'
```

약 14.7MB JSON, 본문 521개 절. `content` 배열이 본문이고 `info` 에 서지 정보가 있다.
⚠️ 응답에 'AI추천문서 … 유사도 NN%' 잡음이 섞여 있으니 걷어내고 읽어야 한다.

⚠️ **이 원문은 저장소에 넣지 않는다.** 한컴 공개 문서와 달리 KS 표준은 자유 배포를 명시적으로
허락하지 않는다(무료 '열람' 이지 재배포 허가가 아니다). 필요할 때 위 명령으로 받는다.

브라우저로 볼 때: https://standard.go.kr/KSCI/standardIntro/getStandardSearchView.do?ksNo=KSX6101
→ '기계가독 원문보기' 버튼.

## ⚠️ 배포 조건 — 반드시 지킬 것

수식 규격서의 저작권 조항이 요구한다:

> 반드시 개발 결과물에 **"본 제품은 한글과컴퓨터의 한글 문서 파일(.hwp) 공개 문서를
> 참고하여 개발하였습니다."** 라고 제품 내 유저인터페이스, 매뉴얼, 도움말 및 소스에
> **모두** 기재하여야 하며

지금 기재된 곳:
- 소스: `experiments/hwp-export/tex_to_hwp.py` 의 파일 첫 주석

아직 안 된 곳(제품으로 낼 때 반드시):
- 사용자에게 보이는 화면(`document-editor.html` 등)
- 매뉴얼·도움말

그 대신 조항은 **"본 문서 및 본 문서에 기재된 내용을 참고하여 개발한 결과물에 대한 모든
저작권은 결과물을 개발한 개인 또는 단체에 있다"** 고 명시한다 — 우리 코드는 우리 것이다.

## 규격서로 잡은 오류 (2026-08-31)

추측으로 만든 것이 실제로 틀렸던 곳들. 전부 `test_tex_to_hwp.py` 의 `[4-2]` 절이 검사한다.

| 규격서 절 | 우리가 하던 것 | 규격 |
|---|---|---|
| 1.2 | `\begin{vmatrix}` → `vmatrix{...}` | 한글에 **`vmatrix` 명령은 없다.** 행렬은 MATRIX·PMATRIX·BMATRIX·**DMATRIX** 넷뿐이고 세로줄은 DMATRIX |
| 1.1.2.3 | 긴 낱말을 그대로 냄 | **한 낱말이 9자를 넘으면 한글이 두 항으로 쪼갠다.** `" "` 로 묶어야 한 낱말로 처리된다 |
| 1.2.1 | 글자 장식 6개만 | acute·grave·check·arch(breve)·under(underline)·dyad 가 더 있다 |
| 1.2.4 | 그리스 문자 일부만 | 대문자(GAMMA·THETA·LAMBDA·XI·PI·PHI·PSI)와 var 계열이 빠져 있었다 |

**넷 다 2026-09-01 에 한글 화면에서 눈으로 확인했다** — 세로줄 행렬, `Probability` 가
한 낱말로 붙는 것, 글자 장식 다섯 개, 새 기호 다섯 개 모두 제 모양으로 나온다.

### KS X 6101 로 잡은 것

| 규격 조항 | 내용 | 우리가 어겼던 것 |
|---|---|---|
| 9.3.2.1 | `itemCnt` 는 **positiveInteger — 1 이상만** 허용. "내용이 없는 문서라도 기본 글꼴 정보는 정의되어 있어야 한다" | 쓰지도 않는 `numberings` 를 `itemCnt="0"` 으로 **자리만 만들어** 넣었다. **규격 위반이다.** 안 쓰는 표는 빼야 한다 |
| — | `refList` 하위: fontfaces · borderFills · charProperties · tabProperties · numberings · bullets · paraProperties · styles · memoProperties · trackChanges | 이 목록을 추측으로 알아냈었다 |
| — | 구역은 반드시 한 개 이상의 문단을 가져야 한다 | 지키고 있었다 |

⚠️ **`itemCnt="0"` 이 두 번째 실패의 유력한 원인이다.** `REV-2026-012` 에서 참조표를 채워
넣으며 "안 쓰지만 자리는 있어야겠지" 하고 빈 `numberings` 를 넣었는데, 규격은 그것을
금지한다. 그때는 규격을 안 보고 있어서 원인을 못 찾고 실물 골격으로 우회했다.

⚠️ 9자 규칙은 **오류가 아니라 결과가 달라지는** 종류다 — 변환은 성공하는데 한글에서
조판된 모양만 틀린다. 표본 시험지 수식 214개에는 걸리는 것이 없어서(수학 기호는 짧다)
그동안 드러나지 않았다. `\mathrm{Probability}` 처럼 긴 낱말에서 터진다.

## 실험 결과 — 골격을 코드로 만들 수 있는가? **아니다** (2026-09-01)

KS X 6101 을 확보한 뒤 **규격대로 코드로만 빈 문서 골격을 만들어 봤다.** 목적은 실물
`templates/blank.hwpx` 를 들고 다니지 않는 것이었다(배포 라이선스 걱정도 함께 사라진다).

규격에서 확인한 것을 전부 지켰다 — `itemCnt` 1 이상, 빈 표 없음, `fontfaces` 포함,
구역에 문단 1개 이상, `refList` 자식 순서. 우리 검증기도 오류·경고 0건이었다.

**그런데 한글이 열지 못했다.** 자동 열기 검사로 확인했다(같은 실행에서 실물 골격 기반
파일은 ✅ 였으므로 환경 문제가 아니다).

좁혀 보려고 세 가지 변형을 더 만들어 각각 따로 돌렸다 — `fontfaces` 제거 / `type="HFT"`
로 변경 / 자칼과 같은 최소 헤더. **셋 다 실패했다.** 즉 원인은 `refList` 안이 아니라
그 밖(`content.hpf` 의 이름공간·`secPr` 세부·`version.xml`·`META-INF` 구성) 어딘가다.

### 그래서 내린 결론

**골격은 계속 실물 파일(`templates/blank.hwpx`)에서 가져온다.**

규격서는 *무엇이 무엇을 뜻하는가* 는 알려주지만, **한글이 실제로 무엇을 요구하는가는
알려주지 않는다.** 이건 `template.py` 가 시험지 틀에 대해 이미 내린 결론과 같다 —
*"실물 파일을 틀로 쓰면 우리가 분석하지 않은 것까지 전부 따라온다."*

⚠️ **이 실험을 다시 하려면** 위 세 변형이 이미 실패했다는 것을 기억할 것. 다음에 볼
곳은 `Contents/content.hpf` 의 이름공간 선언(실물은 15개, 우리는 10개)과 `secPr` 하위
요소다. 다만 **얻는 것이 크지 않다** — 골격 파일은 7KB 짜리 빈 문서이고, 저작물성이
없어 배포 문제도 실제로는 크지 않다.

## 규격서로도 못 푸는 것

**"한글이 이 파일을 열어 주는가"는 규격서에 없다.** 문법이 완벽해도 한글이 거부할 수 있고,
거부할 때 이유를 말해 주지 않는다("파일을 읽거나 저장하는데 오류가 있습니다"만 뜬다).
실제로 이것 때문에 두 번 헛짚었다(`REV-2026-012`).

그래서 **실물 한글로 열어 보는 검사**가 규격서와 별개로 필요하다:

```bash
npm run test:hwpx-opens -- 파일.hwpx
```

`scripts/check-hwpx-opens.mjs` 가 한글로 파일을 열고 **창이 생겼는지**로 판정한다
(한컴 한글은 AppleScript 사전도 CLI 도 제공하지 않아 창 제목을 읽는 수밖에 없다).

- **맥 + 한글 + 손쉬운 사용 권한**이 있어야 한다. 없으면 건너뛴다(종료코드 2).
  권한: 시스템 설정 → 개인정보 보호 및 보안 → 손쉬운 사용
- **CI 에는 걸 수 없다.** 사람이 있는 맥에서 돌린다.
- ⚠️ **파일마다 한글을 껐다 켜지 말 것.** 그렇게 만들었다가 한글이 창을 아예 못 띄우는
  상태가 됐고, 그 뒤로는 멀쩡한 파일까지 전부 실패로 나왔다. 앱은 한 번만 띄우고
  문서만 닫는다. 그래도 전부 실패로 나오면 파일이 아니라 한글을 의심할 것 —
  스크립트가 그 경우 그렇게 안내한다.
