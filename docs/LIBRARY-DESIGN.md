## 0. 먼저 — 이 작업의 **진짜 관문**은 Firestore 규칙이다

폴더도 정렬도 **문제집 문서에 필드를 하나 더 붙이는 일**이다. 그런데:

⚠️ **`firestore.rules` 의 `hasOnly([...])` 에 넣지 않으면 로그인 사용자의 저장이 전부
'권한 오류' 로 실패한다.** 지금 목록은 딱 이것뿐이다
([firestore.rules:52](../firestore.rules:52)):

```
['id','name','header','problems','order','deleted','updatedAt','lineColor','subject']
```

⚠️ **그리고 규칙은 아직 배포되지 않았다**(CLAUDE.md 최상위 미결 항목). 규칙 파일을 고쳐도
**해리가 Firebase 콘솔에 올리기 전까지는 효력이 없다.** 즉 이 작업은

> **규칙 배포 없이는 로그인 사용자에게 도달할 수 없다.**

→ 그래서 설계를 **두 겹**으로 나눈다.

| 겹 | 무엇 | 규칙 배포가 필요한가 |
|---|---|---|
| **A** | 정렬 · 선택 · 설정 화면 · 폴더 **보기** | **아니오** — 전부 기기 안(localStorage)에서 된다 |
| **B** | 폴더 소속을 **클라우드에 저장**(기기 간 동기화) | **예** |

⚠️ A 를 먼저 만들고, B 는 규칙을 함께 고쳐 두되 **배포 전까지는 로컬로만 동작**하게 한다.
그러면 배포가 늦어도 아무도 저장을 잃지 않는다.

## 1. 폴더

### 데이터 모델

- 문제집에 **`folderId`** 하나(문자열 또는 빈 값 = 폴더 없음).
- 폴더 이름 목록은 **문제집이 아니라 따로** 둔다:
  `users/{uid}/prefs/library` 문서에 `{folders:[{id,name,order}]}`.
  ⚠️ 문제집 문서에 이름을 박으면 이름 하나 바꿀 때 **문제집을 전부 다시 써야 한다**
  (300문항짜리가 여럿이면 그때마다 수 MB 를 올린다).

### 반드시 지킬 것

⚠️ **폴더를 지워도 문제집은 지우지 않는다.** 소속만 풀어 `폴더 없음` 으로 보낸다.
   '폴더 삭제' 가 '문제집 삭제' 로 읽히면 사용자는 되돌릴 수 없는 손실을 겪는다.
⚠️ **모르는 `folderId` 는 조용히 버리지 않는다.** 다른 기기에서 만든 폴더가 아직 안
   내려왔을 수 있다 — 그때는 `알 수 없는 폴더` 로 묶어 보여 주고 소속은 **그대로 둔다.**
   (`normSet` 이 화이트리스트로 지우면 그 기기에서 여는 순간 소속이 날아간다.)
⚠️ **`normSet()` 에 `folderId` 를 더할 때 `firestore.rules` 도 같이 고친다** — 한쪽만
   고치면 저장이 통째로 실패한다(CLAUDE.md 가 경고하는 그 사고).
⚠️ 폴더 이동은 **`historyStep()`** 으로 감싼다 — ⌘Z 한 번에 되돌아가야 한다.

### 화면

- 검색 줄 **아래**에 폴더 칩 한 줄: `전체 · 폴더A · 폴더B · + 새 폴더`.
  ⚠️ 왼쪽 사이드바로 두지 않는다 — 375px 에서 격자가 한 칸으로 줄어 있어(`lib-grid`
  `1fr`) 사이드바가 화면 절반을 먹는다.
- 폴더 안에서도 **검색은 전체를 찾는다**(찾는 사람은 어느 폴더인지 모른다).
  결과 카드에 어느 폴더인지 작게 적는다.

## 2. 검색 줄 오른쪽 — `[정렬] [선택] [설정]`

지금 검색은 한 줄을 통째로 쓴다([index.html:1301](../index.html:1301)).
그 줄을 `검색칸(flex:1) + 오른쪽 단추 셋` 으로 바꾼다.

⚠️ **좁은 화면에서 단추가 검색칸을 밀어내지 않게** 한다 — 375px 에서는 단추만 남기고
검색칸이 다음 줄로 접히는 편이 낫다. `test:cross` 가 가로 넘침을 이미 본다.
⚠️ 터치 목표 44px 규칙(`@media (pointer: coarse)`)이 이 단추들에도 걸려야 한다.

### 정렬

지금은 **정렬이 아예 없다** — `sets` 배열 순서 그대로 그린다
([index.html:3471](../index.html:3471)).

| 항목 | 무엇으로 | 새 필드가 필요한가 |
|---|---|---|
| 직접 정한 순서(기본) | 지금 그대로 | 아니오 |
| 이름순 | `name` | 아니오 |
| 최근 수정순 | `updatedAt`(이미 있다) | 아니오 |
| 최근 사용순 | **마지막으로 연 시각** | **예** — 겹 B |

⚠️ '최근 **사용**' 과 '최근 **수정**' 은 다르다. 열어만 보고 안 고친 것이 위로 와야
사용자가 기대하는 '최근' 이다. 필드가 없으면 **기기 안에서만**(localStorage) 기록해
겹 A 로 낸다 — 다른 기기와 안 맞는다는 것을 화면에 적는다.
⚠️ 정렬 기준은 **기기별 설정**이라 계정별 로컬 키로 둔다(`PM_LIB_SORT:{uid}`).
   CLAUDE.md 규칙: **새 로컬 키에는 반드시 uid 를 붙인다** — 안 붙이면 한 브라우저에서
   계정을 바꿨을 때 샌다.

### 선택

- `선택` 을 누르면 카드에 체크칸이 생긴다. 고른 뒤 `폴더로 이동` · `내보내기` · `삭제`.
- ⚠️ **삭제는 되돌릴 수 있어야 한다.** 지금 문제집 삭제는 tombstone 이고 로컬 백업이
  남는다 — 그 규칙을 그대로 따르고, 여러 개를 한 번에 지울 때도 **⌘Z 한 번**으로
  되돌아가게 `historyStep()` 으로 감싼다.
- ⚠️ 선택 모드에서는 카드를 눌러도 **열리지 않아야** 한다(고르는 중이므로).

## 3. 설정

지금 흩어져 있는 것을 **한 곳으로 모은다**. 새로 만드는 것보다 **모으는 것이 먼저**다.

| 칸 | 지금 어디에 있나 | 설계 |
|---|---|---|
| 계정 | 상단바 로그인/로그아웃 · `planBadge` | 사진·이름·메일·플랜을 한 곳에 |
| 데이터 | `데이터 관리` 단추(`#dataModal`) | **그대로 옮긴다**(백업 복구·전체 삭제·계정 삭제) |
| 화면 | 상단바 테마 단추 | 테마(시스템·밝게·어둡게) |
| 구독 | — | 아래 ⚠️ |
| 언어 | — | 아래 ⚠️ |

⚠️ **구독은 '보여 주기' 까지만 한다.** `planLabel()` 은 **표시용**이고 실제 권한은
Worker 가 검증하는 **서명된 custom claim** 이다([index.html:1280](../index.html:1280) 주석).
결제 흐름은 이 저장소에 **없다**. 그러니 설정에는 **현재 플랜과 남은 AI 사용량**만 보여 주고
'업그레이드' 는 안내 링크로 둔다. **결제되는 것처럼 보이는 화면을 만들지 않는다.**

### 언어 — 해리가 방향을 정했다

> **"시스템 언어만 바꾸면 되는 거 맞고, 언어는 가능한 다양하면 좋겠지"**

즉 **화면 글만** 바꾸고(조판은 그대로), **되도록 여러 언어**, 그리고 **시스템 언어를 따라
자동으로**. 그에 맞춰 설계한다.

**(1) 자동 감지 + 손으로 바꾸기**

지금은 세 파일 모두 `<html lang="ko">` 로 박혀 있고 감지가 없다.
→ `navigator.languages` 를 보고 가진 언어 중 맞는 것을 고른다. 없으면 한국어.
⚠️ **사용자가 고른 값이 있으면 그것이 이긴다** — 시스템이 영어인데 한국어로 쓰고 싶은
사람이 있다. 고른 값은 **계정별 로컬 키**(`PM_LANG:{uid}`)에 둔다.
⚠️ `<html lang>` 도 함께 바꾼다 — 화면 낭독기와 글꼴 선택이 그것을 본다.

**(2) 번역하면 안 되는 것을 먼저 못 박는다**

⚠️ **화면 글과 인쇄물 글은 다르다.** 아래는 **시험지에 찍히는 글**이라 언어를 따라가면
안 된다 — 한국 시험지에 `Answer:` 가 찍히면 그건 고장이다.

| 번역하지 않는다 | 어디 |
|---|---|
| `정답: ` | 인쇄본 `answer-block`([index.html:5488](../index.html:5488)) |
| `※ 확인 사항` · `단답형` · `5지선다형` · `수학 영역` | 시험지 틀에서 떠 온 표 |
| `(단, …)` 줄바꿈 · 문항 번호 뒤 탭 · `①②③④⑤` | 조판 규칙 |
| `PEDAGOGY` | 상표 |

→ 카탈로그를 **`ui.*`(번역)** 과 **`sheet.*`(고정)** 으로 갈라 두고, `sheet.*` 는 언어를
바꿔도 한국어로 남긴다. ⚠️ 이 경계를 안 그으면 **인쇄물이 깨진다.**

**(3) 크기 — 660곳을 한 번에 옮기지 않는다**

| 파일 | JS 문자열 | HTML 텍스트 |
|---|---:|---:|
| `index.html` | 394 | 93 |
| `mock-exam-editor.html` | 40 | 32 |
| `document-editor.html` | 83 | 23 |

→ **틀을 먼저, 글은 나중에.** `t("키")` 와 카탈로그를 넣고 **화면 단위로 옮긴다**
(라이브러리 → 설정 → 편집기 → 모의고사 → 문서). 옮기지 않은 곳은 한국어 그대로 나온다 —
**반쯤 옮긴 상태가 정상 동작**이어야 이 크기를 감당할 수 있다.
⚠️ `check:static` 이 **카탈로그에 없는 키를 쓰면 빨간불**을 내게 한다. 안 그러면 키를
잘못 적은 곳이 화면에 `ui.library.title` 같은 날글자로 뜬다.

**(4) 어떤 언어를 넣나**

⚠️ **기계 번역을 그대로 실으면 안 된다.** `문항`·`지문`·`선지`·`묶음`·`별행 수식` 은
교육 현장의 낱말이라 일반 번역기가 틀린다(`선지` → *choice* 가 아니라 *option/answer
choice*, `지문` → *fingerprint* 로 나오기도 한다). 언어마다 **사람이 한 번 봐야 한다.**
→ 먼저 **한국어 · 영어** 둘로 내고, 카탈로그 파일만 더하면 언어가 늘어나게 만든다.
⚠️ 아랍어·히브리어를 넣으려면 `dir="rtl"` 과 좌우 여백이 통째로 뒤집혀야 한다 —
**넣을 때 별도 작업**으로 다룬다. 지금 목록에 올리지 않는다.
⚠️ 날짜는 `toLocaleString("ko-KR")` 로 **박혀 있다**(3곳) — 고른 언어를 따라가게 고친다.

## 4. 만들다 필요해질 것 (내가 더한 것)

- **문제집 카드에 '마지막으로 연 날짜'** — 정렬을 넣으면 왜 그 순서인지 보여야 한다.
- **선택 모드의 '모두 고르기'** 와 고른 개수 표시.
- **폴더별 문항 수 합계** — 폴더가 얼마나 큰지 보이게.
- ⚠️ **빈 폴더도 남는다** — 안에 든 것을 다 옮겨도 폴더는 지우지 않는다(사용자가 지운다).
- ⚠️ **가져오기(import)와 폴더** — 가져온 문제집은 `폴더 없음` 으로 들어간다.
  남의 파일에 든 `folderId` 를 그대로 믿으면 우리 폴더 이름과 안 맞는다.

## 5. 검사 계획

| 무엇 | 어떻게 |
|---|---|
| 폴더를 지워도 문제집이 남는가 | 폴더 삭제 후 문제집 수·소속 확인 |
| 모르는 `folderId` 를 지우지 않는가 | 없는 id 를 넣고 `normSet` 통과 뒤에도 남는지 |
| 규칙과 `normSet` 이 **같은 필드 목록**인가 | `check:static` 이 두 곳을 대조 |
| 정렬이 실제로 순서를 바꾸는가 | 이름순·최근순 각각 고정 기대 순서와 대조 |
| 선택 삭제가 ⌘Z 한 번에 돌아오는가 | `historyStep` 검사와 같은 방식 |
| 좁은 화면에서 줄이 넘치지 않는가 | `test:cross` 의 가로 넘침 |
| 터치 목표 44px | `test:cross` 가 이미 본다 |

⚠️ 항목마다 **일부러 깨서 빨간불**을 확인한다.
⚠️ 특히 '규칙 ↔ `normSet` 목록 대조' 는 **정적 검사**로 만든다 — 브라우저도 Firebase 도
없이 돌아야 하고, 이것이 없으면 필드를 더할 때마다 같은 사고가 난다.

## 코덱스에게 묻고 싶은 것

1. **언어** — 해리가 "UI 만 · 시스템 언어 자동 · 되도록 여러 언어" 로 정했다.
   그래서 **`t()` 틀을 먼저 넣고 화면 단위로 옮기는** 안으로 잡았다(반쯤 옮긴 상태가
   정상 동작). 이 순서가 맞는가? 그리고 **`ui.*` / `sheet.*` 경계**가 인쇄물을 지키기에
   충분한가 — 내가 빠뜨린 '시험지에 찍히는 글' 이 있는가?
2. **폴더 이름을 어디에 둘까.** `users/{uid}/prefs/library` 문서 하나를 새로 만드는 안인데,
   규칙을 또 늘려야 한다. 차라리 **기존 `users/{uid}` 문서에 필드로** 얹는 게 나은가?
   (그 문서는 이미 `create/update` 와 `delete` 가 갈라져 있다.)
3. **겹 A/B 로 나누는 것**이 맞는가? 규칙 배포 전까지 폴더를 로컬 전용으로 두면, 배포 뒤
   기기 간 병합을 어떻게 할지가 남는다 — 로컬 소속을 클라우드로 올릴 때 충돌 규칙이 필요하다.
4. **최근 사용순**을 위해 `lastOpenedAt` 을 문제집 문서에 넣으면, 문제집을 **열기만 해도
   클라우드 쓰기가 일어난다.** 그 비용이 괜찮은가, 아니면 기기 안에만 둘까?
5. 내가 못 본 위험이 있는가? 특히 **`mergeSets()` 와 tombstone** 이 새 필드를 어떻게 다루는지.
