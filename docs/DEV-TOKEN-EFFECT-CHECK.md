# DEV-5 — 첫 분리의 개발 비용 효과 확인

2026-09-13 · 비교 기준 `bc9c6f9^`(추출 전)와 `bc9c6f9`(추출 후).
이 기록은 실제 Codex 사용량이나 원화 비용이 아니라, DEV-1에서 고정한 합성 유지보수 질문의
읽을 범위·파일 왕복·검증 부담을 비교한 대리 지표다.

## 결과

첫 분리는 **AI 변환 내부의 찾기 쉬움과 독립 검증**에는 이득이 있지만, 전체 사진 AI 흐름의
개발 토큰 절감은 입증하지 못했다. 따라서 이 근거만으로 B·C를 계속 분리하지 않는다.
개발 측은 현재 구조를 유지하고 OPS-6 서비스 측정 배포 준비로 이동한다.

| 고정 질문 | 추출 전 기준 | 추출 후 실제 경로 | 판정 |
| --- | --- | --- | --- |
| 사진 AI의 동의·인증·이미지 축소·응답 반영은 어디인가? | `index.html` 6700~6910, 211줄·1파일 | `index.html` 6701~6877, 177줄 + `pedagogy-ai-image.js` 57줄 = 234줄·2파일 | 전체 흐름은 23줄(+11%)·파일 1개 증가. 절감 아님. 다만 축소·응답 변환만 물으면 새 57줄 파일로 바로 좁혀진다. |
| 미리보기 확대가 저장·동기화와 독립적인가? | `index.html`의 `pvMeasure`~`pvFitZoom`, `renderPreview` | 동일. 첫 분리는 이 경로를 바꾸지 않았다. | 변화 없음. 이 질문을 이유로 추가 파일을 읽지 않는다. |

## 확인 근거

- 추출 전 `index.html`은 8,075줄·461,948바이트, 추출 후 8,042줄·460,254바이트다.
  본체에서는 36줄이 줄었지만 새 모듈은 57줄·2,746바이트여서 전체 코드는 작아지지 않았다.
- 이전 AI 구간은 `AI 사진 자동 생성`부터 `renderPreview` 직전까지 211줄이었다. 현재 같은 본체
  구간은 177줄이고, 전처리·응답 변환을 이해하려면 새 모듈 57줄을 더 읽는다.
- 구현에는 새 공개 script, 공개 빌드 목록, `serve.py` 허용 목록, 전용 133줄 브라우저 검사,
  package script가 추가됐다. 이는 재발 방지 이득이지만 이번 한 번의 탐색·검증 부담도 늘린다.
- DEV-3/4에서 HTTP·`file://`·실제 전처리·정규화 우회 변이·기존 regression·공개 세 브라우저를
  확인했다. 이 검증 비용은 구조 변경의 안전 비용으로 남는다.

## 결정과 한계

작은 경계의 독립성은 앞으로 AI 변환 로직만 수정할 때 유용할 수 있다. 하지만 실제 AI 변환 수정
사례가 아직 한 건도 없으므로 그 이득을 확정하지 않는다. 계정 전체 사용량을 이 작업의 토큰 비용으로
환산하지 않으며, 바이트·줄 수를 토큰 또는 요금으로 바꾸지 않는다.

후속 실제 AI 변환 수정이 생기면 이 표에 그 작업의 읽은 파일·범위·재탐색·검사 부담을 한 건만
추가할 수 있다. 이를 위해 새 기능이나 인위적 수정 작업을 만들지 않는다. 지금은 추가 프런트 분리
없이 OPS-6으로 이동한다.
