# 어디서든 깨지지 않게 — 범용성 설계

- 작성: `Claude` · 2026-09-07 · 상태: **검토 반영 완료 · 1단계 착수 가능**
- 짝 기록: `HANDOFF-2026-050` → 검토 `HANDOFF-2026-051`(Codex) → 반영 `HANDOFF-2026-052`
- 독립 검토: [`HANDOFF-2026-051`](../reviews/handoffs/2026-09/2026-09-07-cross-platform-design-review.md)

> **검토에서 §2 와 §5 는 내가 반대로 적고 있었다.** 그 문서대로 고쳤으면 잘못된 방향으로
> 고쳤을 것이다. 아래 두 절은 통째로 다시 썼다.

지금까지 이 저장소는 **맥 + 크롬/사파리 + 데스크톱 한 사람**을 전제로 자랐다.
SaaS 로 내거나 지인에게 링크를 주는 순간 그 전제가 전부 깨진다. 이 문서는
**무엇이 실제로 깨지는지 코드에서 확인한 것**과, 그것을 어떤 순서로 고칠지를 적는다.

## 이 문서를 읽는 법 — 근거의 등급을 표시했다

추측과 실측을 섞으면 검토가 불가능해지므로 항목마다 표시한다.

| 표시 | 뜻 |
|---|---|
| **[코드]** | 이 저장소의 코드를 직접 읽어 확인했다. 줄 번호를 적었다. |
| **[실측]** | 실제로 재거나 돌려 봤다. |
| **[통설]** | 널리 알려진 브라우저 동작이지만 **이 저장소에서 재현하지 않았다.** ⚠️ 검토자가 가장 먼저 의심할 곳이다. |

⚠️ **[통설]로 적힌 것을 근거로 코드를 고치지 말 것.** 고치기 전에 그 환경에서 재현해
[실측]으로 승격시키는 것이 이 계획의 1단계다(§7).

## 1. 로그인이 **아예** 안 되는 환경이 있다 — 가장 큰 위험

지인에게 링크를 준다 = 한국에서는 대부분 **카카오톡으로 준다**. 카톡에서 링크를 누르면
카톡의 인앱 브라우저(WebView)가 열린다.

- **[코드]** 로그인은 `signInWithPopup` 이고([index.html:5869](../index.html:5869)),
  실패하면 `signInWithRedirect` 로 한 번 더 시도한다([index.html:5880](../index.html:5880)).
  다만 **`auth/internal-error` 와 `auth/popup-blocked` 두 코드에서만** 넘어간다.
- **[통설]** 구글은 WebView 에서의 OAuth 를 **구글 쪽에서** 막는다(`disallowed_useragent`).
  팝업이든 리디렉션이든 똑같이 막히므로 **지금의 폴백으로는 못 넘는다.**
- **[코드]** `auth/operation-not-supported-in-this-environment` 는 처리 경로가 없다.

**결과**: 카톡으로 링크를 받은 사람은 "구글로 로그인" 을 눌러도 아무 일도 안 일어나거나
구글의 영어 오류 화면을 본다. 그리고 **우리는 그 사실을 모른다**(원격 오류 수집이 없다).

**[코드]** 그리고 이 문제는 본체만의 것이 아니다. `document-editor.html` 도 로그인이
필요한데 **`signInWithPopup()` 의 예외를 아예 잡지 않는다**
([document-editor.html:239](../document-editor.html:239)) — 폴백도, 오류 안내도 없다.
**두 화면이 같은 실패 분류와 같은 안내를 써야 한다.**

**제안**: 인앱 브라우저를 감지해 **"사파리/크롬에서 열기"** 안내를 함께 띄운다.
안드로이드는 `intent://` 로 크롬을 직접 열 수 있고, iOS 는 주소 복사 + 안내가 최선이다.
⚠️ **capability 로 알아낼 방법은 없다.** UA 매칭은 **미리 경고를 띄우는 힌트**일 뿐이고,
**최종 판정은 실제 인증 오류 코드**로 한다. 감지가 틀렸을 때도 **로그인 버튼은 남겨 둔다**
— 오탐으로 멀쩡한 브라우저에서 로그인이 사라지는 쪽이 더 나쁘다.

⚠️ **파일 저장도 같이 본다.** 모바일·인앱 브라우저에서는 HWPX 를 **만드는 것**과 Blob 을
**기기에 저장하는 것**이 별개다. 연기 검사를 "ZIP 이 만들어졌다" 에서 끝내지 말고 **실제
다운로드 이벤트·파일명·크기**까지 보고, 안 되면 Web Share 로 파일을 넘기는 대안을 검토한다.

## 2. 로컬 서버 기능이 왜 실패하는지 우리는 **아직 모른다**

⚠️ **처음에 "크롬만 `http://localhost` 를 혼합 콘텐츠에서 예외 허용하고 사파리·파이어폭스는
막는다" 고 적었다. 틀렸다.** 표준(W3C Secure Contexts)은 loopback 주소를
*potentially trustworthy* 로 분류하고, Mixed Content 표준은 그런 URL 을 혼합 콘텐츠로 보지
않는다. **어느 브라우저에서도 혼합 콘텐츠 차단이 원인이 아니다.**

- **[코드]** 배포본에서도 두 편집기는 `http://127.0.0.1:8787` 을 부른다
  ([mock-exam-editor.html:1971](../mock-exam-editor.html:1971),
  [document-editor.html:212](../document-editor.html:212)).
- **[코드]** 그리고 `serve.py` 는 **이미 사설망 접근(PNA) 허가 헤더를 처리한다**
  ([serve.py:373](../serve.py:373), [serve.py:382](../serve.py:382)).
  거기 달린 주석 자체가 "크롬이 **https 페이지에서** 로컬 주소를 부를 때 요구하는 헤더" 라고
  적고 있다 — 즉 이 저장소는 이미 https→loopback 이 **된다**는 전제 위에 서 있다.

그러면 실제 변수는 무엇인가:
- **[통설]** WebKit 에 loopback 의 secure-origin / mixed-content 처리가 서로 다르다는
  **공개 미해결 버그**가 있다(webkit.org/b/281149).
- **[통설]** 최신 브라우저의 **Local Network Access / Private Network Access 권한**이 별개 변수다.
  사용자가 권한을 거부하면 우리 쪽 헤더와 무관하게 막힌다.

**그래서 지금 할 일은 고치는 것이 아니라 재는 것이다.** 1단계 검사에서 세 엔진 각각에 대해
`GET /health` 와 **커스텀 헤더가 붙는 실제 `POST`** 를 따로 시험하고, 실패를
**혼합 콘텐츠 / CORS / PNA 권한 / 서버 없음** 네 갈래로 나눠 기록한다.
⚠️ 지금처럼 "서버를 켜세요" 한 줄로 뭉개면 사용자는 원인을 모른 채 자기 탓을 한다.

- **[코드]** 그와 별개로 안내문은 `python3 serve.py` 다 — 윈도우 사용자에게는 파이썬 +
  `typst` 설치를 요구하는 셈이라 사실상 불가능하다. 이건 브라우저 문제가 아니라 **제품 경계**다.
  모의고사 편집기를 지인에게 열어 줄 것인지부터 정해야 한다(§7 5단계).

## 3. 저장이 조용히 사라질 수 있다

- **[코드]** 비로그인 사용자의 데이터는 `localStorage` 뿐이다
  ([index.html:2689](../index.html:2689)).
- **[통설]** iOS 사파리의 ITP 는 "7일간 방문이 없으면" 이 아니라
  **"사파리를 사용한 7일 동안 그 사이트에 사용자 상호작용이 없으면"** 스크립트가 심은
  저장소를 지운다. 상호작용은 클릭·탭·키 입력이고 **스크롤은 세지 않는다.**
  홈 화면에 설치한 웹 앱의 first-party 도메인은 이 제한에서 **빠진다.**
  ⚠️ 처음에 "일주일 뒤 사라진다" 고 단정해 적었다 — 위험은 맞지만 그렇게 쓰면 안 된다.
- **[코드]** 저장 실패는 이미 `try/catch` 로 잡고 토스트를 띄운다
  ([index.html:2689](../index.html:2689)) — **잘 돼 있는 부분이다.**
- **[코드]** 창이 닫힐 때의 저장 보장은 `beforeunload` 와 `visibilitychange` 뿐이다
  ([index.html:3223](../index.html:3223), [index.html:3231](../index.html:3231)).
- **[통설]** iOS 사파리는 `beforeunload` 를 자주 건너뛴다.

**제안**: `pagehide` 를 **동기 로컬 저장의 보조 경로로만** 더한다.
⚠️ **그 안에서 비동기 Firestore 저장이 끝난다고 가정하지 않는다** — `pagehide` 도
`visibilitychange` 도 모바일에서 완전한 종료 보장이 아니다. 데이터 안전의 **주 수단은
따로 있다**: 편집 중 150ms 디바운스 저장 · 저장 상태 표시 · 로그인 · JSON 내보내기.
비로그인 안내 문구도 "이 기기에만 저장됩니다" 에서 **"지워질 수 있습니다"** 로 바꾼다.

### 3-b. 저장소가 막히면 **문서 편집기는 통째로 죽는다** — 새로 찾음

- **[코드]** `document-editor.html` 의 `init()` 은 `firebase` 만 `try` 로 감싸고,
  그 **다음 줄**에서 `localStorage.getItem("PEDAGOGY_DOCUMENT_BETA")` 를 맨몸으로 부른다
  ([document-editor.html:239](../document-editor.html:239)). `init()` 자체를 감싸는 `try` 도 없다.
- **[실측]** 저장소 접근이 `SecurityError` 를 던지게 하고 두 앱을 띄워 봤다:

  | | 버튼에 핸들러가 붙었나 | 입력칸이 채워졌나 |
  |---|---|---|
  | 문서 편집기 · 저장소 정상 | ✅ | ✅ |
  | **문서 편집기 · 저장소 차단** | **❌** | **❌** |
  | 본체 · 저장소 정상 | ✅ | — |
  | 본체 · 저장소 차단 | ✅ | — |

  차단 시 `SecurityError` 하나가 던져지고 **`init()` 의 나머지가 통째로 안 돈다.**
  화면은 멀쩡해 보이는데 **아무 단추도 듣지 않고 오류도 안 보인다.** 본체는 멀쩡하다 —
  `try/catch` 를 곳곳에 둔 규율이 실제로 값을 했다.
- **[통설]** 이 상태는 사파리의 '모든 쿠키 차단', 일부 사생활 보호 창, 기업·학교의
  저장소 차단 정책에서 실제로 일어난다.

⚠️ **이건 설계 대기 항목이 아니다.** 재현이 있으므로 바로 고친다(`REV-2026-022`).

## 4. 손가락으로는 못 쓰는 조작들

- **[코드]** 목록·블록 순서 바꾸기는 SortableJS 인데 터치 옵션이 하나도 없다
  ([index.html:3475](../index.html:3475), [index.html:4328](../index.html:4328)).
  ⚠️ **그렇다고 고장이라고 단정하지 않는다** — SortableJS 는 기본 터치 지원이 있다.
  실제 touchscreen 문맥에서 **끌기와 스크롤이 싸우는 것을 재현한 뒤** `delayOnTouchOnly`·
  `touchStartThreshold` 값을 고른다. 재현 없이 값부터 넣으면 무엇을 고쳤는지 알 수 없다.
- ⚠️ **`:hover` 규칙이 33개라는 것은 판정 기준이 아니다**(처음에 그렇게 적었다).
  대부분은 대체 진입 경로가 있다 — **[코드]** `.q-actions` 는 `:hover` 말고도
  `.selected` 와 `:focus-within` 으로 열린다([index.html:383-385](../index.html:383)).
  터치로 문항을 누르면 `.selected` 가 붙으므로 **문제없다.**
  실제로 hover 에만 걸린 후보는 **`.blk-insert-btn`** 하나다
  ([index.html:570](../index.html:570) — `:hover` 와 `.open` 뿐).
  → **기능별로 대체 진입 경로가 있는지**를 보고, 없는 것만 고친다.
- **[코드]** 단축키는 이미 `metaKey||ctrlKey` 를 둘 다 본다
  ([index.html:5420](../index.html:5420), [mock-exam-editor.html:2299](../mock-exam-editor.html:2299)) —
  **동작은 윈도우에서도 맞다.**
- **[코드]** 그런데 화면에 적힌 라벨은 `⌘` 다(mock 9곳 · index 1곳). **윈도우에서는 거짓말이다.**

**제안**: ① Sortable 에 터치 옵션을 준다. ② `⌘`/`Ctrl` 라벨을 플랫폼에 맞춰 바꾼다(표시만).
③ hover 전용 조작을 찾아 **항상 보이게** 하거나 길게 누르기를 준다.

## 5. 모바일 화면

- **[코드]** `100vh` 가 4곳 있다. **[통설]** iOS 사파리의 주소창 때문에 실제보다 커서 잘린다.
  `dvh` 가 답이지만 **구형 폴백을 남긴다**(`100vh` 를 먼저 쓰고 `100dvh` 로 덮는다).
- ⚠️ **safe-area 는 내가 반대로 적고 있었다.** WebKit 은 기본값 `viewport-fit=auto` 에서
  콘텐츠를 **이미 안전 영역 안에 넣어 준다.** `viewport-fit=cover` 를 넣어야 화면 끝까지
  펼쳐지고, **그때 비로소** `env(safe-area-inset-*)` 보정이 필요해진다.
  즉 지금 `cover` 가 없는 것은 **정상**이고, 처음 제안대로 일괄 추가했다면 **없던 가림을
  새로 만들었을 것이다.**
  → 순서: ① 실제 기기/시뮬레이터에서 가림을 **먼저 재현**한다 ② 전체 폭 배경이 꼭 필요한
    화면에만 `cover` 를 쓰고 ③ 고정 헤더·하단 단추에 `max(기존여백, env(...))` 를 준다.
  ⚠️ `dvh` 와 safe-area 는 **별개 항목으로** 검사한다. iOS 26 에도 관련 WebKit 회귀가
    보고돼 있어 **Playwright WebKit 한 번으로 완료 판정하지 않는다.**
- **[코드]** 반응형 분기가 앱마다 다르다:
  · `index.html` — 1279 / 1023 / 480 (**회귀 검사가 1440·768·375 를 본다**)
  · `mock-exam-editor.html` — 1023 / 480 (검사 없음)
  · `document-editor.html` — **900 하나뿐** (사실상 모바일 미대응)

**제안**: 본체는 이미 낫다. **문서 편집기부터** 손본다.
모의고사 편집기는 **시험지 캔버스(A4 비율·실측값)는 그대로 두고 주변 편집 UI 만** 반응형으로
만든다. ⚠️ "모바일 대응" 과 "시험지를 좁게 재조판" 을 섞지 않는다 — 후자는 조판 정확도를
버리는 일이다. 태블릿은 편집까지, 휴대폰은 **열람·간단 수정**부터가 정직한 범위다.

## 6. 첫 로딩이 무겁다 — 그리고 **어제 내가 더 무겁게 만들었다**

- **[실측]** 본문 글꼴 KoPub Batang 은 **weight 당 2.5MB**, 세 벌이면 **7.6MB** 다.
  게다가 **WOFF2 가 아니라 WOFF** 이고 `unicode-range` 서브셋도 없다(CDN 의 `font-kopub@1.0`).
- **[코드]** 어제 인쇄 첫 대기를 줄이려고 **부팅 뒤 한가할 때 세 벌을 미리 받게** 했다
  (`warmPrintFonts`, [index.html](../index.html)). 데스크톱에서는 옳지만,
  **인쇄할 생각이 없는 모바일 사용자에게 7.6MB 를 미리 받게 한다.**

**제안(검토 반영)**: 화면 폭이나 `saveData` 로 가르지 않는다 — **인쇄 의도가 생길 때** 받는다.
인쇄 메뉴를 열거나 인쇄 단추에 `pointerdown`·`focus` 가 들어오는 순간 선로드하면,
1.2초의 대부분이 **사용자가 인쇄 옵션을 고르는 시간 뒤로 숨는다.** 인쇄할 생각이 없는
방문자는 한 바이트도 받지 않는다. 부팅 뒤 무조건 받는 지금 방식보다 양쪽 모두 낫다.
⚠️ `navigator.connection` 은 모든 브라우저에 있지 않다 — **보조 조건으로만** 쓴다.
⚠️ 자체 WOFF2·서브셋 호스팅은 **라이선스와 조판 동일성을 따로 검증한 뒤**에만 결정한다
([`docs/FONT-LICENSE.md`](FONT-LICENSE.md)).

## 7. 지금 우리는 **맥에서만** 검사한다

- **[코드]** 시각 회귀 기준본은 `test-fixtures/visual-baseline/darwin/` 뿐이다.
- **[실측]** Playwright 는 chromium 과 (어제 내가 깐) webkit 이 있다. **firefox 는 없다.**
- 윈도우에서 돌려 본 적이 **한 번도 없다.**

⚠️ 이 저장소의 원칙상 **재현할 수 없는 것은 고치지 않는다.** 그러니 순서는 이렇다.

## 제안하는 순서 (검토 반영본)

**1단계 — 재현 수단부터 만든다 (§2·§4·§5 의 코드는 아직 고치지 않는다)**
`[통설]` 을 `[실측]` 으로 바꾸는 단계다. 이게 없으면 나머지가 전부 추측 위에 선다.
- Playwright 에 **firefox** 를 더하고, chromium/webkit/firefox 세 엔진에서
  **부팅 → 문제집 만들기 → 블록 추가 → 인쇄본 조립**까지 도는 연기 검사를 만든다.
- 같은 검사를 **모바일 뷰포트**(375×812, 768×1024)에서도 돌린다.
- ⚠️ **시각 비교는 하지 않는다.** OS 마다 글리프가 달라 잡음이 신호보다 크다는 것을
  이 저장소가 이미 실측으로 확인했다(`REV-2026-018`).

판정 기준 (검토에서 크게 늘었다 — 처음엔 셋뿐이었다):

| 무엇을 | 왜 |
|---|---|
| 가로 스크롤 · 콘솔 오류 | 기본 |
| **핵심 요소 쌍**의 겹침 | ⚠️ 모든 교차를 자동 판정하면 **의도한 메뉴·모달도 실패**한다. 쌍을 정해 둔다 |
| 핵심 단추가 화면 안에 있고 누를 수 있는가 · **44px 터치 목표** | 손가락 |
| 키보드가 올라온 뒤 입력칸이 보이는가 | 모바일 입력 |
| 터치 드래그 ↔ 스크롤 충돌 | §4 |
| 편집 직후 `visibilitychange`/`pagehide` 저장 | §3 |
| **CDN 실패 폴백** | KaTeX·글꼴·Firebase 가 막히는 망 |
| 느리거나 깨진 그림으로 인쇄 | `HANDOFF-2026-047`·`REV-2026-021` 이 이미 다룬 경로 |

| `GET /health` 와 **헤더 붙은 POST** 를 따로 · 실패를 4갈래로 | §2 |

⚠️ **Playwright 의 desktop WebKit 은 실제 iOS 사파리도, 카카오 WebView 도 아니다.**
세 엔진 연기 검사는 **공통 DOM·CSS·JS 회귀를 잡는 1차선**이다. 인증·다운로드·키보드·
safe-area 의 **완료 판정에는 실제 기기 표가 따로 필요하다.** 자동 검사만 초록불이라고
"모바일 대응 완료" 라고 쓰지 말 것 — 이 저장소가 반복해서 당한 실패 방식 1번이다.

**2단계 — 되돌릴 수 없는 실패부터** (§1 인앱 브라우저 · 세 앱 공통 실패 분류, §3 `pagehide`)

**3단계 — 손가락** (§4 — 재현한 것만)

**4단계 — 화면** (§5 `dvh` · 문서 편집기 반응형 · safe-area 는 가림을 재현한 뒤에만)

**5단계 — 무게** (§6 인쇄 의도 시점 선로드)

**6단계 — 제품 경계** (§2 서버 필요 기능을 "개발용" 으로 명시할지 결정)

⚠️ **§3-b(문서 편집기가 저장소 차단에서 죽는 것)는 이 순서 밖이다.** 재현이 이미 있으므로
바로 고친다.

## 검토에서 내가 틀렸던 것 (기록으로 남긴다)

1. **§2** — "크롬만 localhost 혼합 콘텐츠를 허용한다" 는 표준과 반대다. loopback 은
   표준상 신뢰 URL 이고, 실제 변수는 **WebKit 구현 버그와 PNA 권한**이다.
   그리고 `serve.py` 는 **이미 PNA 헤더를 처리하고 있었다** — 코드를 덜 읽고 적었다.
2. **§5** — `viewport-fit=cover` 가 없어서 노치에 가린다고 적었는데 **반대**다.
   기본값이 이미 안전 영역 안에 넣어 주고, `cover` 를 넣어야 가림이 **생긴다.**
3. **§3** — ITP 를 "7일간 방문 없으면" 으로 단정했다. 정확히는 "사파리를 쓴 7일 동안
   **그 사이트에 상호작용이 없으면**" 이고 스크롤은 빠지며 홈 화면 웹 앱은 예외다.
4. **§4** — `:hover` 33개를 위험 근거로 썼다. 대부분 대체 경로가 있고 실제 후보는 하나였다.
   **개수는 판정 기준이 아니다.**

⚠️ 넷 다 **`[통설]` 로 표시해 둔 항목에서 나왔다.** 등급을 붙여 둔 것이 값을 했다 —
다음에도 재현하지 않은 것은 반드시 그렇게 표시할 것.
