# 어디서든 깨지지 않게 — 범용성 설계

- 작성: `Claude` · 2026-09-07 · 상태: **검토 요청(코덱스)**
- 짝 기록: `HANDOFF-2026-050`

지금까지 이 저장소는 **맥 + 크롬/사파리 + 데스크톱 한 사람**을 전제로 자랐다.
SaaS 로 내거나 지인에게 링크를 주는 순간 그 전제가 전부 깨진다. 이 문서는
**무엇이 실제로 깨지는지 코드에서 확인한 것**과, 그것을 어떤 순서로 고칠지를 적는다.

## 이 문서를 읽는 법 — 근거의 등급을 표시했다

추측과 실측을 섞으면 검토가 불가능해지므로 항목마다 표시한다.

| 표시 | 뜻 |
|---|---|
| **[코드]** | 이 저장소의 코드를 직접 읽어 확인했다. 줄 번호를 적었다. |
| **[실측]** | 실제로 재거나 돌려 봤다. |
| **[통설]** | 널리 알려진 브라우저 동작이지만 **이 저장소에서 재현하지 않았다.** ⚠️ 검토자가 가장 먼저 의심할 곳이다. |

⚠️ **[통설]로 적힌 것을 근거로 코드를 고치지 말 것.** 고치기 전에 그 환경에서 재현해
[실측]으로 승격시키는 것이 이 계획의 1단계다(§7).

## 1. 로그인이 **아예** 안 되는 환경이 있다 — 가장 큰 위험

지인에게 링크를 준다 = 한국에서는 대부분 **카카오톡으로 준다**. 카톡에서 링크를 누르면
카톡의 인앱 브라우저(WebView)가 열린다.

- **[코드]** 로그인은 `signInWithPopup` 이고([index.html:5869](../index.html:5869)),
  실패하면 `signInWithRedirect` 로 한 번 더 시도한다([index.html:5880](../index.html:5880)).
  다만 **`auth/internal-error` 와 `auth/popup-blocked` 두 코드에서만** 넘어간다.
- **[통설]** 구글은 WebView 에서의 OAuth 를 **구글 쪽에서** 막는다(`disallowed_useragent`).
  팝업이든 리디렉션이든 똑같이 막히므로 **지금의 폴백으로는 못 넘는다.**
- **[코드]** `auth/operation-not-supported-in-this-environment` 는 처리 경로가 없다.

**결과**: 카톡으로 링크를 받은 사람은 "구글로 로그인" 을 눌러도 아무 일도 안 일어나거나
구글의 영어 오류 화면을 본다. 그리고 **우리는 그 사실을 모른다**(원격 오류 수집이 없다).

**제안**: 인앱 브라우저를 감지해 로그인 버튼 대신 **"사파리/크롬에서 열기"** 안내를 띄운다.
안드로이드는 `intent://` 로 크롬을 직접 열 수 있고, iOS 는 주소 복사 + 안내가 최선이다.
⚠️ userAgent 문자열 매칭은 낡는다 — **감지가 틀렸을 때도 로그인 버튼은 남겨 둔다.**
(감지 실패로 멀쩡한 브라우저에서 로그인이 사라지는 쪽이 더 나쁘다.)

## 2. 로컬 서버 기능이 브라우저마다 **다르게** 죽는다

- **[코드]** 배포본에서도 모의고사 편집기와 문서 편집기는 `http://127.0.0.1:8787` 을 부른다
  ([mock-exam-editor.html:1971](../mock-exam-editor.html:1971),
  [document-editor.html:212](../document-editor.html:212)).
- **[통설]** GitHub Pages 는 https 다. https 문서가 http 로 요청하면 혼합 콘텐츠다.
  크롬은 `localhost` 를 신뢰 출처로 **예외 허용**하지만 **사파리·파이어폭스는 막는다.**

**결과**: 같은 안내문("서버를 켜세요")을 따라 해도 크롬에서는 되고 사파리에서는 안 된다.
사용자는 자기 잘못인 줄 안다.

- **[코드]** 게다가 그 안내는 `python3 serve.py` 다 — 윈도우 사용자에게는 파이썬 + `typst`
  설치를 요구하는 셈이라 사실상 불가능하다.

**제안**: 두 갈래를 **명확히 갈라 보여 준다.**
- 브라우저만으로 되는 것(AI 문서 HWPX)은 이미 브라우저 조판이 있다 → 서버 경로를 **대비책**
  으로만 두고 안내 문구에서 서버를 앞세우지 않는다.
- 서버가 꼭 필요한 것(모의고사 실시간 정본·시험지 HWPX)은 **"이 기능은 개발용"** 이라고
  화면에서 미리 말한다. 지금은 눌러 본 뒤에야 실패로 안다.
⚠️ 이건 코드보다 **제품 결정**이다 — 모의고사 편집기를 지인에게 열어 줄 것인지부터 정해야 한다.

## 3. 저장이 조용히 사라질 수 있다

- **[코드]** 비로그인 사용자의 데이터는 `localStorage` 뿐이다
  ([index.html:2689](../index.html:2689)).
- **[통설]** iOS 사파리는 **7일간 방문이 없으면 스크립트가 심은 저장소를 지운다**(ITP).
  비로그인으로 아이패드에서 쓰던 사람은 일주일 뒤 문제집이 사라진다.
- **[코드]** 저장 실패는 이미 `try/catch` 로 잡고 토스트를 띄운다 — 사파리 사생활 보호
  창에서 `setItem` 이 던지는 경우는 **이미 안전하다**(잘 돼 있는 부분이다).
- **[코드]** 창이 닫힐 때의 저장 보장은 `beforeunload` 와 `visibilitychange` 두 개다
  ([index.html:3223](../index.html:3223), [index.html:3231](../index.html:3231)).
  **`pagehide` 가 없다.**
- **[통설]** iOS 사파리는 `beforeunload` 를 자주 건너뛴다(탭 폐기·앱 전환). 권장은 `pagehide` 다.

**제안**: ① `pagehide` 를 저장 보장 목록에 더한다(작고 위험이 낮다).
② 비로그인 상태를 **일시적인 것으로 취급**한다 — 지금은 "이 기기에만 저장됩니다" 라고만
말하는데, iOS 에서는 "지워질 수 있습니다" 가 맞다.

## 4. 손가락으로는 못 쓰는 조작들

- **[코드]** 목록·블록 순서 바꾸기는 SortableJS 인데 **터치 옵션이 하나도 없다**
  ([index.html:3475](../index.html:3475), [index.html:4328](../index.html:4328)).
  `delayOnTouchOnly`·`touchStartThreshold` 가 없으면 아이패드에서 **끌기와 스크롤이 싸운다.**
- **[코드]** `:hover` 규칙이 index.html 에만 **33개**다. 터치에는 hover 가 없다 —
  hover 로만 나타나는 단추가 있으면 그 기능은 터치에서 **존재하지 않는다.**
  (전수 확인은 아직 안 했다 — 검토자가 봐 주면 좋겠다.)
- **[코드]** 단축키는 이미 `metaKey||ctrlKey` 를 둘 다 본다
  ([index.html:5420](../index.html:5420), [mock-exam-editor.html:2299](../mock-exam-editor.html:2299)) —
  **동작은 윈도우에서도 맞다.**
- **[코드]** 그런데 화면에 적힌 라벨은 `⌘` 다(mock 9곳 · index 1곳). **윈도우에서는 거짓말이다.**

**제안**: ① Sortable 에 터치 옵션을 준다. ② `⌘`/`Ctrl` 라벨을 플랫폼에 맞춰 바꾼다(표시만).
③ hover 전용 조작을 찾아 **항상 보이게** 하거나 길게 누르기를 준다.

## 5. 모바일 화면

- **[코드]** `100vh` 가 4곳 있다. **[통설]** iOS 사파리의 주소창 때문에 실제보다 커서 잘린다.
  `dvh` 가 답이지만 **구형 폴백을 남겨야 한다**(`100vh` 를 먼저 쓰고 `100dvh` 로 덮는다).
- **[코드]** 세 앱 모두 `viewport-fit=cover` 와 `env(safe-area-inset-*)` 이 **없다**.
  아이폰 노치·홈 인디케이터에 UI 가 가린다.
- **[코드]** 반응형 분기가 앱마다 다르다:
  · `index.html` — 1279 / 1023 / 480 (그리고 **회귀 검사가 1440·768·375 를 본다**)
  · `mock-exam-editor.html` — 1023 / 480 (검사 없음)
  · `document-editor.html` — **900 하나뿐** (사실상 모바일 미대응)

**제안**: 본체(`index.html`)는 이미 낫다. **문서 편집기부터 손본다.**
⚠️ 모의고사 편집기는 A4 2단 조판을 픽셀로 재는 화면이라 **좁은 화면에 맞추는 것이 의미가
있는지부터** 판단해야 한다 — 무리해서 반응형으로 만들면 조판 정확도를 잃는다.

## 6. 첫 로딩이 무겁다 — 그리고 **어제 내가 더 무겁게 만들었다**

- **[실측]** 본문 글꼴 KoPub Batang 은 **weight 당 2.5MB**, 세 벌이면 **7.6MB** 다.
  게다가 **WOFF2 가 아니라 WOFF** 이고 `unicode-range` 서브셋도 없다(CDN 의 `font-kopub@1.0`).
- **[코드]** 어제 인쇄 첫 대기를 줄이려고 **부팅 뒤 한가할 때 세 벌을 미리 받게** 했다
  (`warmPrintFonts`, [index.html](../index.html)). 데스크톱에서는 옳지만,
  **인쇄할 생각이 없는 모바일 사용자에게 7.6MB 를 미리 받게 한다.**

**제안**: 미리 받기를 **조건부**로 바꾼다 — 데이터 절약 모드(`navigator.connection.saveData`)나
좁은 화면에서는 미리 받지 않고 인쇄를 누를 때 받는다.
⚠️ 이건 내가 어제 넣은 변경을 되돌아보는 항목이다. **검토자가 이 판단을 확인해 주면 좋겠다** —
"인쇄 첫 대기 1.2초" 와 "모바일 첫 방문 7.6MB" 중 무엇을 우선할지는 제품 판단에 가깝다.

## 7. 지금 우리는 **맥에서만** 검사한다

- **[코드]** 시각 회귀 기준본은 `test-fixtures/visual-baseline/darwin/` 뿐이다.
- **[실측]** Playwright 는 chromium 과 (어제 내가 깐) webkit 이 있다. **firefox 는 없다.**
- 윈도우에서 돌려 본 적이 **한 번도 없다.**

⚠️ 이 저장소의 원칙상 **재현할 수 없는 것은 고치지 않는다.** 그러니 순서는 이렇다.

## 제안하는 순서

**1단계 — 재현 수단부터 만든다 (코드는 아직 고치지 않는다)**
`[통설]` 을 `[실측]` 으로 바꾸는 단계다. 이게 없으면 나머지가 전부 추측 위에 선다.
- Playwright 에 **firefox** 를 더하고, chromium/webkit/firefox 세 엔진에서
  **부팅 → 문제집 만들기 → 블록 추가 → 인쇄본 조립**까지 도는 연기 검사를 만든다.
- 같은 검사를 **모바일 뷰포트**(375×812, 768×1024)에서도 돌린다.
- ⚠️ **시각 비교는 하지 않는다.** OS 마다 글리프가 달라 잡음이 신호보다 크다는 것을
  이 저장소가 이미 실측으로 확인했다(`REV-2026-018`). **깨졌는가**(가로 스크롤·요소 겹침·
  콘솔 오류)만 본다.

**2단계 — 되돌릴 수 없는 실패부터** (§1 인앱 브라우저, §3 `pagehide`)
로그인과 데이터는 실패하면 사용자가 복구할 수 없다.

**3단계 — 손가락** (§4 Sortable 터치 · hover 전용 조작 · ⌘ 라벨)

**4단계 — 화면** (§5 dvh · safe-area · 문서 편집기 반응형)

**5단계 — 무게** (§6 글꼴 미리받기 조건부)

**6단계 — 안 되는 것을 미리 말하기** (§2 서버 필요 기능의 안내)

   조건부로 바꾸는 게 맞는가, 아니면 다른 답(서브셋 글꼴 자체 호스팅 등)이 있는가?
   ⚠️ 글꼴을 바꾸는 것은 라이선스·조판 정확도 양쪽에 걸린다(`docs/FONT-LICENSE.md`).
3. **§5** — 모의고사 편집기를 모바일에 맞추는 것이 의미가 있는가, 아니면 "데스크톱 전용"
   이라고 못 박는 것이 정직한가?
4. **1단계 연기 검사**의 판정 기준으로 무엇을 더 봐야 하는가? 지금 생각한 것은
   가로 스크롤·요소 겹침·콘솔 오류 셋뿐이다.
5. **내가 놓친 환경이 있는가?** 특히 안드로이드 크롬, 삼성 인터넷, 윈도우 엣지,
   그리고 학교·학원의 낡은 브라우저.
