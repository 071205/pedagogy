## 1. 사용자가 정한 제품 방향

**AI를 활용해 문항 편집기를 더 쉽게 쓰고, 원하는 문제를 모아 편집·조판한다.**
수업 프린트·N제·기출 재구성·직접 출제·모의고사는 활용 장면이며 하나로 제품을 제한하지 않는다.
결과는 PEDAGOGY 라이브러리에서 계속 편집한다. N제 한글 내보내기는 추가 출력 후보다.
학생 관리·성적 관리는 범위 밖이다.

추가 요구: N제도 전체 페이지를 인쇄 전에 보고, 긴 문항의 잘림과 풀이 공간 부족을 고친다.
사용자는 이 기능을 별도 선행 구현하지 않고 **이번 UX 설계와 함께 구현**하도록 선택했다.
이후 전체 디자인·버튼 흐름에 Apple의 UX를 조사·활용하도록 요청했다.

## 3. 공통 경험 원칙

1. **작업물 중심**: 화면의 주인공은 문제집·문항·지면. AI 대화 기록이 작업물을 대신하지 않는다.
2. **안정적인 위치와 용어**: 같은 동작은 같은 이름/위치. '뒤로'와 '닫기'는 데이터 폐기가 아니다.
3. **선택→조작→결과 확인**: 무엇을 바꾸는지 선택 표시와 제목에 드러내고 결과를 같은 맥락에서 본다.
4. **필요한 설정만 노출**: 기본 조작은 보이고 고급 옵션은 펼친다. 기능 발견성을 희생한 숨김은 피한다.
5. **안전하게 시도**: 되돌릴 수 있는 배치·순서 변경마다 확인창을 띄우지 않고 실제 Undo를 제공한다.
6. **정직한 상태**: '이 브라우저에 저장됨'과 '클라우드 동기화됨', '생성됨'과 '검토됨'을 혼동하지 않는다.
7. **AI와 직접 조작의 연속성**: AI 제안을 같은 컨트롤로 수정한다. 추가 요청은 미리보기 후 명시 적용한다.
8. **장치가 달라도 기능 유지**: 마우스·키보드·터치로 핵심 작업 가능. hover/드래그/단축키 전용 기능 금지.

## 4. 정보 구조와 흐름

다음은 사용 흐름이며 모든 작업을 매번 통과해야 하는 고정 마법사가 아니다.
기존 문제집은 편집/지면 보기로 바로 열고, 뒤로 가도 선택과 작업 상태를 보존한다.

### 라이브러리 → 시작

- '+ 새 문제집': '직접 만들기 / 자료로 만들기 · AI' 두 경로.
- 빈 라이브러리에서도 같은 두 선택을 직접 보여준다.
- '문제집 파일 불러오기(JSON)'는 PDF 자료 투입과 구별한다.
- 기존 여러 권 선택에는 '선택한 문제집으로 새로 구성'을 제안한다.
- 사진 한 장을 현재 문제집에 추가하는 빠른 경로는 유지한다.
- 새 '영구 PDF 자료함'이나 별도 범용 AI 채팅 탭을 필수로 만들지 않는다.

### 자료 → AI 구성안

자료와 요청을 같은 화면에서 받는다. 예: '이 PDF를 단원별로 문제집 5개로 만들어줘'.
단원별/배점별/난이도별/N문항씩 같은 프리셋과 직접 입력을 함께 제공한다.
파일 선택만으로 유료 AI 처리를 시작하지 않는다. 처리 범위·산정 가능한 사용량·전송 안내 뒤 시작.

구성안은 목적지 문제집 목록 + 선택한 권의 문항 목록 + 필요할 때 여는 문항/원문 상세다.
문항을 이동·제외·수정할 수 있고, 손수 고친 구성이 현재 기준이다.
재요청은 '새 구성안 보기→변경 확인→적용'. 본문·수식·정답 수정을 재분류로 덮어쓰지 않는다.
추출 전에는 내용 기반 문항 총수/단원 수를 확정하지 않는다.

- 단원7개/요청5권: 합칠 기준이나 권수 변경을 제안하되 임의 누락·합치기 금지.
- 배점 없는 문항: 원문 배점 없음으로 표시. AI 난이도를 배점 대신 넣지 않는다.
- 미분류: 목적지 지정/별도 권/초안 유지 등 명시 처리. 조용히 버리거나 권수를 늘리지 않는다.
- 공통지문: 각 결과에 필요한 지문이 동반돼야 분리 가능. 못 보장하면 묶음 유지/보류.
- 일부 실패: 실패·미처리 쪽을 표시하고 성공분 사용을 명시 선택. 자동 유료 재시도 없음.
- 초안 복귀는 실제 저장 범위에 맞게 안내. 다른 기기 복귀나 탭 종료 후 계속 처리를 약속하지 않는다.

'문제집 N개 만들기' 후 여러 권이면 결과 목록과 각 '편집하기', '라이브러리에서 보기'를 제공한다.
한 권이면 편집기로 이어지는 안을 검증한다. 저장했다고 미확인 상태를 검토 완료로 바꾸지 않는다.

### 문항 편집 ↔ 전체 지면 배치

**같은 문제집의 두 보기**로 설계한다. 다른 앱/새 문서로 옮겨간다는 느낌을 만들지 않는다.
화면 이름 후보는 '문항 편집 / 지면 배치'. 전환해도 선택한 문항과 가능한 스크롤 위치를 이어간다.
이는 편집 모드 제안이며 모든 지면 글자를 직접 타이핑하는 완전한 WYSIWYG 구현을 뜻하지 않는다.

- 전체 지면: 페이지 축소판/번호 탐색 + 출력 지면 + 선택한 문항 설정.
- 긴 12번을 선택 → '한 단 하나' → 변경된 지면 확인. PDF 저장을 거치지 않는다.
- '함께 배치 / 한 단 하나 / 한 쪽 하나'가 실제 차지할 공간을 작은 예시와 함께 보여준다.
- 내용 수정이 필요하면 같은 문항 편집으로 이동했다가 지면으로 복귀한다.
- 잘림·자동 축소·그림/글꼴 준비 문제는 해당 위치와 연결한다. '확인할 문항 N개'에서 이동한다.
- 어려운 문제의 풀이 공간은 사용자가 판단. AI가 임의 배치하거나 조용히 전체 축소하지 않는다.
- 여백 크기(mm) 자유 조절은 별도 요구가 확정되기 전 추가하지 않는다. 기존 단/쪽 배치를 우선 활용한다.
- 렌더링 중에는 낡은 지면을 최신으로 표시하지 않는다. 변경 반영/준비 실패 상태와 재확인 경로를 둔다.
- 실제 출력 조립·보정·폰트/그림 준비와 경로를 공유한다. 별도 미리보기 조판기를 복제하지 않는다.
- PDF는 브라우저 인쇄 설정에도 영향을 받는다. 모든 출력 환경과 픽셀 단위 동일함을 보장하지 않는다.

## 5. 버튼과 상태 계약 초안

| 동작 | 범위·결과 | 실패/취소/되돌리기 |
| --- | --- | --- |
| 자료로 만들기 | 대량 작업 초안 열기, 아직 기존 문제집 변경 없음 | 돌아가기는 초안 폐기와 구분 |
| 문항 가져와 구성하기 | 안내한 범위의 AI 처리 시작 | 성공분 보존, 실패쪽 확인·사용자 재시도 |
| 새 구성안 보기 | 현재 자료로 변경 제안 | 적용 전 본문/현재 배치 불변 |
| 선택 문항 옮기기 | 선택한 문항과 목적지를 표시 | 한 번의 Undo로 관련 배치 복구 |
| 문제집 N개 만들기 | 초안을 실제 라이브러리 결과로 채택 | 이중 클릭/부분 저장 때 중복·거짓 완료 금지, 저장 계약 필요 |
| 한 단 하나 | 선택 문항의 출력 배치 변경 | 영향받은 묶음까지 정확히 복구, 다른 수동 배치 보존 |
| 지면 배치 | 같은 문제집 전체 출력 보기 | 돌아가도 선택·수정 내용 유지 |
| 내보내기 | 인쇄/PDF·문제집 파일·향후 HWPX를 목적별 구분 | 파일 생성/동기화/실제 인쇄 완료를 혼동하지 않음 |

Undo는 이미 발생한 AI 비용·외부 처리까지 취소하는 의미가 아니다.
저장 실패·충돌·검토 필요는 잠깐 뜨고 사라지는 토스트만으로 전달하지 않는다.
중요하지 않은 성공 피드백은 작고 짧게, 사용자의 선택이 필요한 문제는 지속 상태로 둔다.

## 6. 시각 디자인과 플랫폼 적용 범위

Apple에서 가져올 것은 조작의 예측 가능성과 정보 위계다. 브랜드 전체를 macOS로 복제하지 않는다.
현재 Pretendard 기반 UI, 파랑 강조, 중립 배경, 별도의 인쇄 서체를 출발점으로 둔다.
정확한 색·간격·밀도 변경은 시안 비교 뒤 결정한다. UI 장식이 문제 본문과 경쟁하지 않게 한다.
유리 효과/블러·과도한 애니메이션·아이콘만 있는 버튼을 목표로 삼지 않는다.
Apple 전용 글꼴·아이콘 파일의 재배포를 전제로 설계하지 않는다.

- 좁은 화면에서는 좌우 패널을 접되 현재 문항·기능·명확한 복귀 동선을 보존한다.
- Windows의 Ctrl와 macOS의 Cmd, 브라우저 뒤로 가기·확대·파일 선택 등 웹 관습을 존중한다.
- 터치는 충분한 누름 영역/간격, 키보드는 보이는 포커스·일관된 이동·대화상자 복귀.
- 색만으로 오류/선택/저장을 표현하지 않고 글·표시를 함께 제공한다.
- 시스템 동작 줄이기를 존중하고 문항 위치 파악을 방해하는 자동 애니메이션을 피한다.
- 다크 UI여도 인쇄 지면은 출력 내용을 판단할 수 있는 종이 표현을 유지한다.

보조 디자인 툴킷의 자동 추천은 랜딩페이지/일반 SaaS 성격이라 현재 편집기에 맞지 않아
색·폰트·페이지 구성은 채택하지 않았다. 범위를 좁힌 UX 검색에서는 포커스 가시성 등을 참고했다.
툴킷의 고정 헤더 높이 보정 예시는 이 저장소의 가변 상단바 계약과 맞지 않아 적용하지 않는다.

## 7. 현재 코드 접점과 검증할 것

읽기 전용 코드 확인 기준. 다음 구현 때 최신 위치와 계약을 다시 확인한다.

- index.html: #topActions, #setsActions, #selectBar — 전역/문제집/선택 동작의 분리 후보.
- #editorView, #paneTabs, #metaCard, #spanSeg, #previewArea — 편집↔지면 맥락과 선택 연결.
- buildPrintDoc / fitPrintDoc / doPrint, pedagogy-print.js의 problemGroups / spanOf — 실제 지면 경로.
- 기존 LIBRARY-UX-DESIGN.md, UX-FIXES-DESIGN.md는 과거 실측과 수정 근거이며 새 요구로 덮어쓰지 않는다.

구현 전에는 연결된 시안으로 다음 과제를 사용자와 확인한다.

1. 처음 들어와 PDF로5권 만들기와 직접 만들기를 설명 없이 찾는가.
2. 잘못 분류된 문항을 옮기고 취소하며 원문으로 돌아갈 수 있는가.
3. 긴 문항 잘림과 풀이 공간을 **PDF 생성 없이** 확인·수정할 수 있는가.
4. 내용 편집↔지면 전환 후 같은 문항을 다시 찾느라 헤매지 않는가.
5. 실패쪽·미분류·미검토·로컬 저장·클라우드 저장을 구별할 수 있는가.
6. 1194×834, 768×1024, 375×812에서 핵심 기능과 복귀 동선이 유지되는가.

첫 클릭, 완료 여부, 잘못 누른 횟수, 화면 왕복과 재출력 횟수를 관찰한다.
'Apple 원칙을 썼으니 쉽다'고 단정하지 않고 기존 흐름과 실제 과제를 비교한다.
코드 변경 시 관련 회귀와 실패 주입 검증, 출력 대조, 키보드·터치·접근성 검사를 별도로 수행한다.

## 8. 미결과 경계

- 공용 문항풀/복제와 수정 전파, 원문 PDF 보존기간, B4 순서는 별도 결정이다.
- 모의고사와 N제는 현재 별도 형식이다. 같은 UX 원칙을 쓰되 자동 변환이 이미 된 것처럼 표시하지 않는다.
- 기본 보기(문항/지면), 패널 초기 상태, 반복 사용자 시작 단축은 시안에서 확인한다.
- 새 실행 순서·담당자를 배정하지 않았다. 승인된 UX와 저장 계약의 접점을 정한 뒤 통합 레일에 반영한다.
