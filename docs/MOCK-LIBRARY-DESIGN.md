# 모의고사 라이브러리 전환 설계

## 결론

상단의 `모의고사` 버튼을 계속 전역 버튼으로 두지 않고, 라이브러리 제목 자리에
`문제집 라이브러리 | 모의고사 라이브러리` 세그먼트 전환을 둔다. 다만 현재 모의고사
편집기는 한 개의 `MOCK_DRAFT_V1` 임시본과 JSON 파일 저장만 지원하므로, 화면만 먼저
바꾸지 않는다. 다중 저장 모델과 구형 임시본 이전을 같은 배포에서 완성해야 한다.

현재 맥북에서 `모의고사`와 `AI 문서 β`가 붙거나 겹쳐 보이는 문제는 다중 라이브러리와
별개로 즉시 고친다. `AI 문서 β`의 음수 여백을 제거해 전환 전에도 실제 간격을 확보한다.

## 정보 구조

- 라이브러리 헤더의 제목을 키보드 조작 가능한 세그먼트로 바꾼다.
  - `문제집 라이브러리`
  - `모의고사 라이브러리`
- 선택 상태는 URL 해시 또는 쿼리(`library=sets|mocks`)에 반영해 새로고침·뒤로가기를
  보존한다. `aria-current` 또는 `role="tablist"`/`role="tab"` 계약도 함께 둔다.
- 상단 바에서는 `모의고사` 버튼을 제거한다. `AI 문서 β`는 두 라이브러리와 다른 도구이므로
  상단 유틸리티로 유지한다.
- 모의고사 라이브러리에는 `+ 새 모의고사`, 검색, 정렬, 가져오기와 카드 격자를 둔다.
  카드는 시험명, 선택과목, 문항 수, 마지막 수정 시각을 보여주며 열기·복제·내보내기·삭제를
  제공한다. 카드 전체 클릭과 점 메뉴의 역할은 문제집 카드와 같게 맞춘다.
- 빈 화면은 “새 모의고사 만들기”와 “기존 JSON 가져오기” 두 행동만 제시한다.

## 저장 모델

문제집 `sets` 배열에 모의고사를 섞지 않는다. 문제집과 모의고사는 스키마, 출력 엔진,
이미지 수명과 저장 정책이 달라 한 배열에 넣으면 정규화·클라우드 병합·삭제 계약까지
불필요하게 결합된다.

```js
{
  v: 1,
  id: "mock_<uuid>",
  name: "2027학년도 6월 모의평가",
  round: "2027학년도 6월 모의평가",
  elective: "미적분",
  problems: [],
  createdAt: 0,
  updatedAt: 0
}
```

- 로컬 키는 계정별 `PM_MOCK_SETS_V1:<owner>`와 마지막 선택 ID를 사용한다. 비로그인 사용자는
  별도 guest 소유자로 격리한다.
- 편집기는 선택된 `mockId`만 읽고 1초 디바운스로 해당 항목을 저장한다. 현재 전역
  `MOCK_DRAFT_V1`에 모든 작업을 덮어쓰는 방식은 제거한다.
- 1차 구현은 로컬 다중 저장에 한정한다. 클라우드 동기화는 문제집과 같은 tombstone,
  계정 전환 세션 가드, 충돌 병합 계약을 갖춘 뒤 별도 capability로 켠다.
- JSON 내보내기는 현재 `v:1` 문서 형식을 계속 읽게 하고, 라이브러리 전체 백업에는 종류와
  스키마 버전을 명시한다.

## 구형 임시본 이전

1. 새 모의고사 저장소가 비어 있고 `MOCK_DRAFT_V1`이 유효할 때만 이전 후보로 잡는다.
2. 사용자의 확인 후 `복구된 모의고사` 카드 한 개로 복사한다. 원본 키는 즉시 지우지 않고
   이전 완료 마커와 함께 한 릴리스 동안 보존한다.
3. 새 카드 저장을 다시 읽어 내용이 동일한지 확인한 뒤에만 구형 키를 정리할 수 있다.
4. 취소·파싱 실패·용량 초과 때는 구형 키를 보존하고 JSON 다운로드 경로를 제공한다.
5. 이전은 반복 실행해도 카드가 중복 생성되지 않도록 원본 지문 또는 migration marker로
   멱등성을 보장한다.

## 구현 순서와 완료 기준

1. `mock-library-store.js`에 정규화·CRUD·복제·가져오기·구형 이전을 순수 함수와 저장 어댑터로
   분리하고, 실패 주입 검사를 먼저 만든다.
2. 라이브러리 세그먼트와 모의고사 카드 화면을 연결한다. 이 단계가 끝날 때 상단
   `모의고사` 버튼을 제거한다.
3. `mock-exam-editor.html`이 부모가 전달한 `mockId`를 편집하도록 바꾸고, 자동 저장 성공·실패
   상태를 눈과 화면낭독기에 알린다. iframe 직접 접근보다 `postMessage` 계약을 우선한다.
4. 기존 JSON 저장·불러오기, HWPX·Typst 출력과 닫기 경고를 모두 회귀한다.
5. 1194×834 맥북, 768×1024 아이패드 세로, 375×812 휴대폰에서 전환·CRUD·키보드·overflow를
   검사한다.

완료 조건은 “여러 카드를 만들 수 있음”만이 아니다. 새로고침 후 각각 복구, 복제본 ID 독립,
다른 계정 자료 미노출, 저장 공간 실패 시 경고, 구형 임시본 무손실, 삭제/Undo 정책 명시,
JSON 왕복 및 기존 출력 동일을 모두 통과해야 한다.

## 이번 변경의 경계

이번 변경은 라이브러리 액션 버튼과 폴더 필터 배치를 다듬고 현재 상단 겹침을 제거한다.
다중 모의고사 저장은 위 계약을 한 번에 구현할 다음 작업으로 남긴다. 데이터 계층 없이
세그먼트만 노출하면 사용자가 여러 모의고사가 안전하게 저장된다고 오해하므로 의도적으로
화면만 선행하지 않는다.

## 구현 결과 (2026-09-09 · Claude)

위 설계의 다섯 단계를 모두 구현했다. 설계와 **다르게 한 것**과 **아직 안 한 것**을 아래에
적는다 — 그것을 안 적으면 다음 사람이 '설계대로 다 됐다' 고 읽는다.

### 설계대로 한 것

1. `mock-library-store.js` — 정규화·CRUD·복제·정렬·저장 어댑터·구형 이전을 순수 함수로 뺐다.
   실패 주입 검사(`npm run test:mock-library`)를 **먼저** 만들었고, 그 검사가 실제로 결함
   둘을 잡았다 — `crypto` 가 없는 환경에서 모든 id 가 `mock_00000000` 으로 같아지던 것과,
   저장 실패를 성공으로 보고할 수 있던 경로.
2. 라이브러리 헤더의 세그먼트 전환(`role="tablist"`, 좌우 화살표, `#library=mocks` 해시)과
   모의고사 카드 화면. **상단 바의 전역 `모의고사` 버튼은 제거했다.**
3. `mock-exam-editor.html` 은 본체가 `postMessage` 로 준 `mockId` 를 편집한다. 저장 상태는
   눈(`#hostStatus`)과 화면낭독기(`role="status"`) 양쪽에 간다.
4. JSON 저장·불러오기, Typst·HWPX 출력, 닫기 경고를 회귀로 확인했다.
5. 1194×834 · 768×1024 · 375×812 에서 전환·CRUD·키보드·가로 넘침을 확인했다.

### 설계와 다르게 한 것 (이유 포함)

- **카드 이름과 `round` 를 한 값으로 묶었다.** 설계는 `name` 과 `round` 를 따로 두었는데,
  둘이 갈리면 카드와 시험지 머리가 서로 다른 이름을 말한다. 스키마에는 두 필드를 그대로
  두되 **한쪽만 바꿀 수 없게** 했다(편집기의 제목 입력 = 카드 이름 = `round`).
- **`mock-exam-editor.html` 을 단독으로 열면 예전 그대로 `MOCK_DRAFT_V1` 하나를 쓴다.**
  설계는 "전역 임시본 방식을 제거한다" 고 했지만, 단독 실행에는 라이브러리 화면이 없어
  임시본을 없애면 **크래시 안전망만 사라진다.** 본체 안(`hostEmbedded`)에서만 카드 저장을
  쓰고, 단독 경로는 손대지 않았다. 그래서 구형 이전이 읽을 원본도 계속 남는다.
- **마지막으로 연 카드는 `sessionStorage` 에 둔다.** 설계는 저장 위치를 정하지 않았는데,
  문제집의 `rememberSet()` 이 같은 이유로 sessionStorage 다 — '새로고침은 이어서, 탭 닫았다
  들어오면 라이브러리' 의 경계가 정확히 그 수명이다.
- **닫는 순간의 저장을 본체가 직접 당겨 읽는다.** 1초 디바운스가 그대로 손실 창인데,
  탭이 닫히면 iframe 이 보낸 postMessage 가 우리 차례까지 못 온다. 같은 출처일 때만
  `contentWindow.currentData()` 를 동기로 읽어 쓴다(쓰는 곳은 여전히 본체 하나다).
  `file://` 은 출처가 달라 이 보정이 안 걸린다 — 거기서는 최대 1초를 잃을 수 있다.

### 클라우드 동기화 (2026-09-09 · 같은 세션에서 이어서 함)

SaaS 로 내놓는 이상 '이 기기에만' 은 기능 미완성이 아니라 결함이라 판단해 바로 했다.
**문제집과 같은 계약을 그대로 재사용했다** — 새 모델을 만들지 않았다.

- `users/{uid}/mocks/{mockId}` **한 부 = 한 문서** · tombstone 삭제 · `updatedAt` 병합 ·
  `onSnapshot` 반영. `firestore.rules` 에 같은 모양의 화이트리스트를 넣었다.
- **그림은 문서에 담지 않는다.** 편집기가 본체를 거쳐 Storage(`users/{uid}/images`)에
  올리고 주소만 남긴다. 담아 두면 시험지 한 부가 1MiB 한도를 그냥 넘고, localStorage 도
  넘친다. 계정 삭제의 `wipeStorageImages()` 가 그 폴더를 훑으므로 파기 경로가 자동으로 맞는다.
- **계정 삭제가 모의고사도 지운다.** 개인정보 파기는 나중에 붙이는 기능이 아니다.
- **단계 플래그 `mockCloudSchema` 는 0 으로 내보낸다.** Rules 를 먼저 배포하고 1 로 올린다 —
  순서를 뒤집으면 로그인 사용자의 저장이 전부 '권한 오류' 로 실패한다.

⚠️ **한글 내보내기는 그림 바이트가 필요하다.** 주소만 있는 그림은 편집기가 내보내기
직전에 `fetch` 해서 바이트로 바꾼다(조판기 두 사본에 주소 개념을 넣지 않으려는 seam 이다).
**그 fetch 는 Storage 버킷의 CORS 설정이 있어야 한다** — 없으면 그림이 빠지고 사용자에게
그렇게 말한다(조용히 자리표시로 내보내지 않는다). 한 번만 하면 되는 버킷 설정이다.

### 아직 안 한 것
- **삭제 Undo 가 없다.** 문제집의 Undo 는 `sets` 스냅샷 위에 서 있고 모의고사는 그 스냅샷
  밖이다. 대신 삭제 확인창이 "되돌릴 수 없습니다" 라고 **명시**한다(설계의 '삭제/Undo 정책
  명시' 를 이렇게 지켰다). Undo 를 넣으려면 스냅샷 모델을 함께 정해야 한다.
- **폴더는 문제집에만 있다.** 모의고사 카드 수가 늘면 그때 정한다.
