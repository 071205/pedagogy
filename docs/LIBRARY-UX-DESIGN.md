# 라이브러리 화면 재설계 — 설계안 (검토 요청)

- 상태: `1~3단계 구현 완료 · 4단계 미착수` · 검토자: Codex
- 나온 곳: 해리의 실사용 신고 넷 + 실측
- ⚠️ 처음 쓸 때는 구현 전이었다. **§8 에 구현 결과와 다시 잰 값을 적었다** — 목표치만 적고
끝내면 좋아졌는지 알 수 없다.

## 0. 먼저 잰 값 (지어낸 값이 아니다)

문제집 14개를 넣고 크로미움으로 쟀다. `카드 시작 y` 는 **화면 위에서 카드가 시작하는
지점**이고, 그만큼이 라이브러리가 아니라 머리에 쓰이는 자리다.

| 화면 | 상단바 | 헤더 | 검색줄 | 푸터 | 카드 시작 y | 카드에 남는 높이 | 보이는 행 |
|---|---|---|---|---|---|---|---|
| 맥북13 크롬 1512×760 | 60 | 44 | 44 | **116** | **228 (화면의 30%)** | 416 | **3.6행** |
| 아이패드 가로 1194×834 | 56 | 44 | 44 | 116 | 224 (27%) | 494 | 4.2행 |
| 맥북16 1728×900 | 60 | 44 | 44 | 116 | 228 (25%) | 556 | 4.8행 |
| 휴대폰 390×760 | 56 | **144** | **100** | **155** | **364 (48%)** | 241 | **2.1행** |

**해리의 3번 신고("라이브러리가 중요한데 별로 많이 안 들어가는 느낌")는 정확하다.**
데스크톱에서 화면의 **30%**, 휴대폰에서 **48%** 가 카드가 아닌 것에 쓰인다.
그리고 4번(설정)·2번(푸터)도 결국 같은 원인이다 — **띄울 자리가 없어서 위아래로 쌓았다.**

## 2. §2 — 왼쪽 레일 (핵심 제안)

### 무엇을

상단에 가로로 쌓인 **세 층을 왼쪽 한 줄로 세운다.**

```
┌────────┬──────────────────────────────────────────┐
│ P      │  문제집 라이브러리            [+ 새 문제집] │  ← 헤더 1줄
│        │  [검색                    ]      정렬 선택 │  ← 도구 1줄
│ 문제집 │  ┌────┐┌────┐┌────┐┌────┐┌────┐          │
│ 모의고사│  └────┘└────┘└────┘└────┘└────┘          │
│ AI 문서│  ┌────┐┌────┐┌────┐┌────┐┌────┐          │
│        │  └────┘└────┘└────┘└────┘└────┘          │
│ ─────  │  ┌────┐┌────┐┌────┐┌────┐┌────┐          │
│ 폴더   │  └────┘└────┘└────┘└────┘└────┘          │
│  ㅎㅇ  │                                           │
│  폴더없음│                                          │
│ ─────  │                                           │
│ 설정   │                                           │
│ 계정   │                                           │
└────────┴──────────────────────────────────────────┘
```

- **레일에 들어가는 것**: 라이브러리 종류(문제집·모의고사) · AI 문서 · **폴더 목록** ·
  설정 · 데이터 관리 · 계정.
- **상단에 남는 것**: 없다. 상단바 자체를 없애고, 편집기에서만 쓰는 동작
  (`#topActions`)은 편집기 화면의 자기 머리로 옮긴다.
- **본문에 남는 것**: 제목 한 줄(+ 주 액션 하나) · 검색 한 줄.

### 왜 이게 세 신고를 한꺼번에 푸는가

- 세로 3층(148px) → **1층(≈44px)**. 카드 시작 y 228 → **약 100** (실측 후 확정).
  맥북13에서 보이는 행 3.6 → **약 5.4행**.
- 폴더 칩이 가로 자리를 다투지 않는다 — 폴더가 20개여도 세로로 스크롤하면 된다.
  (지금은 폴더가 늘면 검색줄이 줄바꿈해 본문을 아래로 민다)
- 라이브러리 전환이 '탭' 이 아니라 **자리**가 된다. 지금 세그먼트는 제목 자리를 뺏고 있다.

### ⚠️ 위험과 되돌리기

- **375px 에서 레일은 폭을 먹는다.** 휴대폰에서는 레일을 **하단 탭바**로 바꾸거나
  햄버거로 접는다. ⚠️ 하단 탭바는 iOS 사파리의 주소창과 겹치기 쉬우므로 `dvh` 와
  `env(safe-area-inset-bottom)` 을 함께 봐야 한다(이 저장소는 `viewport-fit=cover` 를
  쓰지 않기로 했다 — 그 결정을 뒤집는 것이라면 **별도 판단이 필요하다**).
- **`test:cross` 의 '상단 바 왼쪽 묶음이 붙어 있다'** 검사는 상단바가 사라지면 의미를
  잃는다. 지우지 말고 **레일 항목 사이 간격**을 재는 것으로 옮긴다(`REV-2026-063` 이
  잡았던 것은 '보이지 않는 채움에 기댄 레이아웃' 이고 그 위험은 레일에도 있다).
- **`check-accessibility`** 의 브랜드 버튼 계약(`aria-label="문제집 라이브러리로 이동"`)과
  건너뛰기 링크 대상이 바뀐다. 레일은 `<nav aria-label="라이브러리 탐색">` + 각 항목
  `aria-current="page"` 로 만든다.
- **`test:library-ui`** 의 탭 계약(`#tabSets`·`#tabMocks`·`aria-selected`)이 레일 항목으로
  옮겨간다. **id 를 유지**하면 검사 수정이 최소가 된다 — 그렇게 하자.
- 되돌리기: 레일은 CSS `grid-template-columns` 한 줄과 마크업 한 덩어리다.
  플래그 없이 커밋 단위로 되돌릴 수 있다.

## 3. §3 — 푸터를 두 줄로

지금 네 줄이다. 데스크톱 116px · 휴대폰 **155px**.

| 줄 | 지금 | 제안 |
|---|---|---|
| 이용약관 · 개인정보처리방침 | 있음 | **유지** |
| "로그인 전 이용약관·개인정보처리방침과 AI 이미지 국외 처리 안내를 확인해 주세요" | 있음 | **삭제** |
| © 2026 PEDAGOGY · 모든 권리 보유 | 있음 | **유지** |
| "본 제품은 한글과컴퓨터의 …" | 있음 | **옮긴다** (§3.1) |

**동의 안내 줄을 지우는 근거**: 이제 로그인 직전에 **항목별 동의 창**이 약관·방침·국외이전을
각각 전문 링크와 함께 받는다(`HANDOFF-2026-093`). 푸터의 한 줄짜리 안내는 그 절차가
없던 시절의 대체물이었고, 지금은 **중복**이다. 동의를 받는 곳이 둘이면 어느 쪽이 진짜인지
흐려진다.

### 3.1 ⚠️ 한컴 고지는 마음대로 못 옮긴다 — **여기가 검토 요청의 핵심이다**

한컴 수식 규격서의 저작권 조항은 그 문장을 **유저인터페이스·매뉴얼·도움말·소스에 모두**
적으라고 요구하고, `check:static` 이 지금 **여섯 곳**을 지킨다.

- 제안: 푸터에서 빼되 **UI 안에 남긴다** — `설정 → 정보` 화면(§4)과 모의고사·AI 문서의
  내보내기 흐름. `legal.html`(매뉴얼)에는 그대로 둔다.
- 그러면 `check:static` 의 대조 대상 목록을 함께 고쳐야 한다.
- ❓ **코덱스에게**: 상시 노출(푸터)에서 한 단계 들어간 곳(설정 → 정보)으로 옮기는 것이
  "유저인터페이스에 적는다" 를 충족한다고 볼 수 있는가? **아니라고 보면 푸터에 남긴다** —
  그 경우 푸터는 세 줄이 되고, 글자를 12px→11px 로 줄이고 한 줄로 합치는 선에서 그친다.

## 4. §4 — 설정을 왼쪽 탭 화면으로

지금은 520px 모달 하나에 전부 세로로 쌓여 있다. 항목이 늘수록 스크롤만 길어진다.

```
┌─────────────┬────────────────────────────┐
│ 화면         │  테마      ○ 시스템 ● 밝게 │
│ 언어         │  글자 크기 ─────○───       │
│ 인쇄         │  밀도      ● 편안 ○ 조밀   │
│ 데이터       │                            │
│ 계정         │                            │
│ 정보         │                            │
└─────────────┴────────────────────────────┘
```

- 갈래: **화면**(테마·밀도) · **언어** · **인쇄**(용지·머리글 안내) · **데이터**(백업 복구·
  전체 삭제·계정 삭제 = 지금 `#dataModal`) · **계정**(로그인 정보·동의 기록·로그아웃) ·
  **정보**(버전·오픈소스·법률 문서 링크·한컴 고지).
- **`#dataModal` 을 여기로 흡수한다.** 지금 '설정' 과 '데이터 관리' 가 상단에 **따로**
  있는데 사용자에게는 같은 갈래다(신고 3번의 '버튼이 많다' 에 직접 기여한다).
  ⚠️ **흡수하되 안전장치는 그대로 옮긴다** — `wiping` 플래그, 구독 해제, 계정 삭제 순서
  (재인증 → 이미지 → 문제집 → 모의고사 → 사용자 문서 → Auth). 그 순서를 바꾸면
  '데이터는 날아갔는데 계정은 남은' 상태가 생긴다.
- 좁은 화면에서는 좌측 탭이 위쪽 가로 스크롤 탭으로 접힌다.
- ❓ **코덱스에게**: 모달 안의 좌우 분할로 갈까, 아니면 **전체 화면**(라이브러리·편집기와
  같은 층의 네 번째 뷰)으로 갈까? 전체 화면이면 주소(`#settings/data`)로 딥링크가 되고
  '데이터 관리' 같은 위험한 조작에 되돌아올 자리가 생긴다. **전체 화면을 권한다.**

## 5. 내가 더 제안하는 것 (해리가 말하지 않은 것)

우선순위 순. 앞의 셋은 §2 와 같이 하면 이득이 크고, 뒤로 갈수록 선택이다.

1. **카드 밀도 선택(편안/조밀)** — 카드가 101px 인데 담는 것은 이름·문항 수·과목뿐이다.
   조밀 모드는 한 줄짜리 리스트(≈44px)로 바꿔 **한 화면에 3배**를 담는다.
   문제집이 14개를 넘어가면(해리는 이미 14개다) 이쪽이 기본이 되어야 할 수도 있다.
2. **⌘K 명령 팔레트** — 검색줄(44px)을 본문에서 걷어내고 키보드로 연다. 문제집·모의고사·
   폴더·설정을 한 곳에서 찾는다. ⚠️ **검색 입력을 없애지는 않는다** — 손가락 사용자와
   단축키를 모르는 사용자에게 검색이 사라지면 안 된다(레일 위 작은 검색 아이콘으로 남긴다).
3. **스크롤하면 접히는 머리** — 카드를 내리는 동안 제목 줄이 접혀 자리를 돌려준다.
   ⚠️ 접히는 높이를 상수로 빼지 말 것(`REV-2026-028` — `calc(100dvh - 60px)` 사고).
4. **카드에 '마지막 연 시각'** — 지금 정렬은 최근 수정순을 지원하는데 카드에는 시각이
   안 보인다. 모의고사 카드에는 이미 있다(둘이 갈려 있다).
5. **첫 방문 빈 화면** — 지금 "오른쪽 위 '+ 새 문제집'" 이라고만 한다. 레일로 옮기면 그
   안내가 틀려진다. 시작 경로 셋(새로 만들기 · JSON 가져오기 · 사진으로 AI 변환)을 카드로.
6. **모의고사 카드와 문제집 카드의 모양 통일** — 지금 모의고사에만 수정 시각이 있고
   문제집에만 폴더 이름이 있다. 같은 그리드에 사는 두 카드가 다르게 생겼다.

## 6. 단계와 완료 기준

한 번에 하지 않는다. 각 단계가 **혼자서 되돌릴 수 있어야** 한다.

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| 0 | (완료) AI 문서 → 모의고사 링크 수정 + 정적 검사 | `check:static` 초록 |
| 1 | 푸터 축약 (§3) — 한컴 고지 결정 뒤 | 데스크톱 푸터 116→**56px 이하** · 여섯 곳 대조 유지 |
| 2 | 왼쪽 레일 (§2) | 카드 시작 y **228→110 이하** · 네 화면 넘침 0 · 키보드로 레일 이동 · 기존 id 유지 |
| 3 | 설정 화면 (§4) | 데이터 관리 흡수 · **계정 삭제 순서와 `wiping` 가드가 그대로** · 딥링크 |
| 4 | 밀도·팔레트 (§5-1,2) | 조밀 모드에서 한 화면 카드 수 **2.5배 이상** |

**⚠️ 단계마다 실측을 다시 붙인다.** 위 표의 '카드 시작 y' 는 지금 값이고, 목표치는
구현 뒤 같은 스크립트로 다시 재서 이 문서에 적는다. 재지 않으면 좋아졌는지 알 수 없다.

## 7. 코덱스에게 묻는 것 (셋)

1. **한컴 고지**(§3.1) — 푸터에서 `설정 → 정보` 로 옮겨도 "유저인터페이스에 표시" 를
   충족하는가? 아니면 푸터에 남겨야 하는가?
2. **설정**(§4) — 모달 좌우 분할 vs 전체 화면 뷰. 나는 전체 화면을 권한다(딥링크·되돌아갈
   자리). 위험한 조작(계정 삭제)이 모달 밖으로 나가는 것이 괜찮은가?
3. **모바일 레일**(§2) — 하단 탭바로 가면 `env(safe-area-inset-bottom)` 이 필요하고,
   이 저장소는 `viewport-fit=cover` 를 **일부러 안 쓰기로** 했다. 그 결정을 건드리지 않고
   하단 탭바를 만들 수 있는가, 아니면 햄버거로 접는 쪽이 맞는가?

그리고 §5 의 여섯 중 **어디까지가 지금 할 일인지** 잘라 달라. 전부 하면 한 번에 너무 크다.

## 8. 구현 결과 (2026-09-09) — 다시 잰 값

### 화면을 봐야 찾은 것 셋 (검사는 전부 초록불이었다)

- **고른 폴더의 글자가 안 보였다.** 배경만 되돌리고 `color:#fff` 를 그대로 두어 밝은 바탕에
  흰 글자가 얹혔다. 계산된 스타일로는 정상이다.
- **폴더 이름이 '수학' → '수' 로 잘렸다.** 이름이 글자 노드라 익명 flex 항목이 되어 줄임표가
  안 걸렸다. `span` 으로 감쌌다.
- **그러고도 이름 칸이 26px 에 머물렀다.** 계산된 값은 `flex:1 1 0%` 인데 자라지 않았다 —
  예전 `.folder-group>.folder-chip:first-child{display:block}` 규칙과 얽혀 있었다.
  **flex 를 포기하고 grid(`minmax(0,1fr) 30px`)로 바꿨다** — 첫 칸이 남는 폭을 갖는 것이
  정의라 얽힘이 없다.
