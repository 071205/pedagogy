# Claude·REA 중단 사례 조사와 H1 재개 판단

- 조사일: 2026-10-15 · Codex
- 범위: 사용자가 전달한 Claude의 중단 설명, 현재 저장소/기존 실행 결과, 공개 1차 자료.
- 결론: **응답 안전 검사에 의한 중단이 유력하지만 원시 오류가 없어 분류·오탐 여부는 미확정**이다.
  REA 설치 실패, 실행 승인 거절, 시간 초과, 모델 응답 거절을 각각 구분해야 한다.

## 1. 이번 환경에서 확인한 것

## 2. 공개 사례 — 제안과 검증된 결과 구분

### A. 도구 결과가 들어온 뒤 정책 응답이 나오는 사례

2026-04-15 [Claude Code #48571](https://github.com/anthropics/claude-code/issues/48571)은
격리된 환경의 ASan/LSan 충돌 추적 결과를 받은 다음 모델 응답이 cyber 정책 오류로 중단됐다고 보고했다.
작성자는 오래된 모델 사용을 대안으로 적었지만 통제된 성공률은 제시하지 않았다.
이 이슈는 비활성으로 자동 종료됐으며 해결된 결함이라는 증거가 아니다.
한글 호환성 분석과 같은 작업은 아니지만 **도구 실행 성공 후 다음 응답에서 멈추는 구조**가 유사하다.

Anthropic의 [공식 설명](https://support.claude.com/en/articles/16049681-why-claude-switched-models-in-your-conversation-with-opus-5-or-opus-5-5)은
사용자 메시지뿐 아니라 읽어 온 파일·검색·연결 자료도 자동 검사의 대상이라고 명시한다.
따라서 사용자 질문이 정상이어도 이후 입력이 된 자료와 문맥을 살펴야 한다.
다만 이 설명만으로 한글 의사코드가 실제 원인이라고 확정할 수 없다.

### B. ‘역공학’ 오류 문구의 원인이 다른 지시였던 사례

2026-09-19 [Claude Code #95561과 작성자 정정](https://github.com/anthropics/claude-code/issues/95561)은
처음 정상 업무 23건의 `reasoning_extraction` 차단을 오탐으로 주장했다.
같은 날 후속 실험에서 자신의 래퍼에 내부 추론을 응답으로 서술하도록 요구하는 지시가 있었음을 확인했다.
보고된 비교는 추가 지시 없음 0/5 거절, 전체 지시 5/5 거절, 해당 문장 제거 0/3 거절이었다.
작성자는 대부분을 오탐이라고 했던 주장을 철회했다. 다른 미해결 사례도 따로 남겼다.

적용: 출력 요구가 **작업 진행·근거·결론**인지 **모델 내부 사고 원문**인지 구분한다.
이 저장소의 AGENTS/CLAUDE/HWP 스킬/검토 래퍼/설계에서 관련 표현을 좁게 검색했으나
그 사례와 같은 요구는 찾지 못했다. 전역 설정·모든 플러그인·실제 중단 세션까지 검사한 것은 아니다.
따라서 이를 이번 원인이라고 주장하지 않는다.

### C. 실제 REA 이용자들의 최근 중단 보고

2026-10-12 [REA #2095](https://github.com/morluto/rea/discussions/2095)는
Claude Code·Codex·Cursor에서 역공학 작업이 막힌다고 보고한다.
원래 작업·프롬프트·오류가 공개되지 않았고, 모델/실행 도구 교체 제안의 성공 증거도 없다.
[REA #2027](https://github.com/morluto/rea/discussions/2027)도 Cursor의 거절을 보고하지만 답변과 재현 자료가 없다.
**‘다른 제품이나 로컬 모델로 바꾸면 해결된다’는 근거로 삼을 수 없다.**

[REA #2304](https://github.com/morluto/rea/discussions/2304)는 한 함수·한 형식·한 질문으로
범위를 명료하게 하고 실제 권한·목적을 정확히 설명하며 오탐을 신고하자는 정리다.
사용자가 Claude로 작성한 커뮤니티 글이므로 Anthropic의 공식 승인이나 해결 실험으로 취급하지 않는다.

### D. 정책처럼 보이지만 전송량·재개 오류인 사례

2026-01-27 [Claude Code #21120](https://github.com/anthropics/claude-code/issues/21120)은
약 1MB 이상의 MCP 결과가 있는 세션을 재개할 때 멈췄고, 기록 크기를 줄인 뒤 재개됐다고 보고했다.
구버전 2.1.17의 사례로 현재 버전에서 재현됐다고 볼 수 없다. 세션 원문을 임의로 잘라 고치는 방법은 채택하지 않는다.

REA의 [공식 MCP 계약](https://github.com/morluto/rea/blob/main/docs/mcp-contracts.md)은
큰 결과를 Evidence로 보존하고 요약·페이지 단위로 읽는 경로를 제공한다.
또 Ghidra 시작 허용 시간과 MCP 클라이언트 대기 시간이 별개임을 설명한다.
**transport 용량 오류나 timeout이 확인됐을 때** 해당 경로를 쓴다. 모델 거절을 분할 출력으로 우회하는 용도가 아니다.
설치된 6.4.0과 최신 문서의 도구 지원 차이는 실제 도구 목록으로 확인한다.

## 3. 원인별 대응

| 관찰된 오류 | 다음 행동 | 완료 증거 |
| --- | --- | --- |
| MCP 도구 호출 전에 permission/approval 거절 | 요청 동작·경로·외부 전송을 특정하고 필요한 승인만 받기 | 같은 승인 범위의 호출 실행 결과 |
| provider/architecture 오류 | 해당 공급자 진단·지원 아키텍처 확인. 원본을 유지한 분석 사본 사용 | 대상 해시·공급자·정상 분석 결과 |
| transport/timeout | 진행/종료 코드 확인, 보존 Evidence의 요약·페이지 회수, 실제 병목의 대기 시간 조정 | 완전/부분 범위와 남은 공백 명시 |
| 모델의 refusal/fallback | 가능하면 category·요청 ID·실제 모델·시점을 수집해 공식 지원에 최소 재현 신고 | 지원 회신 또는 허용된 요청의 독립 성공. 재시도 횟수는 증거가 아님 |
| 일반적인 ‘시스템이 막았다’ 설명만 있음 | raw error와 모델 자체 설명을 구분하고 미확정으로 기록 | 오류 유형을 입증하는 로그/알림 |

[Claude 권한 문서](https://code.claude.com/docs/en/permissions)와
[샌드박스 문서](https://code.claude.com/docs/en/sandboxing)는 실행 권한과 OS 경계를 다룬다.
응답 분류기 문제를 해결하려고 포괄 권한이나 샌드박스 해제를 적용하지 않는다.
모델 거절에 대한 공식 대응은 피드백과 해당 서비스가 제공하는 복구 절차다.
[CVP](https://support.claude.com/en/articles/14604842-cyber-verification-program)는 사이버 업무를 위한 제도이며,
이번 문서 조판 호환성 연구가 신청 대상이거나 승인될 것이라고 보장할 수 없다.

신고 초안에 필요한 최소 정보: 작업 목적(HWPX 호환성), 실제 앱/모델 버전, 시점,
마지막 도구 이름, 오류 범주·요청 ID, 제3자 코드를 포함하지 않는 재현 설명.
원본 바이너리·의사코드·사용자 문서를 공개 이슈에 첨부하지 않는다. 이번에는 신고를 발송하지 않았다.

## 4. H1을 계속 진행할 방법

1. **현 상태 먼저 고정**: `2547a1e`의 Claude 하네스 수정분을 Codex가 독립 검토한다.
   한글이 앞에 없을 때 접근성 창 목록이 비는 현상과 `activate`의 범위를 확인한다.
2. **기존 증거 재사용**: 함수 5개 분석·8개 열기 표본·PDF 관찰에서 이어간다.
   Codex가 이전에 생성한 4개 재저장 파일과 재열기 보고서도 로컬에 남아 있다.
   현재 문서에는 미반영이므로 입력 해시·본문·환경을 재대조하고 기록한다.
3. **다음 REA 질문을 좁힘**: `0x69cc78`의 구역 개수 출처와 ID 조회 의미.
   여러 구역의 정상/ID 누락/순서 변형 표본과 비교해 정적 추론을 검증한다.
4. **제품 개선으로 연결**: 실증된 규칙만 생성기·validator 진단 후보로 정리하고
   Python/JS 계약·반례·red를 갖춘 H1-c 적용 계약으로 넘긴다.
5. **검토는 독립된 허용 범위로 진행**: Claude는 우리 소스·자체 제작 표본·실험 판정의 검토를 맡을 수 있다.
   이것은 디컴파일 결과의 재분석과 다른 검토이며, 내부 분석 독립 검증을 받았다고 표시하지 않는다.

공급자의 차단 원인/해제가 확인되지 않은 내용을 다른 모델로 자동 재전송하지 않는다.
Codex가 수행할 별도 요청도 HWPX 호환성 범위와 현재 실행 정책을 기준으로 판단한다.
누구든 제한을 만나면 해당 경로의 상태를 남기고 진행 가능한 실물 시험·우리 코드 검증을 계속한다.
완료한 질문마다 대상 해시·Evidence ID·관찰/추론·표본·다음 행동을 남겨 한 번의 중단이 연구 전체의 재시작이 되지 않게 한다.
