# REV-108 — 지문 묶음의 명시 소속과 권 버전 게이트

기준: `877a8e7`, 선행 판정: `0cc9945`와 [REV-108](../reviews/issues/2026-09/2026-09-23-index-passage-group-positional.md).
[HANDOFF-194](../reviews/handoffs/2026-10/2026-10-19-index-passage-membership.md)는 ①·② 구현과 검토 근거를 기록한다.
2026-10-19 후속 보완은 옛 로컬 검토 상태(REV-131), 2→1문항 안내(REV-132), 앱이 고르는 삽입 위치(REV-133),
묶음이 아닌 옛 안내의 출력(REV-134)을 수정했다. Claude Opus 2회차 검토는 131·132와 133의 정상 묶음,
D-a·D-b를 확인했고 133의 옛 묶음과 134를 새로 지적했다. Claude Opus 3회차는 그 두 변경분에 결함이 없다고 판정해 ①을 승인했다.
② 권 버전·Rules 쓰기 게이트는 2026-10-20~21에 구현·정상/RED로 검증했다. Claude 전반 정적 검토 후 REV-135·136을 추가 보완했고, 후속 Claude 검토는 두 번 시간 초과로 미완료다. 추가 수정의 독립 Codex 확인은 결함 미발견으로 마쳤고 Claude 재검토·운영 적용은 남아 있다.

## 저장과 진단

- `groupOf`는 같은 권의 대표 문항 ID다. 대표는 자신을 가리킨다. ID는 권 안에서 유일해야 한다.
- 대표가 앞에 있는 연속 구간, 최대 10문항만 유효하다. 대표에는 `passage` 또는 비어 있지 않은 `groupLead`가 있어야 한다.
- `groupSpan`은 소속으로부터 계산하는 호환용 값이다. 인쇄의 pair/col/page 배치와는 별개다.
- `groupReview`: `legacy`(옛 위치 모델), `invalid`(모호하거나 잘못된 참조/범위), `intake`(AI 공통지문 확인 필요).
  이 표식은 JSON·클라우드 정규화 뒤에도 보존한다. 표식이 있으면 정상 묶음으로 출력하지 않는다.
- 옛 활성 `groupSpan`은 위치상 후보와 `legacy`를 남긴다. 이미 손상된 옛 소속을 복구했다고 주장하지 않는다.
  지문·안내가 없어 비활성인 옛 값은 되살리지 않는다. 명시 소속 오류를 옛 위치 모델로 자동 강등하지 않는다.
- 로컬 디스크와 B3 pending 원본도 편집 전에 이관한다. 원본 디스크 비교값, 권·문항의 무관한 필드와 기존 고유 ID는 보존하고,
  삭제·무관한 관계 변경만으로 옛 검토 표식을 지우지 않는다.
- 누락된 대표, 중복 ID, 비연속/역방향 참조, 겹침·잘린 범위·수 불일치를 진단한다.
  본문과 문항을 버리지 않고, 사용자가 소속을 명시 재구성하도록 한다.

## API와 편집 경로

`pedagogy-normalize.js`의 공통 API를 사용한다.

| API | 계약 |
| --- | --- |
| `normGroupProblems(raw, opts)` | 모든 문항 ID를 먼저 발급하고 유일한 원본 ID 대응표로 내부 참조를 옮긴다. 모호한 참조는 진단한다. |
| `groupDiagnostics(arr)` / `validGroups(arr)` | 오류 위치·이유와 검증된 묶음을 반환한다. |
| `setGroupSpan(arr, leaderId, n)` | 사용자가 명시한 소속 재구성. 다른 정상 묶음을 침범하지 않는다. |
| `removeGroupedProblem(arr, i)` | 구성원 삭제 후 파생 크기를 갱신한다. 다른 구성원이 있는 대표 삭제는 차단한다. |
| `moveWholeGroup(source, target, leaderId, at)` | 전체 묶음을 새 ID로 재매핑해 옮긴다. 꼬리 ID를 통한 부분 이동과 대상 묶음 중간 삽입은 거절한다. |
| `detachedProblem(q)` | 독립 복제. 공유 지문에 의존하는 꼬리 문항만 복제하는 요청은 거절한다. |
| `insertionIndexAfterGroup(arr, afterIndex)` | 정상 명시 묶음 또는 구조가 유효한 `legacy` 후보 안쪽의 복제·JSON 붙여넣기는 마지막 구성원 뒤에 둔다. `invalid`·`intake`와 다른 위치는 유지한다. |
| `confirmableLegacyGroups(arr)` | 구조까지 확인된 `legacy` 대표만 일괄 확정 후보로 돌려준다. `invalid`·`intake`는 제외한다. |

- 대표만 이동 요청은 전체 묶음 이동으로 해석한다. 꼬리만 복제/이동은 조용히 지문을 잃게 하지 않고 차단한다.
  부분 분리 UI·권간 이동 UI는 U2 범위다. 이동 API 호출자는 권 저장과 원문 연결 권한을 별도로 확정해야 한다.
- 무관한 문항을 자동 가입시키지 않는다. 앱의 대표 복제·묶음 구성원 뒤 JSON 붙여넣기는 정상 명시 묶음과
  구조가 유효한 `legacy` 후보의 끝 뒤로 삽입한다. 옛 후보의 검토 표식·출력 차단은 그대로 유지한다.
  사용자의 재정렬 등으로 비연속 관계가 되면 진단하고 인쇄를 막는다.
- 안내만 있는 2문항 묶음이 구성원 삭제로 1문항이 되어도 남은 대표의 `groupOf===id`를 유지한다.
  이 대표의 안내는 범위 없이 미리보기·실제 출력에 표시하고 편집할 수 있다. 묶음이 아닌 문항의
  남은 `groupLead`는 편집기에 보존하되 출력하지 않는다. 명시 `이 문항만`/`묶음 풀기`는
  자기 참조 소속을 제거해 후자의 상태로 전환한다.
- 삭제·복제·붙여넣기·재정렬의 배열/소속/배치 변경을 Undo 스냅샷에 함께 넣는다.
- 여러 권의 JSON을 붙여넣을 때는 권마다 ID를 재매핑한 뒤 합친다. 다른 권의 ID는 연결 권한이 아니다.
- 권 복제와 충돌 사본은 권 메타데이터를 보존하고 문항 ID와 소속 참조를 함께 재발급한다.
- 검토 필요 대표와 고아 문항은 기존 묶음 선택 칸의 ‘다시 선택’에서 명시 재구성할 수 있다.
  검토 필요 대표는 같은 문항 수를 선택해도 확인된다. 정상 구성원은 대표에서 소속을 바꾼다.
- 미리보기 경고의 `옛 묶음 N개 확인하기`는 구조가 유효한 `legacy` 묶음만 범위·대표 첫 줄 30자·문항 수와 함께 보여 준다.
  항목별 `빼기`와 취소는 자료를 바꾸지 않는다. 확정은 한 `historyStep`이므로 Undo 한 번에 복원된다.
  대화상자를 연 뒤 owner·epoch·권·자료 또는 쓰기 권한이 바뀌면 확정하지 않는다.

## AI 채택과 출력

현재 AI 계약은 공통지문을 첫 `statement`에 포함한다. 문항 본문과 안전하게 자동 분리할 증거가 없으므로
채택 시 명시 소속과 `groupReview:'intake'`를 남긴다. 내용은 그대로 보존하며, 사용자가 대표의 지문·안내와
소속을 확인하기 전에는 범위 표시와 인쇄를 막는다. 추출 계약이나 실제 공급자 호출은 변경하지 않는다.
대표 지문·안내가 없으면 편집기에서 지문 블록으로 옮길 것 또는 `묶음 풀기`를 안내한다.
풀기는 `setGroupSpan(대표,1)`을 한 히스토리 단계로 적용하며 본문을 자동 분리하지 않는다.
같은 수 재선택으로 `intake` 표식만 지워도 대표 내용 진단이 남으면 이 안내와 풀기 단추를 유지한다.

`computeNums()`는 검증된 구성원 ID만 범위로 표시한다. 문항 미리보기에는 진단을 보이고,
`buildPrintDoc()`와 `doPrint()`가 오류 출력을 거절한다. 지면 조립 오류 때 기존 지면·축소판을 비워
옛 범위가 현재 결과처럼 남지 않게 한다. 브라우저 인쇄/PDF의 방어선이며 다른 편집기의 출력 계약까지
완료했다고 주장하지 않는다.

## ② 권 버전과 쓰기 게이트 — 구현·로컬 검증, 배포 전

- 지원 권 문서는 최상위 `setSchemaVersion:1`을 쓴다. `setToDoc()`가 새 권·복제·충돌 사본·복원 저장·AI 채택 저장·삭제 tombstone에 표식을 붙인다. `setJSON()`과 CAS 기준은 표식을 포함하되, 기존 무표식 문서의 지문은 유지하여 서버의 옛 본문을 읽을 수 있다. 같은 본문의 무표식 서버 revision도 새 저장 시 v1 다음 revision으로 승격하며, ACK 뒤 로컬 본문과 영속 동기화 기준을 한 번 맞춘다.
- Rules는 새 문서와 모든 다음 revision/tombstone에 정수 `1`을 요구한다. 기존 문서는 표식이 없거나 정수 `1`일 때만 새 revision을 받는다. 미래·손상 표식의 지원 버전 덮어쓰기를 막는다. 이 게이트는 **권 최상위 계약**이며 문항 배열 속 `groupOf`를 재귀 검증한다고 주장하지 않는다. 기존 owner·revision CAS·크기·삭제 권한은 유지한다.
- 무표식 문서는 읽고, 옛 `groupSpan`은 ①의 `legacy` 검토 상태로 이관한다. 지원 버전 저장 전까지 원본문항·ID·무관한 메타데이터를 보존한다. 미래·손상 버전은 알 수 없는 최상위·문항 필드와 비배열 자료도 **원형 그대로 로컬/백업/전체·선택 내보내기에 보존**하고 목록에서 읽기 전용으로 표시한다. 선택 내보내기의 정상 권은 기존처럼 `folderId`를 제외하지만 미래 권은 뜻을 알 수 없어 이 필드도 보존한다. 편집·자동 최신본 채택·충돌 승인·정상 저장·tombstone·JSON 가져오기 승격은 막는다. 미래 권의 비배열 `problems`는 intake 검사에 넘기지 않고 별도 버전 게이트로 보류한다. 다른 정상 권의 저장은 계속한다. 계정 전체 영구 삭제는 별도의 명시적 개인정보 삭제 경로다.
- 계정을 유지하는 **모든 문제집 삭제**는 로컬 읽기 전용 권을 먼저 확인하고, 서버 문서 전체의 미지원 버전을 첫 tombstone 전에 조회해 부분 삭제를 막는다. 계정 영구 삭제는 본인 확인 뒤 미래 권도 하드 삭제할 수 있으며 타인 문서는 Rules가 거절한다.
- 클라우드 권 크기 900KiB 판단은 `setSchemaVersion`과 예상 다음 `revision`까지 포함한 실제 직렬화 문서 크기를 사용한다. 저장 초과·지원하지 않는 서버 버전은 원본·초안을 유지하고 해당 권만 보류한다.

`service-config.js`는 이미 `setRevisionSchema:1`을 제공한다. 실제 전환에서 **엄격 Rules를 먼저 적용하면 구형 운영 편집기의 쓰기가 새 Pages가 도착할 때까지 거절**되고, Pages를 먼저 적용하면 기존 Rules의 `hasOnly`가 새 클라이언트의 `setSchemaVersion` 표식을 거절한다. 2026-10-21 사용자는 쓰기 중단 창을 수용하고 **엄격 Rules → PR 병합/Pages → 로그인 왕복** 순서를 확정했다. 엄격 Firestore Rules는 `pedagogy-huryul`에 컴파일·릴리스 완료했다(HANDOFF-194, SHA-256 `9b16c418…`). 다음 병합/Pages는 Claude 담당이며 아직 실행하지 않았다. 구형 탭·신규 쓰기·복제·tombstone 거절 및 새 편집기 승격의 운영 확인은 남는다. Worker는 배포하지 않았다. 그러므로 REV-108 전체 해결이나 안전한 운영 클라우드 왕복을 선언하지 않는다. 공유 문항/D1 연동은 범위 밖이다.
