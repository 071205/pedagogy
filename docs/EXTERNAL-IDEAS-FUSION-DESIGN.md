## ① 지문을 문항 밖 독립 객체로 — REV-108 의 두 번째 안

### 지금과 원본

- **우리 지금**: 지문은 묶음 첫 문항의 `passage` 블록이고 소속은 위치(`groupSpan`)로 정한다. 이것이 REV-108 결함이다.
- **REV-108 선행 판정(A안 · Astra 2026-10-04)**: 구성원마다 `groupOf = 대표 문항 ID`. 지문은 **대표 문항 안**에 남는다.
  그래서 "대표만 삭제 → 남은 구성원이 있으면 기본 차단(대표 이전·지문 동반·전체 삭제 중 명시)" 이라는 규칙이 필요했다.
- **rhwp(원본)**: 지문을 최상위 `passages[]` 에 **한 번만** 두고 문항은 `passage_ref` 로 가리킨다. 빌더는 처음 가리키는 자리에
  지문을 찍는다. 안내문(`[1~3] 다음 글을 읽고…`)은 지문의 첫 블록이지 문항 발문이 아니다(`07_passages_questions.md:15`).
  **약점**: 오타 난 참조를 스키마가 못 잡는다고 스스로 적었다(`:66`).

### B안 — 융합

문제집에 `passages:[{id, lead, boxed, parts}]` 를 두고, 문항은 `passageId` 로 가리킨다. 지문 블록 데이터 모양(`lead·boxed·parts`)은 그대로 옮긴다.
A안의 불변조건은 **전부 유지**한다 — 권 안 유일 ID · 존재하는 지문만 참조 · 구성원은 한 묶음에만 · 연속 구간 · 상한 10 ·
깨진 참조는 자동 복구 없이 진단 · 옛 `groupSpan` 은 '검토 필요' 로 이관 · 구형 클라이언트 쓰기는 스키마 표식 + Rules 게이트로 차단.

| 경우 | A안(대표 문항 안) | B안(독립 객체) |
|---|---|---|
| 대표 문항만 삭제 | 기본 차단 + 세 선택지 | **그냥 삭제된다** — 지문은 남은 구성원이 계속 가리킨다 |
| 구성원 전부 삭제 | 지문도 함께 사라짐 | 아무도 안 가리키는 지문 → 진단 후 정리(자동 삭제 안 함, ⌘Z 로 복원 가능) |
| 묶음 전체 이동 | 대표 포함 이동 | 구성원 이동만. 지문은 첫 구성원 앞에 그려진다 |
| 안내만 공유하는 묶음(영어 31~34) | `groupLead` 를 대표가 가짐 | `passages` 항목에 `lead` 만, `parts` 빈 배열 |
| AI 투입 계약 | 첫 문항 statement 에 지문을 넣고 `group` 문자열 | **원본 rhwp 와 같은 모양** — `passages[]` + `passageRef` 로 바로 받는다 |
| 문항 복제·다른 권으로 넣기 | 지문 블록이 따라감 | 지문을 함께 복사하고 새 ID 로 재매핑(D1 연동은 범위 밖) |
| 저장 크기 | 지문 본문은 같다 | 지문 본문은 같지만 객체 ID·참조·검토 상태·보존 중인 고아 지문만큼 달라진다 — **실제 직렬화 크기로 판정** |
| 바꿀 곳 | `normProblem`·렌더·인쇄·HWPX | 위 + `normSet`·`firestore.rules`(정상 저장·신규 사본·충돌 사본·tombstone 각각의 게이트)·`check:static` 대조 3곳·이관기 |

**판정: B안으로 바꾼다**(Codex Astra high 2026-10-13 동의 — 단 아래 비용 정정). '대표만 삭제 차단' 은 구조적으로 사라진다.
⚠️ **비용은 "필드 하나" 가 아니다**(내 처음 평가가 틀렸다). 대표의 역할 이전이 없어지는 대신 **지문 객체의 수명·참조 관리**가 새로 생긴다.
A안의 '대표가 맨 앞' 은 '**검증된 연속 구성원의 첫 문항 앞에 지문을 그린다**' 로 바뀐다.

B안에서 새로 정하는 계약(구현 전 확정):
- **지문 삭제**: 참조 중인 지문 객체 자체를 지우려면 차단하거나 명시적 분리(구성원을 지문 없는 문항으로)를 고르게 한다.
- **두 가지 '고아'를 구별**: 아무도 안 가리키는 지문(보관·정리 정책, Undo 범위 명시) ≠ 없는 지문을 가리키는 문항(진단·**인쇄 차단**).
  `lead` 도 유효한 `parts` 도 없는 지문은 묶음으로 인정하지 않는다.
- **복제·다른 권으로**: 한 작업 안에서 같은 원본 지문은 **한 번만** 복사하고 모든 구성원을 같은 새 ID 로 잇는다. 목적지에 우연히 같은 ID 가
  있어도 합치지 않는다. 부분 분리 = 지문을 동반한 새 묶음, 무관한 복제 = 자동 가입 없음(A안 정책 유지).
- **스냅샷**: `problems[]`·`passages[]`·참조·검토 상태를 **한 스냅샷**으로 — Undo·클라우드 수신·B4 충돌 사본 모두. 서로 다른 revision 의 두 배열을 섞지 않는다.
  삭제 뒤 늦은 저장이 지문을 되살리지 않는다.
- **이관**: 옛 지문 블록 추출 → 권 전체 ID 대응표 → 참조 변환·검증. 중복 ID 를 임의로 잇지 않고, 비활성 `groupSpan` 을 되살리지 않으며,
  이미 손상된 옛 묶음은 B안으로 옮겨도 소속을 복구할 수 없으므로 **미검토·인쇄 차단**을 유지한다.
- **AI 응답을 `passages[]+passageRef` 로 바꾸는 것은 별개의 계약 변경**이다 — 저장 모델을 B안으로 바꾼다고 동시에 바꿀 필요는 없다.

### 원본의 약점을 메우는 검사(깨보기 포함)

rhwp 가 놓친 '오타 난 참조' 를 우리는 코드로 잡는다. REV-108 완료 증거 표에 아래를 더한다.
- `passageId` 가 없는 ID 를 가리킴 → 진단, 범위 라벨 없음, **인쇄 차단** (깨보기: 검증 함수를 항상 참으로 → 빨간불이어야 함)
- 한 지문을 가리키는 구성원이 비연속 → 같은 처리
- AI 응답의 `passageRef` 오타 → 그 쪽을 '확인 필요' 로(조용히 지문 없는 문항으로 만들지 않음)

## ② 처리 명세 ↔ 코드 ↔ 약관 — 3방향 검사

### 지금과 원본

- **우리 지금**: `check:static` 이 `legal.html` 에 법정 항목 **제목 14개가 있는지**만 본다(`scripts/check-static.mjs:369`).
  [L2 준비 계약](LEGAL-TAX-READINESS.md) §3 이 '데이터 흐름 표' 를 요구하지만 사람이 쓰는 표다.
- **korean-privacy-terms**: Step 1~9 인터뷰(서비스 → 수집 항목 → 방법 → 목적 → 제3자 → 위탁 → 책임자 → 특수 상황 → 시행)로
  처리방침 재료를 빠짐없이 모은다. 법정 11항목 체크리스트(`references/law-checklist-2026.md`).
  ⚠️ 청약철회 오분류가 있으니 **질문 순서만** 쓴다.
- **harness cross-document-linker**: 문서 간 필수 일치 규칙 CR-01~07(서비스명·운영자·수집 항목·환불 조건·쿠키·시행일·관할).

### 융합 — 기계가 읽는 처리 명세 한 장

`docs/legal/processing.json` 하나를 **정답표**로 두고 세 방향으로 대조한다. 필드는 privacy-kr 인터뷰 순서를 따른다.

```
{ operator:{name, contact, cpo}, effectiveDate, version,
  items:[{id, data, purpose, method, retention, legalBasis}],
  processors:[{name, role:"위탁|국외이전|제3자", hosts:[...], country, items:[...]}] }
```

| 방향 | 무엇을 견주나 | 빨간불 예 |
|---|---|---|
| **코드 → 명세** | CSP `connect-src`·`img-src` 의 외부 호스트, Worker 의 외부 `fetch` 대상, `firestore.rules` 의 `hasOnly` 필드 목록 | 코드에 새 외부 호스트가 생겼는데 `processors[].hosts` 에 없다 |
| **명세 → 약관** | `processors` 이름·국가, `items` 의 데이터·보존 기간, 운영자·책임자 연락처가 `legal.html` 해당 조에 있는가 | 명세의 위탁사가 처리방침 위탁 조항에 없다 |
| **문서 ↔ 문서**(CR 규칙) | 약관·처리방침·환불 고지의 서비스명·운영자·시행일·버전·환불 조건이 서로 같은가 | 약관 시행일과 처리방침 시행일이 다르다 |

- **약관 문장을 명세에서 자동 생성하지 않는다** — 문장은 L2 교차 작성으로 쓰고, 이 검사는 **사실이 빠지거나 어긋난 것만** 잡는다.
- 지금 `legal.html` 의 '⚠️ 미입력' 칸(운영자·책임자)은 명세에 `null` 로 두고 **P1 활성화 검사에서만** 빨간불로 올린다(평소엔 경고).
- 깨보기 3종: CSP 에 가짜 호스트 추가 · 처리방침에서 위탁사 한 줄 삭제 · 한 문서의 시행일만 변경 — 각각 빨간불이어야 한다.
- harness `unfair-terms-detector` 의 불공정 약관 유형(약관규제법 제6~14조)은 **L2 교차 검토 체크리스트**로 쓴다(자동 검사 아님).
- 자리: 명세·대조표와 검사 스크립트(`check:static` 안) 모두 **L2**. 문서·검사라 Codex 선행 판정은 필요 없고, 검사 코드는 Claude → Codex 검토.

## ③ 내용 보존 지문 대조 — "둘이 함께 틀림" 막기

### 지금과 원본

- **우리 지금**: `test:hwpx-exam` 이 같은 payload 를 파이썬·JS 에 넣어 **두 결과를 서로** 견준다. 둘이 함께 선지 하나를 빠뜨리면 통과한다 —
  CLAUDE.md 가 경고한 '검사에서 목록과 인쇄를 서로 견주지 말 것'(같은 함수를 쓰면 함께 틀린다)과 같은 모양이다.
  `strictValidate`(`hwpx-engine.js:990`)는 구조·참조만 본다.
- **hwpx-skill**: 순서 있는 본문·표 셀·붙임 문구·**실제 삽입 이미지 해시**를 원고와 산출물 양쪽에서 대조한다. 기대 쪽 수(`--expected-pages`)가 다르면 실패.

### 융합 — 원본 payload 기준 '내용 지문'

입력 payload 에서 한 번, 결과 HWPX(section XML)에서 한 번, 같은 모양의 지문을 뽑아 **고정 기대값 대신 입력 자체**와 견준다.

| 항목 | 입력에서 | 결과에서 |
|---|---|---|
| 문항 순서·번호 | `problems[].num` | 번호 문단의 숫자 |
| 본문 글자(정규화: 공백·탭 접기) | 발문·조건·보기 텍스트 | `<hp:t>` 를 문단 순서로 |
| 선지 순서·개수 | `choices` 5개(단답형은 0) | ①~⑤ 문단 |
| 수식 자리 | 문항·블록별 `$…$` 개수 | 같은 문항·블록 문단 안의 `<hp:script>` 개수(내용은 변환 결과라 비교 안 함). 전체 개수만으로는 순서를 못 본다 — **문항·블록 위치로 대응**시킨다 |
| 그림 | 데이터 URL 의 SHA-256 | `BinData/` 바이트의 SHA-256 |
| 명시적 쪽나눔 | 편집기 `buildPages()` 를 같은 상태로 돌린 쪽 시작 문항(브라우저 검사에서만 — payload 에는 쪽 정보가 없고 `breakAfter`·`heightMm` 만 실린다) | `pageBreak="1"` 이 붙은 문항. ⚠️ 이것은 **명시적 나눔**만 본다 — 한글의 자동 넘침까지 포함한 실제 쪽 수는 PDF 로만 안다 |

- 파이썬·JS **각각**을 입력과 견준다(서로가 아니라). 기존 파이썬↔JS 대조는 그대로 둔다 — 갈라짐과 함께 틀림을 **둘 다** 잡는다.
- 깨보기 4종: 방출기에서 선지 하나 건너뛰기 · 두 문항 순서 바꾸기 · 그림 하나를 자리표시로 · 쪽나눔 하나 누락 — 각각 빨간불.
- 이것도 '열린다·제대로 찍힌다' 의 증명은 아니다. 실물 판정은 여전히 `test:hwpx-opens` + PDF 눈 확인이다.
- 자리: **옆길 Q1**(`test:hwpx-exam`·`test:hwpx-browser` 안, CI 의 `hwpx` 작업). R6 은 '코드를 바꾸지 않는 칸' 이라 넣지 않았다.

kordoc 은 조판 캐시가 없는 파일(우리가 만든 파일)을 **자체 TS 조판(reflow)** 으로 그린다(kordoc SKILL.md '미리보기').

**회고 실험(1회 · 로컬)** — CLAUDE.md 에 기록된 '검사는 초록인데 결과물이 틀렸던' 결함을 최소 표본으로 다시 만든다.

| 표본 | 원래 어떻게 발견했나 |
|---|---|
| 조합 기호 `_6\mathrm{C}_2` 앞머리 첨자 → 발문 통째로 빈칸 | 한글 PDF 눈 확인 |
| 머리말을 `secPr` 에 넣음 → 열리는데 안 찍힘 | 한글 PDF |
| 탭으로 이은 선지의 `$\dfrac32$` 가 글자로 찍힘 | 화면 확인 |
| 머리말 속 run 까지 제목 모양(19pt) | PDF |
| 구조 표시까지 채움글자로 덮은 틀 | 문항 번호 크기 변화 |

각 표본의 **고친 판 / 고장 판** 을 kordoc `validate`·`render` 에 넣어 차이가 보이는지 센다.
- 하나 이상을 잡으면: 고정 버전 devDependency(lockfile·`npx -y` 금지)로 `test:hwpx-kordoc`(**CI 제외**, `test:hwpx-opens` 와 같은 자리)를 만든다.
  통과를 한글 호환 판정으로 쓰지 않는다 — 차이가 나면 한글 PDF 로 판정한다.
- 하나도 못 잡으면: **들이지 않는다**고 기록한다.
- 의존성 검토(라이선스 MIT·설치 스크립트·크기·하위 의존성)는 R6 에서.

## ⑤ 그림 영역 잘라 붙이기 — U2 뒤 별도 묶음

### 지금 — 생각보다 손실이 크다

`pedagogy-intake-contract.js` 의 `validateResponse()` 는 문항 하나라도 `unsupported:true` 면 **그 쪽 전체를 던진다**
(`problems.map` 안의 `throw Error('본문/그림/쪽 경계 확인 필요')`). 프롬프트는 "그림/표를 텍스트로 보존할 수 없으면 unsupported" 라고 시킨다.
그래서 **그림 문항이 하나만 섞인 쪽도 나머지 문항까지 전부 실패**한다. 수학 시험지는 거의 모든 쪽에 그래프·도형이 있다.
**결함은 아니다**(Codex 판정 · 근거 확인): R2 는 '공급자 호출당 한 쪽' 과 '여러 쪽 작업의 **쪽별** 부분 성공' 만 약속하고
(`PROBLEM-INTAKE-DESIGN.md:859-861`), 쪽 **안의 문항별** 부분 성공은 약속하지 않는다. 지금 동작은 닫힌 실패로 계약과 양립한다.
그러니 문항별 구제는 결함 수정이 아니라 **새 계약**으로 다룬다(아래).

### 원본의 장점

- **의미 배치**: 그림 자리를 픽셀이 아니라 `between`(발문→그림→선지, 기본) · `above` · `below` · `inline` 으로 말한다. 애매하면 `between`.
  `inline` 은 깨지기 쉬우니 중요한 자료는 `between` 으로 내린다(`09_media_placement.md`).
- **숫자를 내게 한다**: "페이지 중상단" 같은 말로는 자르지 않는다(`11_crop_bbox.md`).
- **약점**: 범위 검사(`x+w ≤ 폭`)를 에이전트에게 맡기고, 사람 확인 단계가 없다.

### 융합 설계

**계약(응답 v2)** — 새 블록 `{type:"figure", box:[ymin,xmin,ymax,xmax]}` 를 더한다.
- **좌표는 0~1000 정규화 정수**다. AI 에 보내는 쪽 이미지는 `maxDimension` 한도로 렌더·축소된 JPEG 다(`pedagogy-intake.js:461-467`).
  그 픽셀 좌표로 자르면 그림이 거칠다. 정규화 좌표는 해상도와 무관하므로 **PDF 원본은 더 높은 해상도로 다시 렌더해서** 자를 수 있다
  (벡터 그래프가 선명하게 나온다). 사진 원본은 원본 해상도에서 자른다.
  Gemini 는 물체 검출 상자를 이 형식으로 내도록 학습돼 있다 `[통설 — C2 표본으로 정확도 확인]`.
- **배치는 블록 순서가 정한다** — 우리 문항은 이미 블록 배열이라 rhwp 의 enum 이 필요 없다. 기본은 발문 뒤·선지 앞(= `between`).
  문장 안 작은 그림(`inline`)은 받지 않는다 — 원본도 약하다고 한 경로다. 그런 문항은 계속 '확인 필요'.
- `unsupported` 는 **다른 쪽으로 이어지는 지문·판독 불가** 에만 남긴다.
- **문항별 격리(새 계약)** — 응답 전체가 스키마를 통과했고 **명시적으로 `unsupported` 라고 표시된 문항만** 격리한다.
  잘린 JSON·전체 스키마 오류·`finishReason` 이상은 지금처럼 쪽 전체 실패다(구제하지 않는다).
  격리한 문항은 조용히 지우지 않고 **자리와 이유**를 남긴다. 공유 지문이 실패하면 그 지문의 구성원도 함께 보류한다.
  다시 시도할 때 이미 채택한 문항이 중복되지 않게 한다.

**검증(코드)** — rhwp 가 에이전트에게 맡긴 것을 전부 코드로.
- 네 값이 0~1000 정수 · `ymin<ymax`·`xmin<xmax` · 최소 넓이(예: 쪽의 0.5%) · 문항당·쪽당 그림 수 상한(D3 한도 키에 `figures` 추가).
- 결과는 **요청 당시의 출처**에 묶는다: owner · `sourceId` · 쪽 번호 · AI 에 보낸 이미지의 해시(B5 `sourceHash`) · 삭제 세대 ·
  **좌표 변환 정보**(PDF 쪽 영역·회전·사진 방향·축소 비율). 지금 렌더 함수는 JPEG 와 크기만 돌려주므로(`pedagogy-intake.js:460-474`)
  변환 정보를 함께 기록하도록 바꿔야 한다.
- 출처 검사는 **자르기 시작 때와 채택 직전 두 번** 한다 — 그 사이 원문 삭제·로그아웃·문항 제외가 일어날 수 있다.
- 최소 넓이를 고정 숫자로 정하지 않는다(작은 유효 그림을 거절한다). 대신 사람 확인에서 걸러진다.

**자르기(브라우저 · 서버 없음)** — B6 가 이 기기에 보관한 원본(`readSource`)에서 자른다.
원본이 지워졌거나 동일성이 확인되지 않으면 **다른 것으로 대체하지 않고 보류**한다. 고해상도 재렌더에는 픽셀 수·메모리·동시 작업·결과 총용량 한도를 둔다.
- 정규화 좌표를 **자를 이미지의 해상도**(PDF 는 다시 렌더한 쪽, 사진은 원본)로 환산하고 여백(예: 1%)을 더한 뒤 쪽 경계로 자른다.
  AI 가 본 이미지와 같은 쪽·같은 방향인지(회전·EXIF 보정 후) 확인한 뒤에만 자른다.
- 잘린 그림은 기존 그림 경로를 탄다 — 로그인이면 Storage 업로드(5MB·`storage.rules`), 아니면 압축 데이터 URL. 900KiB 문서 한도·
  `blockImageSlots()` 경유를 지킨다(CLAUDE.md 'REV-019·020' 교훈).
- 원문을 지워도 이미 채택한 그림은 남는다(U0 '결과 그림은 원문과 독립 보존'). 원문 정리가 채택 그림을 지우지 않게 한다.
- 업로드는 성공했는데 문서 저장이 실패한 경우, 취소·Undo 뒤 남은 Storage 파일의 정리 경로를 정한다(`releaseImage` 의 '다른 문제집이 쓰면 안 지움' 규칙 재사용).

**사람 확인(U2 검토 화면)** — 원본 쪽 위에 상자를 겹쳐 보여 주고, 끌어서 고치거나 '그림 없음' 으로 바꿀 수 있다.
- 확인 전 그림·자산 누락이 있으면 **그 출력 작업 자체를 막는다** — 그림만 빼고 문항을 찍는 것이 아니다(조용히 틀린 출력 금지,
  REV-108 의 인쇄 차단과 같은 원칙). '그림 없음' 선택도 내용을 지우는 결정이라 명시 확인을 받는다.
- 확인한 뒤 좌표·원본·소속이 바뀌면 확인 상태를 **무효화**한다.
- 좌표 검사로는 다른 문항의 그림, 잘린 축·범례, **모델이 그림 자체를 빠뜨린 경우**를 못 잡는다 — 그래서 사람 확인이 필수다.
- 다른 문항·이름·학번이 상자에 섞이면 사용자가 줄이거나 보류한다. AI 전송 전 개인정보 확인과 채택 전 확인은 별개다.
- 자르기가 D10 권리 확인을 대신하지 않는다.

**깨보기** — 좌표 범위 검사 제거 · 출처 해시 대조 제거 · 미검토 그림 인쇄 허용 · 해상도 환산 누락(정규화 좌표를 픽셀로 그대로 씀) — 각각 빨간불.

**자리** — AI 계약·Worker 검증·저장이 함께 바뀌므로 U2 화면 작업에 끼우지 않고 **U2 뒤 별도 묶음(U2-F)**.
**P1 출시 범위에 그림 지원을 넣으면 U2-F → R5**(계약·저장 변경이 종합 검증보다 앞서야 한다). 넣지 않으면 R5 를 늦출 근거는 없고
U2-F 는 P2 전 묶음이 된다 — **해리 결정**(아래). 구현은 Codex Sol high(계약·검증·출처 묶기) → 화면은 Claude, 각각 비구현자 검토.
