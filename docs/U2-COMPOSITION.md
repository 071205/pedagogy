# U2 일괄 구성 구현 계약

2026-10-22 · 사용자 지시로 Codex 구현, 구현하지 않은 Codex 에이전트 독립 검토.
상위 계약은 PRODUCT-UX-U0-CONTRACT/PRODUCT-UX-DESIGN, 순서는 DEV-TOKEN-ROADMAP을 따른다.

## 구현 순서

1. B6 owner별 원문/작업/채택 저장소에 기존 문제집의 읽기 시점 스냅샷과 편집 가능한 구성 초안을 연결한다. 별도 저장소·공유 문항·Rules/Worker 변경은 만들지 않는다. 이 저장 확장은 UI보다 먼저 독립 검토한다.
2. 기존 라이브러리에서 선택 권으로 새 구성 시작, 목적지/문항/본문·원문 상세, 묶음 단위 이동·제외·수정, 프리셋의 새 구성안 미리보기/명시 적용/Undo, 권별 만들기/결과/초안 복귀 UI를 연결한다.
3. B6 자료 추출 작업에도 같은 구성 화면을 사용한다. 운영 한도·transport가 없는 현재 상태에서는 PDF 선택으로 AI 호출을 시작하지 않으며 일괄 추출 활성화는 C1~C3/D3 게이트를 유지한다. 실제 AI 운영 완료로 기록하지 않는다.

## 불변조건

- 기존 권은 읽기 시점 스냅샷만 사용한다. 결과는 새 권/문항 ID인 독립 사본이다. 원본과 기존 검토 상태·본문/수식/이미지/출처를 보존한다. 미지원 버전/보류 권/소속 미확인 묶음은 구성 시작을 보류한다.
- 구성 버전 변경은 저장소 transaction으로 확인한다. 오래된 제안은 적용하지 않는다. 손수 고친 본문은 배치 제안으로 덮어쓰지 않으며 실제 Undo를 제공한다. 원문 표시로 접근 권한을 새로 만들지 않는다.
- 모든 문항은 목적지/명시 제외/미분류 중 한 곳에 있다. 누락/임의 권수 증가를 완료로 표시하지 않는다. 단원 7개/요청 5권의 차이를 적용 전에 확인한다. 배점 없음과 난이도를 구별한다.
- 명시 소속 묶음은 전체를 한 단위로 이동/제외하며 실제 구성원 순서와 지문을 유지한다. 같은 문항을 서로 다른 결과에 넣는 기능은 명시 복제 계약을 별도로 구현하기 전 허용하지 않는다.
- 만들기 시작 뒤 고정된 adoption 매핑을 재사용한다. 연타·부분 저장·재진입으로 권을 중복 생성하거나 삭제된 결과를 복원하지 않는다. 로컬 저장과 cloud pending/ACK/tooBig/error/conflict/check를 나눠 표시한다.
- 단순 재배열은 AI 0회다. 유료 재시도에는 새 범위/차감 확인이 필요하며 성공 쪽 재처리·자동 재시도는 하지 않는다. AI 생성은 미확인, 기존 legacy 검토 상태는 unknown으로 유지한다.
- owner/epoch·삭제 세대·탭 잠금·로컬 실패 경계를 기존 B6 조정 안에서 유지한다. 작업이 있는 기기의 저장 범위만 안내한다.

## 화면 방향

기존 밝은/어두운 디자인 토큰·한글 본문 글꼴·남색 동작색을 유지한다. 목적지 목록, 문항 목록, 선택 문항 상세의 세 영역이 서로의 실제 데이터를 보여주며 좁은 화면에서는 순서대로 쌓인다. 불필요한 상태 카드 대신 문항 수/미분류/제외와 권별 저장 상태를 해당 항목 옆에 둔다. 원문 상세는 기존 B6/U1.5 읽기 경로를 사용한다.

## 수용 검사

기존 권 스냅샷/본문·그림·검토·출처 보존, owner/구형 탭/미지원 버전/불명확 지문 차단, 7단원/5권·배점 없음·미분류, 묶음 이동/제외/Undo, 본문 수정 뒤 오래된 제안, 두 번 클릭/부분 저장/재진입/삭제된 결과, local/ACK/실패 분리, 실제 키보드·375/768/1194 화면 및 정상/방어 제거 RED를 확인한다. 운영 유료 호출은 하지 않는다.

## 저장 엔진 상태 · 2026-10-22

`createComposition/readComposition/saveComposition/undoComposition/listJobs/forkComposition`을 B6 owner transaction에 추가했다. 구성 시작은 선택 권의 불변 스냅샷을 만들고, 모든 저장은 draftVersion을 확인한다. Undo/Redo는 본문·분류·검토 상태와 구성의 실제 이전 값을 복구한다(최근 20개, 누적 약 12MiB를 넘으면 오래된 것부터 제거하되 최근 1개 유지). 새 추출 응답을 붙일 때는 기존 Undo로 새 결과를 지우지 않도록 기록을 초기화한다.

만들기 시작 후에는 기존 adoption ID·배치를 고정하며 편집/추가 유료 재시도를 차단한다. provider 시작 직전에도 다시 검사한다. 이미 시작한 응답은 보존하고, 사용자가 선택한 미채택 문항 전체 묶음만 새 작업으로 복사할 수 있다. 이미 채택한 문항이나 묶음 일부만 넘기는 요청은 거절한다. 가져온 sourceId만으로 원문 grant를 만들지 않는다.

독립 Codex의 저장 엔진·화면 검토, 정상/RED와 CI·Pages 배포를 완료했다. 로그인 Chrome에서 기존 권→새 두 권 구성/계정 ACK/새로고침·작업 재진입/원본 불변까지 확인했다. 실제 Safari/iPad·유료 AI 검증은 포함하지 않는다. 검토 범위·해시·검사는 HANDOFF-197을 기준으로 한다.

## 구성 화면

라이브러리 선택의 **여러 권으로 구성** 또는 새 문제집 메뉴의 **여러 권으로 새로 구성**에서 연다. 다른 PEDAGOGY 탭 닫기 확인 후 선택 권 스냅샷/남은 B6 작업을 읽는다. 목적지·문항·본문/원문 상세를 보여주며 좁은 화면에서는 순서대로 쌓인다. 묶음 이동·제외/복귀, 순서·목적지 추가/이름 변경·빈 목적지 삭제, 본문/정답/단원/자유 난이도/배점 수정, 실제 Undo/Redo를 제공한다. 확인된 기존 분류의 모델 출처는 해당 필드를 고치지 않으면 유지한다.

구성 요청은 명시된 로컬 문법(예: 단원별로 5권, 난이도별로, 20문항씩)만 해석하며 해석하지 못한 말은 오류로 돌려준다. 지원하지 않는 자연어를 처리했다고 표시하거나 AI로 조용히 전송하지 않는다. 새 구성안은 목적지별 수·제외/미분류 변화와 문항별 목적지 변경을 보여주고 사용자가 적용해야 저장된다. 요청 권수와 실제 권수가 다르면 별도 확인이 필요하다. 미분류가 남으면 만들지 않는다. 배점은 0 이상 유한 숫자만 허용하고 없음/판독 불가를 난이도나 null점으로 대체하지 않는다.

만들기 결과에서 로컬 저장과 계정 ACK/대기/크기 초과/실패/충돌/확인을 구분한다. 로그인 전에는 이 기기 저장이라고 쓴다. 실패 저장만 같은 고정 adoption으로 재시도하며 삭제한 결과를 다시 만들지 않는다. 한 권 정상 결과의 바로 편집기 선호(D4)를 계정별 이 브라우저에 기억한다. 미채택 문항은 전체 묶음으로 새 구성에 넘긴다.

기존 권은 과목을 스냅샷에 보존하며 같은 과목으로만 구성된 결과는 해당 과목, 서로 다른 과목이 섞인 권은 **제한 없음**이다. 머리말·선 색은 새 문제집의 빈 머리말/기본 남보라를 사용한다. 원본 설정을 덮어쓰거나 원본 권과 동기화하는 기능은 아니다. 문항의 본문/이미지/명시 소속/출처는 보존한다.

계정 전환·강제 닫기·즉시 재오픈에는 화면 세대를 사용한다. 이전 비동기 응답과 finally가 새 화면을 렌더하거나 잠금을 풀지 못한다. 늦게 열린 원문 뷰어는 취소됐으면 즉시 닫는다. 미저장 본문이 있으면 다른 작업과 닫기 전에 저장/되돌리기를 안내한다. PDF·사진 일괄 추출은 운영 transport/비용/한도가 승인되기 전 비활성화한다.

D4 선호는 결과 목록뿐 아니라 설정 → 화면의 구성 후 이동에서도 켜고 끈다. 새 구성안의 변경 목록은 목적지 이름과 권 안 문항 번호를 함께 비교해 동일한 권의 재정렬도 숨기지 않는다.

U2 배포 전 U0 §5-2의 원문 관리 표시도 대조했다. 기존 H184의 목록/용량/삭제 기능은 그대로 사용하고, 활성/비활성/미지원/조회실패를 빈 목록에서도 구분한다. 활성은 영구 보관이나 백업 보장으로 표시하지 않는다(REV-146).
