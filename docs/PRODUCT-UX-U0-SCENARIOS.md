## 1. 시안이 잇는 흐름

```
라이브러리 ─┬─ 직접 만들기 ──────────────────────────→ 문항 편집 ⇄ 지면 배치
            └─ 자료로 만들기 · AI
                 → 자료+요청 → 쪽별 처리 ─┬─ 전부 성공 ─→ 구성안 → 권별 결과 ─→ 문항 편집
                                          └─ 부분 실패 ─→ 성공분만 사용 / 실패 쪽 재시도
                                                            ↘ 재개 · 원문 만료
                                                               문항 편집 → 충돌(B4) → 복구
```

시안 화면 아홉은 위 상자와 1:1이다. 실패 경로가 **막다른 길로 끝나지 않고** 늘
`구성안 → 권별 결과 → 편집`의 정상 경로로 돌아온다 — 그것이 '연결'의 내용이다.

### 화면마다 무엇을 지키는가

| # | 화면 | 지키는 계약 |
|---|---|---|
| 1 | 라이브러리·시작 | 두 경로 동시 노출 · JSON 불러오기와 PDF 투입 분리 · 영구 자료함 안 만듦 |
| 2 | 자료+요청 | 자료와 요청 한 화면 · 파일 선택만으로 과금 없음 · 추출 전 문항 수 미확정 |
| 3 | 처리·부분 실패 | 쪽만 숫자로 셈 · 결과를 드러내는 버튼 이름 · 자동 유료 재시도 없음 |
| 4 | 구성안+원문 | 손수 고친 구성이 기준 · 미분류 명시 처리 · **공통지문 경고**(아래 §3) |
| 5 | 권별 저장 결과 | '5권 완료' 금지 · 로컬/ACK 구분 · 크기 초과는 그 권만 · 실패 권 초안 보존 |
| 6 | 문항 편집 | 기존 `#paneTabs`·`#spanSeg` 재사용 · 미검토/확인함 구분 |
| 7 | 전체 지면+경고 | PDF 없이 잘림 확인 · 맥락별 설정 · 경고에서 위치로 이동 · 기존 출력 경로 공유 |
| 8 | 충돌 복구 | 네 선택지 지속 표시 · 두 revision · 시각은 설명용 · 사본 1회 |
| 9 | 재개·원문 만료 | 같은 채택 ID · 삭제 권 자동 부활 금지 · 성공 잠금 중 자동 재호출 금지 |

## 2. 여섯 사용 과제 — 시나리오와 관찰표

제품 UX §7의 여섯 과제다. **세 화면 크기에서 각각** 수행한다.
`1194×834`(아이패드 가로/노트북) · `768×1024`(태블릿 세로) · `375×812`(휴대폰).

각 과제는 **첫 클릭 · 완료 여부 · 잘못 누른 횟수 · 화면 왕복 · 재출력 횟수 · 미결**을 적는다.
⚠️ 관찰 전에는 **비워 둔다.** 추정으로 채우면 이 표가 거짓말이 된다.

### 과제 ① 시작 발견 — 설명 없이 두 경로를 찾는가

> "PDF 한 묶음이 있습니다. 이걸로 문제집 5권을 만들어 보세요."
> 그리고 "이번엔 AI 없이 빈 문제집을 직접 만들어 보세요."

- 시안 화면: 1
- 보는 것: '+ 새 문제집'을 누르는가, 아니면 '문제집 파일 불러오기'를 먼저 누르는가.
- 실패 신호: JSON 불러오기를 PDF 투입으로 착각한다 / 빈 라이브러리에서 무엇을 할지 모른다.

## 3. 시안이 계약에 **더한** 것 — 공통지문 경고

U0 계약 §3은 "초기안은 공통지문 묶음 단위 이동·채택"만 적는다.
독립 검토에서 **계약에 없는 실패 방향**을 재현했다(`REV-2026-108`).

| 사용자가 하는 일 | 지금 코드가 하는 일 |
|---|---|
| 묶음 가운데 문항을 **제외** | `groupSpan`이 그대로라 **뒤의 무관한 문항이 묶음에 흡수**된다 |
| 지문 보유 문항만 **이동** | 목적지의 다음 문항들이 그 지문 범위로 **잘못 묶인다** |
| 지문 없는 뒤 문항만 **이동** | 지문이 **조용히 사라진다**(경고 없음) |

셋 다 오류가 나지 않고 **인쇄물만 틀린다.** 그래서 시안 화면 4는 묶음을
`grouped` 세로선으로 묶어 보이게 하고, 선택 시 **무엇이 깨지는지 미리 말한다**:

> 02–04는 지문 하나를 함께 씁니다. 따로 옮기면 03·04에는 지문이 따라가지 않고,
> 02만 옮기면 목적지의 다음 두 문항이 이 지문 묶음으로 잘못 묶입니다.
> `[세 문항을 묶음째 옮기기]` `[묶음 풀고 지문 복제하기]`

▶ **계약 보강 제안**: U0 §3의 지문 항목에 **목적지 쪽 흡수**를 추가하고,
채택 시점에 `groupSpan`을 **실제 배치된 연속 구성원 수로 다시 쓴다**고 명시할 것.
D1(독립 사본)에서는 '묶음 풀고 지문 복제'가 자연스러운 선택지가 된다 —
**풀/혼합이면 지문을 공유 참조로 둘지 다시 정해야 한다.**

## 4. D1 · D2 · D4 결정표

⚠️ **D1/D2/D4 사용자 답을 반영했다.** 과거 시안 가정과 앞으로 반영할 화면을 구분한다.
개정 계약은 검토 요청 2건 보완 후 Claude 좁은 재검토 대기이며, HTML 시안의 미반영 동작을 구현 기준으로 쓰지 않는다.

| ID | 질문 | 선택지 | 시안이 쓴 가정 | 고르면 바뀌는 화면 | 막고 있는 것 |
|---|---|---|---|---|---|
| **D1 — 방향 선택** | 문항을 다른 권에 넣을 때 독립/수정 연동을 고르게 | **사용자 결정: 두 방식 선택 가능** | 기존 독립 사본 시안 | 화면 4의 삽입 방식 선택, 화면 6의 영향받는 권/여기서만 고치기 표시와 연동 해제 흐름이 필요하다. 지문 참조·원본 삭제는 U0 §3-1 개정안 검토 대기 | 완료 B3/B4 유지. 연동 저장 확장은 별도 Rules·호환·전환 게이트 |
| **D2 — 답변 완료** | 원문 PDF/이미지 수명 | **② 결과 뒤에도 보관 · 숫자 TTL 없음** | 과거: 종료 시 삭제 | 작업 종료·권 삭제와 원문 삭제 분리(Undo/백업 복구 보존). 명시 연결 해제/원문 관리에서 삭제 범위를 선택. 화면 9는 삭제/유실 이유·다시 연결, 설정은 용량·연결 목록·명시 삭제. 'n일 남음' 없음 | U0 §5 검토 → B6 공통 보관 → B7 복구 차단·U1.5 대조 |
| **D4 — 답변 완료** | 생성 뒤 기본 화면 | **결과 목록 먼저 + 다음부터 편집기 기억** | 과거: 한 권 편집 직행 | 화면 5 아래 owner별·이 브라우저 기억, 설정 해제. 여러 권/실패는 목록 유지, 정상 한 권만 기억 적용 | U0 §4-1 검토 → U1/U2 |

### D4 과거 비교안 — 사용자 답변 전 검토 자료

| | ⓐ 편집 우선 (시안) | ⓑ 지면 우선 | ⓒ 항상 결과 목록 |
|---|---|---|---|
| 한 권일 때 | 편집기로 직행 | 지면 보기로 직행 | 목록 한 번 거침 |
| 여러 권일 때 | 결과 목록 → 권마다 `편집하기` | 결과 목록 → 권마다 `지면 보기` | 같음 |
| 잘 맞는 상황 | **막 뽑은 문항은 미검토다** — 먼저 내용을 본다 | 인쇄가 목적이고 내용은 이미 믿을 때 | 저장 결과를 늘 확인시키고 싶을 때 |
| 위험 | 지면 잘림을 늦게 안다 | **미검토 문항을 안 보고 인쇄로 간다** | 한 권일 때 클릭이 는다 |
| 과제 영향 | ③·④가 쉬워짐 | ③이 쉬워지고 ⑤가 어려워짐 | ⑤가 쉬워지고 ①이 어려워짐 |

▶ 현재 선택은 **결과 목록 먼저 + 정상 한 권 편집 직행 기억**이다. 과거 권장을 대체한다.
목록을 건너뛰어도 미검토 상태·원문 대조·저장 상태를 숨기지 않는다. 세부 예외는 U0 §4-1을 따른다.
