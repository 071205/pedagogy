5개 파일을 읽었습니다. 아래는 읽기 전용 검토 결과입니다.

## 합의

- **F01·F02·F04의 내부 경로 이름이 실물과 맞습니다.** `charPr`→언어별 `fontRef`, `linesegarray`, 바탕쪽/머리말 필드는 이 저장소가 이미 실물로 만진 요소이고(`docs/HWPX-ELEMENT-SPECS.md:202-208`), 추측 네이밍이 아닙니다.
- **단정 회피가 전반적으로 지켜졌습니다.** 576ms를 "한 번의 관찰, 지연 상한 아님"으로 두 곳(계획 12행, json `limitations`)에 적고, 폰트 차이를 "같은 코드 경계 / 영향 크기 미확인"으로 분리했고, `document.fonts.ready`·`FontFaceSet.check`를 글리프 증명으로 쓰지 않겠다고 못 박았습니다(35행). 실시간 모드를 DOM 텍스트로 판정하지 않겠다는 구분(12·33행)도 코드와 맞습니다(`mock-exam-editor.html:1048`은 LIVE면 서버 렌더로 빠집니다).
- **정적/실행/실물을 다른 근거로 센다는 규칙**과 "실행 추적 불가 시 정적 분석을 실행 증거로 꾸미지 않는다"(27행), "REA가 밝힌 함수도 실물 없이 validator 강제 규칙으로 승격하지 않는다"(29행)는 hardened runtime 미시험 상태에 맞는 안전한 설계입니다.
- 범위도 로드맵 전2(`DEV-TOKEN-ROADMAP.md:25`, 66행의 "다음")와 어긋나지 않습니다.

## 수정해야 할 구체 항목

1. **F01에 HWPX 선언 대체 경로가 빠졌습니다.** 런타임 face fallback만 추적하면 우리가 실제로 쥔 레버(틀의 `hh:fontface`/`substFont` 선언, 어떤 `charPr` id를 참조하는지)를 놓칩니다. 우리는 틀을 열어 쓰므로 조사 대상에 선언 경로를 같이 넣어야 출력에 연결됩니다.
2. **F02의 "제품에 연결할 결과"가 화면 결함처럼 쓰여 있습니다.** 실제로는 같은 측정이 출력 payload로 들어갑니다 — `measureCh`→`layoutOf`(702-728)가 `layoutResolved`로, `measureProblemHeights`가 `heightMm`로 `hwpxPayload()`(2199-2212)에 실립니다. 문서 12행과 F02 칸에 "숨은 측정이 HWPX payload에 직접 들어간다"를 명시해야 영향 범위가 축소 해석되지 않습니다.
3. **폰트 미보유 환경 정책이 완료 기준에 없습니다.** `injectServerWebfonts()`는 `LIVE.webfonts`와 `LIVE.base/font/...`에만 의존하므로(2020-2037) 로컬 서버가 없는 공개 배포에서는 `@font-face`가 아예 주입되지 않습니다. 상용 폰트 웹 재배포를 제외한(35행) 이상, 공개 UI에서 받은 HWPX의 `layoutResolved`/`heightMm`은 대체 글꼴로 측정된 값입니다. 이 상태의 허용 정책(서버 경로 유도·대체 표시·측정값 생략 중 무엇인지)을 전2 완료 기준으로 적어야 합니다.
4. **출력 시점 준비 게이트 부재를 1단계 재현 대상에 넣어 주세요.** `document.fonts.ready` 재렌더는 미리보기에만 걸려 있고(2040), `toHwpx()`는 `resolveFigureBytes()` 직후 바로 `hwpxPayload()`를 호출해(2269-2270) 폰트 준비·이미지 decode를 기다리지 않습니다. REV-2026-130의 출력 쪽 사례이므로 화면 측정 결함과 따로 세워야 합니다.
5. **F04에 이미 확정된 실물 사례를 명시**하세요: TOTAL_PAGE `num`이 조판 전 캐시라는 점과 재계산 시점(열기/인쇄/저장), 낡은 `linesegarray` 제거(ELEMENT-SPECS 202·208). 지금 F04는 일반 서술이라 관찰 대상이 흐립니다.
6. **그림이 F01~F04 어디에도 없습니다.** 그런데 48행은 "새 그림 표본의 실제 한글 출력 미검증"을 남겨 둡니다. F05(BinData 해석·크기/DPI·배치)를 추가하거나 "그림은 REA 분석 없이 실물 대조로만 판정"을 명시해 매핑 공백을 없애야 합니다.
7. **관찰 json 필드 보강.** 현재 live 블록에는 pvMode·측정 시작/종료 지점·폴링 간격·`serverWebfonts` 주입 여부·실제 사용 face·편집 내용/대상 문항이 없습니다. 특히 ① 해시 변경은 "갱신"의 증거이지 "최신 내용"의 증거가 아니므로 스크린샷 시각 대조를 근거 필드로 적어야 하고, ② 기록된 모드가 `이 문항`인데 코드가 명시한 무거운 경로는 전체보기(78ms 재조립, 1122-1127행 주석)이므로 미측정 모드를 한계에 적어야 합니다.
8. **연속 편집·화면↔출력의 완료 기준이 판정 가능하지 않습니다.** 3·4단계는 설계 방향("세대를 측정 경계에 묶는다", "대조한다")이고 통과 조건이 없습니다. 예: `연속 N회 입력 종료 후 마지막 revision과 화면 이미지/HTML이 일치, stale 게시 0건(전체보기+LIVE 조합과 Chrome·Safari 각각)`, `문항 순서·본문 문자열·선지 배치(1/2/v)·쪽 분배가 화면·HWPX XML·한글 전 쪽 PDF에서 동일, 단폭 초과 0건` 수준으로 적어야 합니다. 576ms에서 상한을 만들지 않은 것은 맞지만, 상한 없이도 "최신성 일치"는 판정 가능합니다.
9. **18행에 재서명 금지를 명시**하세요. hardened runtime 때문에 `get-task-allow`를 붙이려 한글을 재서명하면 서명이 깨지고 피시험체가 바뀝니다. 불가 시 정적 분석으로 남긴다는 규칙(27행)과 짝을 맞춰 "앱 수정/재서명은 범위 밖"을 적어야 합니다.
10. **표기 분리:** "build6544"(한글 빌드)와 "REA 6.4.0"이 한 문단에 섞여 숫자 혼동을 부릅니다. 또 6.8.0 비교는 "F01~F04에 필요하지 않으면 6.4.0 고정"을 기본값으로 적으면 범위가 분명해집니다.

## 근거

- 숨은 측정 불일치는 수치로 재확인됩니다. `#measure`는 `Hamchorom,serif / 11.04pt / 자간 없음 / nowrap`(602-603)이고 11.04pt=14.72px로 json `hiddenMeasureSize`와 정확히 일치합니다. 실제 선지는 `ExamBody…` 스택·14.5467px(≈10.91pt)·자간 −0.4364px입니다. 즉 측정이 크기에서 약 1.7% 과대이고 자간이 빠져 10자 기준 약 4.4px(≈1.16mm)이 더 붙는데, `fits1`/`fits2`의 여유는 1.0mm입니다(707-708). 방향성은 **과대추정 → 1단 배치의 과소 선택**이고, 그 결과가 `layoutResolved`로 HWPX에 실립니다(2210).
- 디바운스 구조: `edChanged`는 전체보기+비LIVE만 220ms로 미루고 그 외는 즉시 렌더(1142-1149)이므로, 연속 편집 최신성은 LIVE 요청/캐시 쪽 세대 관리에 달려 있습니다 — 그래서 8번의 판정 기준이 필요합니다.
- F04 근거는 ELEMENT-SPECS 200-208(TOTAL_PAGE `num` 캐시, masterpage0~3, CENTER 사본·낡은 linesegarray 제거)과 로드맵 66행의 REV158/159 확정 이력입니다.
- 범위 정합 근거는 `DEV-TOKEN-ROADMAP.md:25`(전2 완료 기준)과 66행("다음은 … 선지 측정·폰트 준비 결함 재확인과 REA 심화 분석·실시간 미리보기 대조").

## 미확인

- 연구 브랜치 `10a0914`의 REV-2026-129/130 본문, 구역/수식 함수·값 흐름 분석, Evidence ID: 이번 검토에서 열지 못했습니다. 따라서 **F03의 "equation reader→script 준비→측정 기록 후보"와 F01~F04가 가리키는 기존 Evidence의 존재·정확성은 미확인**입니다. 이름이 맞는지도 확인하지 못했습니다.
- REA 6.8.0의 변경 내용과 기존 build6544 스냅샷/profile 호환성: 미확인.
- 실제 한글의 디버그 허용(get-task-allow/hardened runtime): 사용자 제공대로 미시험. `observe_native_calls`가 새 프로세스를 띄운다는 제약상, 이미 열려 있는 한글 세션 기반의 기존 실물 흐름과 같은 프로세스를 관찰할 수 없다는 점도 조사 시작 시 확인이 필요합니다.
- `mock-live-updated.png`/`mock-html-mode.png`의 시각 내용과 `requestRender`/`LIVE.cache` 구현(세대·취소 처리 유무)은 지정 5파일 범위 밖이라 읽지 않았습니다. **576ms 갱신이 "최신 내용" 반영인지, 현재 stale 방어가 있는지는 미확인**입니다.
- 4번에서 지적한 decode 미대기가 실제로 `heightMm`을 틀리게 하는지, 3번의 공개 환경 측정 차이가 실제 출력 오류로 이어지는지: 실행하지 않았으므로 경로 지적까지만이고 영향 크기는 미확인입니다.
- Chrome/Safari·실기기·새 그림 표본의 한글 출력 품질: 미확인(계획 48행과 동일).
