## 먼저 `REV-2026-029` — 내 검사가 5MB 를 통과시키고 있었다

5단계에서 만든 글꼴 검사가 URL 로 뭉뚱그려 세고 "3건 이하면 통과" 였다. 정상값 1건은
**CSS** 이고 실제 글꼴은 0건이므로, **2.5MB 짜리 WOFF 두 벌(≈5MB)이 부팅 중 내려와도
초록불**이었다 — 5단계가 없앤 낭비의 대부분이 되돌아와도 몰랐다.

→ 브라우저가 알려 주는 `resourceType()==="font"` 로 **실제 글꼴만** 세고 인쇄 의도 전
**0건**을 요구한다. 인쇄 뒤에는 **KoPub 세 굵기를 이름으로** 확인한다(건수만 보면 어느
벌이 빠졌는지 모른다).
⚠️ 처음 고쳤을 때 **화면 글꼴 Pretendard(0.25MB)** 가 걸려 빨간불이 났다 — 그건 부팅 때
받는 것이 맞다. `resourceType` 위에 인쇄용(KoPub·KaTeX)만 고른다.
코덱스 요구대로 한 벌·두 벌을 각각 심어 빨간불을 확인했다(2.52MB / 5.14MB).

## 6단계 — 설계 §2 의 "실측 전 미정" 을 쟀다

배포본(https)에서 `http://127.0.0.1` 을 부르는 그 상황을, **로컬에 자체서명 https 서버를
띄워** 세 엔진에서 재현했다.

| 엔진 | https 페이지 → http loopback |
|---|---|
| chromium | **된다** (GET 200 · POST 서버 도달) |
| firefox | **된다** |
| **webkit** | **막힌다** (`Not allowed to request resource`) |

⚠️ 내 설계 초안은 "크롬만 되고 사파리·**파이어폭스**는 막는다" 였다 — **파이어폭스가
틀렸다.** 코덱스의 정정(표준상 loopback 은 신뢰 URL이고 문제는 WebKit 구현)이 맞았다.

## 그리고 더 나쁜 것을 찾았다 — **구별할 수가 없다**

WebKit 에서 살아 있는 서버와 죽은 포트를 나란히 불러 봤다:

```
webkit    살아 있는 서버(8787) → TypeError: Load failed · 0ms
          죽은 포트(8799)      → TypeError: Load failed · 0ms
chromium  살아 있는 서버       → 200 · 3ms
          죽은 포트            → Failed to fetch · 6ms
```

**문구도 시간도 같다.** 'Not allowed to request resource' 는 **콘솔에만** 남고 스크립트는
읽을 수 없다. 즉 페이지 안에서는 **'브라우저가 막았다' 와 '서버가 없다' 를 가를 수 없다.**

→ 그래서 **단정하지 않는다.** 안내는 **두 가능성을 함께** 말하고, UA(사파리처럼 보이는가)는
**어느 쪽을 먼저 말할지**만 정한다. 하나만 말하면 절반의 사용자에게 따라 할 수 없는
지시가 된다 — 인앱 로그인에서 세운 원칙과 같다.

## 무엇을 바꿨나

- 모의고사 편집기 상단에 **누르기 전에** 뜨는 안내 줄(`#serverNote`):
  "실시간 정본 미리보기와 한글 내보내기는 로컬 서버가 있어야 하는 **개발용 기능**"
- 서버가 필요한 단추(`실시간`·`한글 내보내기`)에 `·서버` 표시
- ⚠️ **단추를 비활성화하지 않는다** — 서버를 방금 켰을 수도, 우리 감지가 틀렸을 수도 있다.
  기대치만 미리 알린다.

실제 동작(https 배포본 흉내 · 서버 켠 상태):
`chromium` 안내 없음 · `firefox` 안내 없음 · `webkit` **안내 뜨고 브라우저 설명이 먼저**.
서버를 끄면 `chromium` 도 안내가 뜨고 **서버 켜기가 먼저** 나온다.

## 남은 제품 결정 — 코드로 답할 수 없는 것

설계 §2 에 적어 둔 대로 이건 **제품 경계**다. 지금은 "개발용 기능" 이라고 **말해 주는**
데까지 했다. 그 다음은 사람이 정해야 한다:

1. 모의고사 편집기를 지인·상용 사용자에게 **열어 둘 것인가**, 아니면 감출 것인가?
2. 연다면 **윈도우 사용자**는 어떻게 하나? 지금 안내는 `python3 serve.py` 인데 파이썬 +
   `typst` 설치를 요구한다 — 사실상 불가능하다.
3. 시험지 HWPX 는 실물 틀 파일이 있어야 해서 브라우저만으로는 못 한다(`HANDOFF-2026-029`).
   AI 문서 쪽은 이미 브라우저만으로 되므로, **두 기능의 위상이 다르다**는 것을 UI 에서
   더 분명히 할지.
