## 무엇을 했나

한글(HWPX) 시험지에 없던 둘을 넣었다. 화면 미리보기와 Typst 정본에는 원래 있었고
**한글 내보내기에만 빠져 있던 것**이다.

| | 전 | 후 |
|---|---|---|
| `단답형` 구획 태그 | 없음 | 첫 단답형 문항 앞(공통 16번 · 선택 29번) |
| `※ 확인 사항` | 없음 | 각 과목 마지막 쪽 오른쪽 아래 |

`5지선다형` 은 **틀의 표제부에 이미 있다**(종이 기준 절대배치). 다시 넣으면 두 번 나오므로
넣지 않는다.

## 핵심 — 표를 지어내지 않았다. 틀에서 떠다 심었다

설계 문서는 '크기·테두리·안쪽 여백을 실물에서 재어 `append_table()` 로 만들라' 고
적어 두었다. 더 나은 길이 있었다: **틀 파일에 실물 표가 그대로 들어 있다.**

`template.capture_marks()` 가 `clear_body()` **전에** 표를 통째로 떠 두고
(이어지는 쪽 머리말을 다루는 방식과 같다), `mock_to_hwpx` 가 도로 심는다.
그래서 크기·테두리·안여백·글꼴이 **한 군데도 우리 값이 아니다.**

실물에서 잰 값(검사가 이 숫자와 직접 맞춘다 — 우리 코드를 우리 코드로 검사하지 않는다):

| 개체 | 크기 | 자리 |
|---|---|---|
| `5지선다형` | 38.82 × 8.28mm | 틀의 표제부(종이 기준) |
| `단답형` | 27.84 × 8.28mm | 문단 기준 · 글자처럼 흐름 |
| `※ 확인 사항`(3줄) | 111.00 × 35.64mm | **쪽 기준 절대배치** 오른쪽 아래(아래 0.5 · 왼쪽 123.0mm) |
| `※ 확인 사항`(2줄) | 111.00 × 21.15mm | 같음 |

**태그가 단 위에서 먹는 높이는 15.9mm** — 한글이 쓴 `linesegarray` 에서 읽는다
(태그 문단 위 끝 → 첫 문항). 그 값이 그 단의 '위 여백' 이 되어 문항 벌리기에 들어간다.
⚠️ `read_column_tops_mm()` 과 **이중으로 세지 않는다** — 그쪽이 읽는 값은 그 단의 첫
문단(= 태그 문단) 자리라 태그 높이를 담고 있지 않다.

## 곁가지로 찾아 고친 것 — Typst 가 태그 자리를 잘못 쓰고 있었다 🔴

`column-slots` 가 태그 자리를 첫 칸 **안**에 `v(pad-top)` 으로 밀어 넣고 있었다.
칸 경계는 그대로라 **태그가 붙은 단의 둘째 문항이 제자리에 남았다.**

| | 17번이 놓이는 자리 |
|---|---|
| 고치기 전(칸 안에 v) | ~123mm |
| 격자 앞에 v (중간 시도) | 176.1mm |
| **지금(격자 높이에서 뺌)** | **167.9mm** |
| 실물 | 172.8mm |

렌더해서 픽셀로 재어 확인했다. 지금은 화면·Typst·한글이 모두 같은 자리에 놓는다.

**그리고 태그가 먹는 높이가 화면·Typst 에서 19.5mm 였다.** 근거가 적혀 있지 않은
값이고 실물은 15.9mm 다. 셋을 **15.92mm** 로 맞췄다(`.tag` 아래 여백 7.63mm ·
Typst `TAGH` · 한글은 틀에서 읽는다). `npm run test:mock-layout` 이 셋의 일치를 검사한다.

## 되돌리지 말 것 (겪은 함정들)

- ⚠️ **태그 표 사본 중에는 셀 안에 이어지는 쪽 머리말을 품은 것이 있다.** 그걸 떠다
  심으면 쪽마다 머리말이 겹쳐 찍힌다 — 셀 안 문단이 **하나인** 사본만 고른다.
- ⚠️ **`「선택과목(…)」` 를 통째로 찾으면 못 찾는다.** 실물은 괄호와 과목 이름이 **다른
  run**(글자 모양 61 · 86)이라 사이에 태그가 끼어 있다. 실제로 그래서 한 번 틀의
  '미적분' 이 그대로 나갔다. `선택과목\([^)<]*\)` 로 찾는다.
- ⚠️ **첫 줄의 `※` 를 우리가 쓰지 않는다.** 실물은 기호 글꼴로 찍은 `*` 라, 유니코드
  `※` 를 넣으면 모양이 달라진다. 과목 이름만 갈아 끼우고 글은 실물 것을 쓴다.
- ⚠️ **`TMPL_MARKS` 를 `MARKS` 로 되돌리지 말 것.** `MARKS` 는 선지 라벨 ①②③④⑤ 다 —
  가려서 `KeyError: 0` 로 죽었다.
- ⚠️ **`<hp:p>` 를 정규식으로 자르면 표가 안 보인다.** 표 안에 문단이 또 있어
  `<hp:p ...>.*?</hp:p>` 가 표 안쪽에서 먼저 닫힌다. 검사를 그렇게 썼다가 6건이
  헛돌았다 — 문서 트리(lxml)로 훑는다.
- ⚠️ **JS 템플릿 리터럴(`TYPST_FRAME`) 안에 backtick 을 쓰지 말 것.** 주석에 하나 넣었다가
  편집기 스크립트가 통째로 죽었다(`Unexpected identifier`).

## 고친 곳

| 곳 | 무엇 |
|---|---|
| `pedagogy_hwpx.py` | `XmlNode.text_content()` — `<hp:t>단<fwSpace/>답…</hp:t>` 의 꼬리 글자까지 읽어야 태그를 찾을 수 있다 |
| `template.py` | `capture_marks()` — 표 두 종류와 태그 높이를 `clear_body()` 전에 떠 둔다 |
| `mock_to_hwpx.py` | `emit_section_tag()` · `attach_note()` · `tag_index()`, `build()` 에서 자리·단나눔·쪽나눔·단 위 여백 처리 |
| `mock-exam-editor.html` | Typst `column-slots` 의 태그 자리 버그 · `TAGH` 신설 · `.tag` 아래 여백 |

태그 문단이 단나눔·쪽나눔·이어지는 쪽 머리말을 **모두 안도록** `before` 를 태그보다 먼저
잡는다(실물도 태그 문단이 `columnBreak="1"` 을 안는다). 단 중간에서 유형이 바뀌면
태그를 흐름대로 넣고(화면의 `.tag.inline` 과 같다) 그 문항이 그만큼 길어진 것으로 센다.

## 검증 (§6 의 넷 + 하나 더)

1. `npm run check:fast` 통과 · 브라우저 회귀 **94/94**.
2. **실물 한글이 연다** — 30문항·단 중간 태그·첫 문항이 단답형인 경우까지 3종 확인.
3. **한글에게 좌표를 물었다** — 태그 뒤 첫 문항이 **15.9mm**(실물과 같다),
   확인 사항은 쪽 기준 절대배치 그대로 살아남는다.
4. **일부러 되돌려 빨간불 확인** — 태그를 빼고 확인 사항을 첫 문단에 매달면
   `test_sections.py` 4건이 실제로 실패한다. Typst 쪽은 `TAGH` 를 어긋나게 두면
   `test:mock-layout` 이 실패한다.
5. 🆕 **한글로 PDF 를 뽑아 눈으로 봤다.** '열린다' 와 '조판이 맞다' 는 다른 문제라
   이 단계를 새로 넣었다 — 6쪽·12쪽의 `단답형` 태그와 8쪽·12쪽의 `※ 확인 사항` 이
   실물처럼 찍힌 것을 확인했다.
   (파일 → PDF로 저장하기 를 `System Events` 로 누른다. ⌘S 와 마찬가지로 단축키는 안 먹는다.)

새 검사: `test_sections.py` 19건(크기·자리·나눔 속성·줄 수·절대배치·마지막 쪽·과목 이름·

## 검토 요청

- 태그가 먹는 높이를 19.5 → 15.92mm 로 바꾼 것. 실물은 15.9 이고 우리 공식으로는
  17번이 167.9mm(실물 172.8)에 놓인다. 19.5 였다면 169.75mm 로 실물에 1.8mm 더
  가깝다 — 다만 근거가 없는 값이었고 한글 쪽은 표의 여백이 정하므로 바꿀 수 없다.
- `※ 확인 사항` 을 **그 구역 마지막 쪽의 첫 문단**에 매다는 선택(쪽만 맞으면 되므로
  어느 문단이든 되지만, 규칙이 하나여야 한다고 봤다).
- 실물 `section0`(공통)에는 확인 사항 상자가 **없다**. 편집기 `noteFor()` 는 넣는다
  (한 학생의 시험지는 공통 뒤에 선택이 이어지므로 맞다고 봤다). 편집기를 따랐다.
