## 구현

1. ≤1023px 탐색을 본문 앞의 55px 가로 스크롤 행으로 배치했다. 고정·오버레이가 아니므로
   `viewport-fit=auto`를 유지하고 safe-area 보정은 추가하지 않았다.
2. 설정 출처를 문제집 편집기, 모의고사 편집기, 문제집/모의고사 라이브러리로 구분해 기억한다.
   뒤로 버튼의 이름과 실제 복귀 대상을 일치시키고 편집 세션 기억을 보존한다.
3. 모의고사 편집기 상단에 그 화면에서만 보이는 설정 버튼을 추가했다.
4. 문제집 14권 모바일 배치와 설정 3종 왕복을 브라우저 회귀로 고정했다.

## 검증

- Chromium 실측: 375×812(터치), 768×1024(터치), 1194×834, 1512×760.
- 375×812·14권: 탐색 수정 전 y=1798~1913 → 수정 후 y=77~132(높이 55px), 본문 y=158.
- 문제집 설정 왕복: `readLastSet()`과 `currentSetId` 유지, `editorView` 복귀.
- 모의고사 설정 왕복: 버튼 표시, 동일 `mockOpenId` 복귀.
- `npm run test:library-ui` 통과(15건), `npm run check:static` 통과.
- 고장 주입(`LIBRARY_UI_RED=1`)에서 새 두 회귀가 빨간불임을 확인했다.
- `npm run check:fast` 최종 통과. 함께 진행되던 `HANDOFF-2026-103`이 완료된 뒤 다시 실행해
  브라우저 감사 154건을 포함한 전체 계약을 확인했다. `test:mock-library-ui`의 후반 실패 출력은
  의도적인 고장 주입이 실제로 빨간불이 되는지 확인하는 자기검사이며 명령은 정상 종료했다.
  HWPX Python 대조는 로컬 `lxml` 부재로 기존 정책대로 건너뛰었다.
