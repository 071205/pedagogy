# 변경 인계 — 지문 없는 문항 묶음의 안내 줄

- ID: `HANDOFF-2026-042`
- 날짜: `2026-09-04`
- 작성자: `Claude`
- 상태: `ready-for-review`
- 영향 영역: `index.html`, `regression-test.html`, `scripts`, `test-fixtures`, `docs`
- 관련: `docs/ENGLISH-SUBJECT-DESIGN.md` ⑤ · `HANDOFF-2026-041`

## 무엇을 했나

지문 없이 **안내 한 줄만 공유하는 묶음**(`[16~17] 다음을 듣고, 물음에 답하시오.`)을 만들
수 있게 했다. 지금까지 범위 안내는 **지문 블록의 `lead`** 로만 나왔다.

## 근거 — 두 실물의 묶음 안내를 전부 뽑아 대조

| | 지문을 **함께 쓰는** 묶음 | **안내만** 함께 쓰는 묶음 |
|---|---|---|
| 국어 | 9개 — **전부** | **없다** |
| 영어 | 41~42 · 43~45 | 16~17(듣기) · 31~34 · 36~37 · 38~39 |

설계 문서가 남겨 둔 물음("지문 없는 묶음이 국어에 있는지 확인 필요")의 답은 **없다** 이다.
'다른 규칙' 이 존재하지 않으므로 과목을 가르지 않았다(④ 와 같은 판단).

⚠️ **31~34·36~37·38~39 는 문항마다 제 지문을 갖는다.** 묶음이 공유하는 것은 안내뿐이다.
그래서 `groupSpan` 을 '지문을 함께 쓰는 문항 수' 로만 읽으면 이 형식을 표현할 수 없었다.

## 무엇이 막고 있었나

`groupSpanOf()` 의 첫 줄이 `if(!hasPassage(q)) return 1;` 였다. 지문이 없으면 묶음 자체가
없는 것으로 쳐서 `computeNums()` 가 범위를 만들지 않았다.
그리고 묶음 설정 UI 가 **지문 블록 편집기 안에만** 있어서, 지문 없는 문항에는 애초에
묶음을 걸 수조차 없었다.

## 고친 곳 (네 곳)

1. **계약** — 문항에 `groupLead`(안내 글, 200자) 추가. `normProblem()`.
   ⚠️ `firestore.rules` 는 손대지 않았다 — 필드 화이트리스트는 **문제집 문서 수준**이고
   `problems` 는 `is list` 로만 검사한다(확인함).
2. **판정** — `groupSpanOf()` 의 빗장을 풀되 **안내 글이 있을 때만** 푼다.
3. **렌더** — `groupHeadHTML(q, range)` 를 미리보기·인쇄 **두 경로 모두**에서 블록 앞에 붙인다.
4. **편집 UI** — 묶음 칸(문항 수 + 안내 글)을 **문항 정보** 패널로 옮겼다.

## ⚠️ 되돌리지 말 것

- **안내 글 조건.** `groupSpan` 은 원래 '지문을 함께 쓰는 문항 수' 였다. 지문 블록을 지우고
  남은 옛 `groupSpan` 이 갑자기 `[01~02]` 를 그리면 **예전 데이터의 뜻이 바뀐다.**
  실물도 범위만 있고 안내 글이 없는 줄은 쓰지 않는다.
- **지문이 있으면 그리지 않기.** 지문 블록이 이미 `psg-head` 로 그린다 — 안 막으면 두 번 나온다.
- **묶음 UI 는 한 곳에만.** 블록이 아니라 **문항**의 값이다. 지문 블록 편집기에 남겨 두고
  문항 쪽에도 두면 `select` 둘이 같은 값을 쓰면서 서로 갱신되지 않아 한쪽이 낡는다.
  그래서 지문 블록 쪽은 지우고 안내 문구만 남겼다.
- **겉모습은 `psg-head` 재사용.** 따로 만들면 같은 문서 안의 두 안내 줄이 다르게 보이고,
  나중에 한쪽만 고쳐 갈라진다(이 저장소의 반복된 실패 ③).

## 검증

- **인쇄·미리보기 두 경로를 각각 그림으로** 봤다. 안내 줄이 같은 자리에 같은 모습으로 나온다.
- 지문이 있는 묶음과 없는 묶음을 한 문제집에 섞어 넣고 인쇄 DOM 을 세었다 —
  `grp-head` 1개 · `psg-head` 1개로, **안내가 두 번 나오지 않는다.** 지문 있는 문항에
  일부러 넣어 둔 `groupLead` 는 렌더에 나타나지 않는다.
- 편집 UI 를 세 경우(지문 있음 / 지문 없는 묶음 / 묶음 아님)로 훑어 안내 칸 표시와
  힌트가 각각 맞는 것을 확인했다.
- 브라우저 회귀 **106/106**(새 검사 4건). 셋을 일부러 되돌려 실패 확인:
  지문 있을 때도 그리기 · 안내 글 조건 제거 · `groupLead` 의 `sanitize()` 제거.
- `setHasContent()` 에 `groupLead` 를 더했다 — 안내만 적어 둔 문항이 '내용 없음' 으로
  판정돼 병합에서 빠지면 데이터가 사라진다(CLAUDE.md 가 경고한 자리).
- 시각 회귀 표본 `05-english-order` 에 지문 없는 묶음을 넣었다. 5건 통과 ·
  `npm run check:fast` 통과 · **국어 기준본 0.000%**(국어 경로 무변경).
- ⚠️ 표본이 바뀐 그 한 장만 다시 떴다. 나머지 넷은 되돌렸다(`HANDOFF-2026-037`).

## 곁가지 발견 — 묶음 안내 줄도 실물에서 굵지 않다 (이번 범위 밖)

영어 12.2pt · 국어 11.5pt, 둘 다 `bold=False`. 우리 `psg-head` 는 `font-weight:500` 에
범위를 `<b>` 로 감싼다. `.dlg-who` 건(`HANDOFF-2026-041`)과 같은 종류다 —
**우리 조판이 실물보다 굵다.** 고치면 국어 기준 시각본이 함께 바뀌므로 따로 두었고,
근거는 `docs/ENGLISH-SUBJECT-DESIGN.md` §6 에 모아 두었다. 둘을 한 번에 고치면 된다.
