# 변경 인계 — 이미 실패한 그림의 인쇄 대기 제거

- ID: `HANDOFF-2026-048`
- 날짜: `2026-09-06`
- 작성자: `Codex`
- 상태: `ready-for-review`
- 영향 영역: `index`, `tests`, `docs`
- 관련 이슈: `REV-2026-021`

## 변경 내용

최신 인쇄 최적화의 `awaitPrintImages()`를 다시 검토해, `error` 이벤트가 이미 지나간 그림을
8초 동안 다시 기다리는 문제를 고쳤다. 이제 성공·실패가 끝난 그림은 즉시 판정하고 아직
로딩 중인 그림만 기다리며, 실패나 시간 초과는 음수 개수로 돌려 기존 인쇄 경고가 뜨게 한다.

`tests/regression-test.html`에는 깨진 그림의 오류 이벤트가 **끝난 뒤** 함수를 호출하는 검사를
추가했다. 기존의 “붙인 직후 호출” 검사와 실행 순서가 달라, 지나간 이벤트를 기다리는 회귀를
잡는다.

## 위험과 검토 요청

- 정상 그림 여러 장이 진행 중일 때는 모두 도착한 뒤 양수 대기 개수를 반환해야 한다.
- 진행 중 그림 일부가 실패하면 나머지 그림은 계속 기다린 뒤 실패 개수를 음수로 반환해야 한다.
- 8초 상한에서는 아직 안 끝난 그림과 실패 그림의 합을 음수로 반환해야 한다.
- 완료 또는 상한 뒤 등록한 이벤트 리스너와 타이머가 남지 않는지 확인하면 된다.

## 검증

- 수정 전 실제 Chromium: 새 검사 실패 — `결과 hung · 1202ms`.
- 수정 후 브라우저 회귀: `122 / 122` 통과.
- `npm run test:visual`: 기준본 7종 및 글줄 삭제 자기검사 통과.
- `npm run check:fast`: worker·fixture·mock layout·static 통과.
- HWPX Python 검사는 로컬 환경에 `lxml`이 없어 건너뜀. 이번 변경은 HWPX 경로를 건드리지 않는다.

## 다음 검토자에게

`index.html`의 `awaitPrintImages()`와 `tests/regression-test.html`의 “이미 실패한 그림도 즉시
판정한다” 검사를 보면 된다. 잘못된 PNG data URL이 `complete=true`, `naturalWidth=0`이 된 뒤
호출했을 때 1초 안에 음수를 반환해야 한다.
