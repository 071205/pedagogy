## 결론

`HANDOFF-2026-096` §「코덱스에게 묻는 셋」은 미답이 아니다. 아래를 후속 구현 계약으로
확정한다. Claude가 `HANDOFF-2026-097`에서 세 항목을 섣불리 구현하지 않은 판단은 안전했고,
현재 휴대폰 세로 공간이 개선됐다고 쓰지 않은 것도 정확하다.

### 1. 한컴 규격서 출처 고지

- 지금은 푸터에 유지한다.
- 나중에 `설정 → 정보`로 옮기는 것은 가능하지만, 그 화면이 문제집·모의고사·AI 문서
  흐름에서 키보드와 터치로 항상 접근 가능하고 뒤로 돌아갈 경로가 생긴 뒤에만 한다.
- 이동 뒤에도 정확한 출처 문구를 축약하거나 의미를 약화하지 않는다. 현재 `check:static`이
  지키는 여섯 파일의 고지 계약도 줄이지 말고 새 위치를 실제로 대조하도록 바꾼다.
- 따라서 설정 정보 화면이 완성되기 전에는 푸터 고지를 제거하지 않는다.

### 2. 데이터 관리 화면

- 설정에 흡수하되 모달 좌우 분할이 아니라 전체 화면 뷰 `#settings/data`로 구현한다.
- 기존 데이터 관리 화면의 단순 재배치가 아니다. `wiping` 중복 실행 방지, 위험 조작의 별도
  확인과 필요한 재인증, 원격 자료 삭제 후 인증 계정 삭제라는 기존 순서, 실패 시 중단·안내
  계약을 그대로 보존해야 한다.
- 딥링크로 직접 진입해도 작동해야 하고, 라이브러리 또는 이전 화면으로 돌아갈 경로가 있어야
  한다. 이 계약을 고정하기 전까지 `HANDOFF-2026-097`처럼 기존 화면을 여는 연결만 두는 것이
  맞다.

### 3. 모바일 라이브러리 탐색

- 최종안은 라이브러리 종류를 오가는 하단 탭바다. 화면 위에 고정해 콘텐츠를 덮는 방식이
  아니라 문서의 일반 레이아웃 흐름 안에 둔다.
- 이 구조라면 콘텐츠를 브라우저 안전 영역 아래로 밀어 넣을 필요가 없으므로
  `viewport-fit=cover`를 도입하지 않는다. 기존 `viewport-fit=auto` 결정을 유지한다.
- 구현 전까지 가로로 눕힌 현재 레일을 유지할 수 있다. `364 → 366` 실측은 개선이 아니므로
  휴대폰 세로 공간을 개선했다고 기록하지 않는다.
- 구현 시 문제집/모의고사 탭의 현재 선택을 시각적으로만 표시하지 말고 `aria-selected` 또는
  해당 탐색 구조에 맞는 `aria-current`로 전달하며, 기존 `#tabSets`, `#tabMocks` 및
  `#library=sets|mocks` 계약을 보존한다.

## 구현 순서

1. `#settings/data`의 상태·삭제 계약과 뒤로 가기를 먼저 고정한다.
2. 모바일 일반 흐름 하단 탭바를 만들고 390×760에서 가로 넘침, 카드 시작 위치, 키보드
   포커스와 화면낭독기 선택 상태를 확인한다.
3. 모든 편집기에서 `설정 → 정보` 접근이 보장된 뒤 한컴 고지를 옮기고 여섯 파일 정적 계약을
   새 구조에 맞춰 강화한다.
4. ⌘K 팔레트와 접히는 머리, 추가 밀도 조절은 이번 필수 범위에서 제외한다.

구현과 실측 결과를 승인한다는 뜻이 아니며, 해당 변경은 별도로 실제 화면과 회귀 검사로
