## 변경 내용

[통합 레일](../../../docs/DEV-TOKEN-ROADMAP.md)에 제품 방향·AI 일괄 구성·N제 전체 지면·Apple UX
해석을 남은 R4/U0~U2와 B4~B7, R5 연결 검토, R8 사용자 과제로 배정했다.
[실행 지시](../../../docs/RAIL-ORDERS.md)와 [INDEX](../../INDEX.md)의 현재 위치를
**문서 통합 완료 → U0 요구 차이·연결 시안**으로 맞췄다. 실행 지시의 맨 앞에 현재 선택할 모델/명령과 나머지 모델별 큐를 추가하고 R1 독립 검토를 R5 전 비차단 작업으로 노출했다. GPT-6 Astra high용 U0 지시문은 미답 결정을 권장안·영향표로 한 번에 모으도록 구체화했다. 기존 미커밋 완료/검토 기록을 보존했다.

저장 계약·B3 코드/검토 증거·배포 미완료(`setRevisionSchema=0`)·R4.5 승인은 유지했다.
R1의 자기검증을 독립 승인으로 표시하던 실행 지시의 축약을 바로잡았다. 원문 설계·저장 계약과
기능 코드는 수정하지 않았고 `transcript.txt`는 열거나 수정하지 않았다.

## 위험과 검토 요청

- HANDOFF-162 Q3의 잠정 조판 중심 정의는 사용자 제품 방향으로 대체. Q1/Q2의 저장 구조·수정
  전파는 D1/U0로 이어받았으며 승인으로 닫지 않았다. B4는 D1/충돌 시안과 B3 실제 배포가 선행.
- 현 저장 계약 기준 순서와 B5 독립 진행, U1 앞당김 조건, B6의 U0 데이터 계약 의존을 대조할 것.
  U1/U2가 R5/R8에서 빠지거나 R5 완료가 다시 B4 선행이 되는 순환은 허용하지 않는다.
- D1~D4 제품 결정과 D5 기존 배포/실호출 승인을 분리했다. D3 운영 숫자 대기가 로컬 fixture
  구현을 막지 않지만 실서비스 활성화/운영 검증을 완료로 만들지도 않는지 확인할 것.
- 복제안은 권장안일 뿐이다. 공용 풀 선택 시 변경되는 계약·이행 경계만 먼저 설계하며 기존
  승인 diff의 무조건 재검토·폐기나 저장 구조 전환을 이번 통합이 승인하지 않는다.

## 검증

- 코드 접점 읽기 전용 확인: `newProblem`, `setToDoc`/`docToSet`, Rules `hasOnly`,
  `doPrint`/`fitPrintDoc`, `setRevisionSchema=0`. 문항 내부 꼬리표만으로 최상위 Rules 변경이
  필수라는 과거 INDEX 문구를 정정했다. 기능 동작을 재검증했다는 뜻은 아니다.
- `npm run check:review-hygiene` 통과: 이슈 107건/열림 3건 일치, INDEX 114/120줄, 최근 5/5, 자기검사 6/6.
- 변경 문서의 로컬 Markdown 링크 41개와 `git diff --check` 통과. 저장 계약·원문 제품 설계·
  기존 164/165 인계는 시작 시점 사본과 동일. `transcript.txt`는 내용 접근 없이 inode/크기/mtime 불변 확인.
- 기능/전체 회귀·실호출·배포는 미실행(문서 변경만). 독립 검토는 미실행이며 위 결과는 자기검증이다.
