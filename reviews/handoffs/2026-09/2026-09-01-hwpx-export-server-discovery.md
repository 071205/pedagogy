# 변경 인계 — 한글 내보내기가 로컬 서버를 제대로 찾게

- ID: `HANDOFF-2026-028`
- 날짜: `2026-09-01`
- 작성자: `Claude`
- 상태: `ready-for-review`
- 영향 영역: `index`

## 무엇을 고쳤나

배포본에서 `한글 내보내기` 가 **로컬 서버가 아니라 페이지 자기 주소**로 요청을 보내
404 를 받고 `한글 내보내기에 실패했어요` 만 띄우던 것을 고쳤다(`REV-2026-017`).

원인은 한 줄이다.

```js
const LIVE={ … base:'' … };                                  // 초기값이 빈 문자열
if(LIVE.base===null||LIVE.base===undefined){ await pingServer(); }   // 절대 참이 안 됨
```

`base:''` 가 '같은 출처' 라는 **유효한 값**이면서 '아직 안 찾아봄' 이라는 뜻으로도 쓰였다.
두 상태를 한 변수에 담아서 구분이 불가능했다. `LIVE.found` 를 따로 두어 갈랐다.

⚠️ **404 는 `catch` 로 가지 않는다.** 그래서 서버가 없을 때 쓰라고 만들어 둔 안내에
영영 도달하지 못했다. 오류 처리를 `catch` 에만 두면 '응답은 왔는데 틀린 응답' 을 놓친다.

## 바뀐 파일

- `mock-exam-editor.html` — `LIVE.found` 추가, `pingServer()` 가 그것을 세운다.
  `toHwpx()` 는 누를 때마다 없으면 다시 찾고, **못 찾으면 보내지 않는다.**
  안내 문구는 `NO_SERVER_MSG` 한 곳에 두고 두 자리에서 함께 쓴다.
- `document-editor.html` — `findHwpxServer()` 신설. 여긴 `"/document-hwpx"` 가 상대경로로
  하드코딩돼 서버를 찾는 단계 자체가 없었다(더 나빴다).

## 되돌리지 말 것

- ⚠️ **`base` 와 `found` 를 다시 한 변수로 합치지 말 것.** 빈 문자열은 정상적인 주소다.
- ⚠️ **서버를 부팅 때 한 번만 찾지 말 것.** 페이지를 먼저 열고 나중에 `serve.py` 를
  켜는 것이 오히려 흔한 순서다. 누를 때마다 확인한다.
- ⚠️ **못 찾았으면 요청을 보내지 말 것.** 보내면 404 가 오고, 그 404 는 사용자에게
  아무 도움이 안 되는 문구로 번역된다.

## 검토 요청 · 남은 것

- ⚠️ **이 수정은 깃허브 페이지에 아직 없다.** 배포본은 `main` 에 push 된 것을 서비스하므로,
  커밋·푸시하기 전까지 사용자는 여전히 옛 코드를 본다. 확실히 되는 길은
  `http://127.0.0.1:8787` 로 여는 것이다.
- 배포본에서 로컬 서버에 **닿을 수 있는가**는 별개 문제다. 확인한 환경에서는
  `net::ERR_BLOCKED_BY_CLIENT` 로 막혔다(우리 CSP·CORS·PNA 헤더는 모두 정상). 광고 차단
  확장이나 크롬의 로컬 네트워크 정책일 수 있다. 다른 브라우저·시크릿 창에서 확인해 주면 좋겠다.
