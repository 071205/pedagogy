## 무엇을 했나

영어 순서 문항의 `(A)(B)(C)` 가 **별도 줄**이던 것을 실물처럼 **문단 첫머리 인라인 +
행잡기**로 바꿨다. 국어 `(가)(나)(다)` 는 그대로 별도 줄이다.

## 근거 — 실물 `.hwp` 를 직접 읽었다

⚠️ 이번엔 **한글이 파일을 못 여는 상태**였다(창 0개인데 메뉴는 살아 있음 — CLAUDE.md 가
경고한 그 증상. 재시작해도 낫지 않았다). 그래서 PDF 를 못 뽑았고, 대신 `.hwp` 를 직접
읽었다. 값이 오히려 더 정확하다(조판된 좌표가 아니라 **조판 규칙 자체**를 읽는다).

| | 국어 실물 | 영어 실물 |
|---|---|---|
| 라벨 | `(가)(나)(다)` 가 **자기 혼자 있는 문단**(shape 34), 본문은 다음 문단(shape 2) | `(A)`+묶음빈칸(`\x1e`)+본문이 **한 문단**(shape 21) |
| 문단 모양 | — | 왼쪽 여백 3.99mm · **내어쓰기 7.62mm** |
| 라벨 글자 | — | 본문과 **같은 char shape**(11.5pt · 굵지 않음) |
| 해당 문항 | 여러 곳 | 36번(문단 363~365) · 37번(436~438) — 여섯 문단 모두 같은 모양 |

내어쓰기 7.62mm ÷ 본문 11.5pt(4.057mm) = **1.88em**. 우리 단이 실물보다 좁으므로
(82.37 vs 109mm) mm 가 아니라 em 으로 옮겼다.

곁가지로 확인된 것: 일반 지문 문단(shape 12)의 첫 줄 들여쓰기는 3.705mm 로, 앞서
PDF 로 잰 3.72mm 와 맞는다(= 지금 쓰는 0.87em). **두 방법이 서로를 검증한다.**

읽는 방법과 함정 셋(태그 번호 · **단위가 2배 다름** · 제어 문자)은
`docs/ENGLISH-SUBJECT-DESIGN.md` §5 에 적어 두었다.

## 고친 곳

1. `proseHTML(raw, lead)` — `lead` 를 받으면 **첫 산문 문단**에만 인라인 라벨을 붙인다
   (`psg-p psg-p-lab` + `<span class="psg-lab-in">`). 이미 `sanitize()` 를 거친 값을 받는다.
2. `blockHTML()` 의 지문 — `english && 라벨 있음 && 운문 아님` 이면 인라인, 아니면 종전대로
   `psg-label` 별도 줄. 운문은 `verseHTML()` 이 따로 그리므로 인라인이 가지 않는다.
3. CSS **두 벌**(`.preview` · `.pq`) — `text-indent:-1.88em; padding-left:1.88em`.

## ⚠️ 되돌리지 말 것 — 라벨의 `text-indent:0`

**검사가 다 초록불인데 인쇄물에서 라벨이 통째로 안 보였다.** `text-indent` 는 상속되고
라벨은 `inline-block`(= 제 블록)이라 음수 들여쓰기를 **한 번 더** 적용한다. 글자가 자기
상자 왼쪽 밖으로 나가고, 그 자리는 단 밖이라 `.pq{overflow:hidden}` 에 잘린다.

이때 **HTML 도 계산된 스타일도 요소의 자리도 전부 정상으로 나온다**(`labRect.x` 가
단 왼쪽 끝에 정확히 있었다). 마크업만 보는 검사로는 잡을 수 없고, 인쇄물을 눈으로
봐야만 보인다 — 이 저장소의 반복된 실패 ①번 그대로다.

그래서 **잡는 검사를 두 개 붙였다**(둘 다 일부러 되돌려 빨간불을 확인했다):
- 회귀 스위트 「인라인 라벨이 제 상자 안에 그려진다」 — `Range` 로 **글자가 실제로 놓인
  자리**를 재어 문단 상자 밖으로 나가는지 본다(되돌리면 `-21.7px` 로 잡힌다).
- 시각 회귀 표본 `05-english-order` (되돌리면 배치 **0.645%** · 허용 0.100%).

## 검증

- **인쇄 · 미리보기 두 경로를 각각 그림으로 뽑아 눈으로 봤다.** 실물처럼 `(A)` 가 문단
  첫머리에 오고 이어지는 줄이 라벨 뒤에 맞는다. 두 경로가 같다.
- 브라우저 회귀 **100/100**(새 검사 3건). 셋 다 일부러 되돌려 실제로 실패시켜 봤다 —
  과목 분기 제거 / 라벨 `sanitize()` 제거 / 라벨 `text-indent:0` 제거.
- `npm run check:fast` 통과 · 시각 회귀 **5건** 통과.
- **국어 기준본이 0.000% 로 그대로다** — 국어 경로를 건드리지 않았다는 직접 증거.
- ⚠️ `update:visual-baseline` 은 다섯 장을 모두 덮어쓴다. 새로 생긴 영어 한 장만 남기고
  나머지 셋(내용은 그대로인데 바이트가 바뀐 것)은 되돌렸다(`HANDOFF-2026-037`).

## 검토 요청

- 한 조각이 **여러 문단**일 때 인라인 라벨을 **첫 문단에만** 붙이고 나머지 문단은 종전대로
  0.87em 들여쓰기로 두었다. 실물 36·37번은 조각이 한 문단씩뿐이라 근거가 없는 구간이다.
- `min-width:1.88em` 이라 `(가)` 처럼 더 넓은 라벨이 오면 그 줄만 밀린다(잘리지는 않는다).
  지금은 영어 전용이라 실제로 걸릴 일이 없지만, 국어에도 열면 다시 볼 것.
