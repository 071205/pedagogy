## 왜 했나

`REV-2026-043` ~ `-050` 은 **보고자와 수정자가 둘 다 코덱스**다. 저장소 규칙("구현자와
독립 검토자가 번갈아 확인한다")대로 다른 눈이 한 번은 봐야 했다. 제품 코드는 고칠 것이
없었고, **검사 쪽에서 재현 가능한 결함 하나**가 나왔다.

## 1. 코덱스 8건 — 독립 검증 결과: **유효하다**

제품 코드는 한 줄도 고치지 않았다.

- **실패 주입 재현.** `REVIEW_RED=1 node scripts/check-review-contracts.mjs` 는 기준 커밋
  `31da3eb` 의 제품 코드를 페이지에 공급한다. **16건 중 13건이 빨간불**이다. 초록 셋은
  정당한 대조군이다 — 정적 HTTP 다운로드는 기준 커밋에서도 됐고(코덱스가 대조군이라고
  적은 그것), 나머지 둘은 제품과 무관한 브라우저 사실과 기존 계약이다.
  즉 **8건 전부 옛 코드에서 실제로 잡힌다.**
- **짝 확인(`REV-049`·`-050`).** "한 곳만 고치지 않는다" 규칙대로 JS·파이썬 양쪽을
  직접 봤다. 디코딩 후 2MiB 상한이 `mock-exam-editor.html:2302`(`atob(...).length`)과
  `mock_to_hwpx.py:_figure_bytes`(`base64.b64decode(validate=True)`) 양쪽에 있고,

  `mock_to_hwpx.py:515`(`data.startswith(b"\x89PNG")`) 양쪽에 있다.
- **`REV-046` 의 디바운스 함정.** CLAUDE.md 가 "여러 문항을 한꺼번에 바꾸면
  `historyStep()` 으로 감싸라(350ms 디바운스)" 고 경고하는 지점이다. 선택 삭제 핸들러
  (`index.html:3816`)가 변경 앞뒤로 `flushHistory()` 를 부르고 있고, 실제 `onclick` →
  `doUndo` → 늦은 `onSnapshot` → `doRedo` 를 도는 검사가 그것을 지킨다. 문제없다.

### 남겨 두는 관찰 (이슈로 올리지 않음)

2MiB 상한 값이 JS 와 파이썬에 **각각 리터럴로** 박혀 있다. 언어가 달라 상수를 공유할 수
없고, 지금은 값이 같으며 재현되는 결함이 아니라 이슈로 만들지 않았다. 다만 `test:hwpx-exam`
의 대조 표본에 **상한을 넘는 그림이 없어** 이 값이 갈라지면 아무도 모른다. 실무 위험은
낮다(서버 경로는 `MAX_BODY` 가 따로 막는다).

## 2. `libraryCloudSchema` 를 **0(A단계)** 으로 내렸다

`42b62d8` 이 `firestore.rules` 의 `hasOnly` 목록에 `folderId` 를 넣고 `prefs/library`
경로를 새로 열었다. 코덱스도 "운영 Rules 배포가 완료됐다는 커밋 설명은 원격 조회로
재확인하지 않았다" 고 적었다. **해리가 배포 여부를 확인하지 못한다고 답해 0 으로 내렸다.**

새 Rules 가 실제로 배포돼 있지 않은데 1 로 두면 **로그인 사용자의 문제집 저장이 전부
'권한 오류' 로 실패한다.** 0 에서는 소속을 계정별 로컬 metadata 에만 쓰고 저장 요청에
`folderId` 를 넣지 않아 구형 Rules 에서도 저장된다. `CLAUDE.md` 에 그 이유와 되돌리는
조건을 적었다.

## 3. `REV-2026-051` — 검사가 배포 플래그를 물려받았다

**0 으로 내리자마자 검사 7건이 빨간불이 됐다.** 제품이 깨진 것이 아니라, 두 검사 묶음이
B단계 동작을 검사하면서 자기 단계를 선언하지 않고 `service-config.js` 값을 그대로 썼기
때문이다.

방향이 나쁜 쪽으로 겹친다 — `HANDOFF-2026-073` 이 "공개 전에 0 으로 내려라" 고 지시하는데,
**그 지시를 따르는 순간 안전망 일곱이 잘못된 이유로 빨간불이 되고 제품 결함과 구분할 수
없다.** 부수적으로 **A단계(지금 출시하는 설정) 경로에는 실질 검사가 거의 없었다.**

| 곳 | 고친 방법 |
|---|---|
| `scripts/check-review-contracts.mjs` | `app()` 이 `index.html` 검사에 `schema`(A=0·B=1) **선언을 강제한다** — 안 하면 던진다. 앞으로 어떤 검사도 플래그를 조용히 물려받을 수 없다 |
| `tests/regression-test.html` | `withSchema(v, fn)` 으로 걸고 **되돌린다**(안 되돌리면 같은 페이지의 뒤 검사가 오염된다) |

계약도 갈랐다. **삭제된 폴더 가리기(`liveFolderId`)는 두 단계 모두** 지켜야 하고(정본이
문제집 문서든 옛 이관 지도든), **"명시적 빈 값이 옛 지도를 이긴다" 는 B 전용**이다 —
A 는 클라우드에 `folderId` 를 보내지도 읽지도 않으므로 로컬 지도가 정본으로 남는 것이
맞다. 처음엔 이것을 제품 결함으로 의심했는데, 코드를 읽어 보니 **내 기대가 틀렸다.**

**규칙 허용 필드 대조는 두 단계를 함께** 본다. 새 Rules 가 `folderId` 를 선택 필드로
받으므로 A 의 좁은 키 목록도 유효해야 하고, 한쪽만 보면 구형 Rules 배포에서 저장이 통째로
막히는 것을 못 잡는다.

  5. `setToDoc` 이 **B 에서도 folderId 를 안 보내게** 하면 → 3건 빨간불.

- `npm run check:fast` **종료코드 0**.
