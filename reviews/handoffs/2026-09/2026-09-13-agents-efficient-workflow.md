## 변경 내용과 범위

사용자가 승인한 비용 절약 제안의 6번만 설계·적용했다.
[`AGENTS.md`](../../../AGENTS.md)에 필요한 범위부터 탐색, 확인 내용 재사용,
긴 로그의 증거·종료 코드 보존, 불필요한 검사 반복 방지, 간결한 보고·인계를 추가했다.
고정 줄 수 제한·한 줄 코드 강제·전체 읽기 금지를 넣지 않았다. 기존 공동 리뷰와
기능 변경 시 회귀·실패 주입 의무는 그대로 유지한다.

Worker 측정·출력 한도·공급자 비교/어댑터·제품 코드 분리(제안 1~5번)는 이번 범위 밖이다.
모델 전환이나 외부 호출을 자동화하는 규칙·플러그인도 추가하지 않았다.

## 검토 기준

- 큰 함수: 검색 결과 한 줄로 판단하지 않고 호출부·실패 경로까지 읽을 수 있어야 한다.
- 긴 검사: 화면의 PASS만 보지 않고 실제 완료·원래 종료 코드·실패 로그를 확인해야 한다.
- 동시 변경: 앞서 읽은 내용과 검사 결과를 무조건 재사용하지 않아야 한다.
- 문서 변경: 관련 문서 검증으로 마무리하되, 기능 변경의 필수 회귀는 생략하지 않아야 한다.
- 모델 인계: 다음 작업자가 실제 파일을 확인하며, 전수 재탐색은 필요한 경우에만 한다.

## 검증

기존 규약 보존과 위 다섯 상황을 문구로 대조했다. 문서 링크·인계 ID·diff 공백 검사를
실행했다. 제품 코드 변경이 없어 브라우저 회귀와 AI 호출은 실행하지 않았다.
토큰 절감률과 모델별 지침 준수율은 측정하지 않았으며 특정 비율을 보장하지 않는다.

6번의 구현은 완료됐다. 남은 일은 위 기준에 따른 짧은 독립 문서 검토다.
추천 모델은 `GPT-5.6 Luna`, 추론 `medium`이다. 현재 앱에서 선택 가능하며,
[공식 모델 설명](https://developers.openai.com/api/docs/models/gpt-5.6-luna)의 비용 중심 용도와
이번 제한된 문서 검토 범위를 고려한 추천이다. 앱 사용량 절감률을 계산한 것은 아니다.

검토 범위: `AGENTS.md`의 추가 절, 이 인계, `INDEX.md`의 123 연결.
기존 미커밋 변경을 보존한다. 필수 검증 약화·오류 은폐·지침 충돌이 없는지 확인하고
명확한 문서 결함만 최소 수정한다. 이상이 없으면 이 인계에 검토 결과만 덧붙여 끝낸다.
제품 코드·모델 설정 변경, 제안 1~5번 착수, 전체 회귀 재실행은 이 검토의 범위가 아니다.

## 독립 검토 결과 (2026-09-13 · Codex)

승인한다. `AGENTS.md`의 기존 공동 리뷰 규약과 추가 절을 전문으로 읽고 실제 diff와
이 인계의 다섯 검토 기준을 대조했다.

- 필요한 구간부터 읽되 지침 전문, 호출부, 상태 변경, 실패 경로와 전체 검토 예외를 명시해
  검색 결과 일부만 보고 판단하게 하지 않는다.
- 긴 로그를 보존하고 원래 검사 프로세스의 종료 코드·완료 여부·잘린 출력까지 확인하게 해
  `head`나 마지막 파이프 명령이 실패를 숨기는 경로를 막는다.
- 코드·의존성·환경 변경과 새 실패 근거가 있으면 재검증하며, 기존 필수 회귀와 실패 주입은
  유지한다고 명시해 검증 의무를 약화하지 않는다.
- 간결한 보고는 전체 코드의 재출력만 줄이며 오류 처리·설명 생략과 한 줄 압축을 금지한다.
- 인계 효율 규칙 앞에 상위 리뷰·검증 의무를 줄이지 않는다는 우선 문장이 있어, 기능 변경 뒤
  새 인계 기록을 만드는 기존 의무와 충돌하지 않는다.

문서 결함과 수정 필요 사항은 발견하지 못했다. 제품 코드와 제안 1~5번은 건드리지 않았고,
문서 전용 변경이라 전체 제품 회귀는 반복하지 않았다. `git diff --check`와 기존 규약 보존,
로컬 링크·인계 ID 연결을 확인했다.
