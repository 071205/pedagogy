## 무엇을 했나

**AI 문서 → 한글 내보내기가 로컬 서버 없이 된다.** 사이트만 열면 브라우저가 직접
`.hwpx` 를 만든다. `serve.py` 는 이제 대비책이다.

파이썬 변환기(`pedagogy_hwpx.py` · `tex_to_hwp.py` · `document_to_hwpx.py`, 약 1,340줄)를
자바스크립트로 옮겼다.

| 새 파일 | 하는 일 |
|---|---|
| `hwpx-engine.js` | ZIP 읽기·쓰기, XML, 문단·수식·그림·표, LaTeX→HWP 수식 변환 |
| `hwpx-document.js` | 문서 JSON 11블록을 문단으로 푸는 규칙 |
| `scripts/check-hwpx-browser.mjs` | **브라우저 ↔ 파이썬 결과 대조** |

## 왜 서버가 필요했는지, 무엇이 남았는지

두 가지가 막고 있었고 **둘 다 성격이 달랐다.**

1. **틀 파일** — 해리 확인 결과 `평가원 수학 양식.hwpx` 는 평가원 저작물이 아니라 개인이
   만든 것이다(파일 안에 만든 사람 이름이 207곳 박혀 있다). 다만 그 파일에는 2025 수능
   문제와 도형 9개가 들어 있어 **그대로 올릴 수는 없다.** 내용을 벗긴 틀로도 시험지가
   글자 하나까지 같게 나오고 한글이 여는 것을 확인했다(`clear_body` + `strip_bindata`).
   → 지금 이 변경에는 넣지 않았다. 모의고사를 브라우저로 옮길 때 함께 결정할 일이다.
2. **변환기가 파이썬** — 이번에 옮긴 것이 이것이다.

⚠️ **모의고사(`/hwpx`)는 여전히 서버가 필요하다.** 시험지는 실물 틀을 읽어야 하고, 그
   틀은 아직 저장소에 없다. AI 문서만 `templates/blank.hwpx`(한글이 저장한 빈 문서, 저작물
   아님, 이미 저장소에 있음)를 쓰므로 브라우저만으로 된다.

## 기술 선택과 이유

- **외부 라이브러리를 쓰지 않았다.** ZIP 은 브라우저의 `CompressionStream('deflate-raw')`
  으로 직접 쓰고, XML 은 `DOMParser`/`XMLSerializer` 를 쓴다. CDN 하나를 더 부르면
  CSP·SRI·오프라인 동작이 전부 걸린다.
- **빈 골격은 여전히 실물 파일을 받아 쓴다**(`templates/blank.hwpx`). 코드로 지어 만들면
  한글이 못 연다 — 이미 두 번 실패한 길이다(`docs/HWP-SPEC.md`).
- **base64 로 파일에 박아 넣지 않았다.** 박으면 `file://` 에서도 되지만 골격이 두 벌이
  되어 갈라진다. 이 저장소가 반복해 당한 방식이라 `fetch` 로 한 벌만 둔다.
  ⚠️ 그래서 `serve.py` 의 `STATIC` 에 골격 경로를 넣었다. 빼면 로컬에서 404 로 죽는다.

## 되돌리지 말 것

- ⚠️ **`scripts/check-hwpx-browser.mjs` 를 지우지 말 것.** JS 는 파이썬의 **사본**이고,
  사본은 갈라진다. 같은 문서 JSON 을 진짜 브라우저(Playwright)와 파이썬에 넣어 결과를
  맞춘다. 바이트가 아니라 **조판을 결정하는 신호**(글자 조각 차례·수식 스크립트·문단 수·
  문단/글자 모양 참조 차례·표·그림·탭·테두리)를 본다 — 직렬화 차이로 깜빡이지 않게.
- ⚠️ **검사 편의로 CSP 에 `unsafe-eval` 을 열지 말 것.** 신호 추출을 브라우저 안에서
  `eval` 로 돌리려다 막혔고, 그래서 Node 에서 뽑도록 바꿨다. 그 `unsafe-eval` 없음은
  일부러 세운 방어선이다.
- ⚠️ 브라우저는 빈 글자칸을 `<hp:t/>`(자기닫음)로, 파이썬은 `<hp:t></hp:t>` 로 쓴다.
  뜻은 같다. 대조 정규식이 자기닫음을 함께 보지 않으면 **다음 태그까지 삼켜** 수식
  스크립트가 글자 조각에 섞여 든 것처럼 보인다(실제로 그렇게 한 번 오진했다).

## 검증

- `npm run test:hwpx-browser` — 표본 문서와 '표본에 없는 블록' 문서(행렬·cases·3+2 선지·
  세로 선지·라벨 없는 상자·라벨 바꾼 보기) 두 건 모두 **파이썬과 완전히 일치**.
- **일부러 깨뜨려 확인** — 인용문 글자 모양을 한쪽만 바꾸자 `charRefs` 한 자리(12→11)를
  잡아 빨간불이 났고, 되돌리니 다시 초록불.
- **실물 한글이 브라우저가 만든 파일을 연다**(`npm run test:hwpx-opens`, 2건).
- **서버가 전혀 없는 정적 호스팅에서 동작 확인** — `python3 -m http.server` 로 띄우고
  (`/health` 404 · `/document-hwpx` 없음) 내보내기 버튼을 눌렀다. 요청한 것은 빈 틀
  하나뿐이고 서버 경로는 시도조차 하지 않았으며 파일이 나왔다. 배포본과 같은 조건이다.
- `npm run check:fast`(HWPX 10건 + 브라우저 대조) · `npm run test:visual` 통과 ·
  `regression-test.html` **92/92 통과**.
- CI 의 `hwpx` 작업에 `HWPX_REQUIRE=1` 로 걸었다. 이 대조는 글꼴 실측이 아니라 XML 결과
  비교라 `test:hwpx-parity` 와 달리 깜빡이지 않는다.

## 검토 요청

- **파이썬을 언제 걷어낼 것인가.** 지금은 두 벌이고 검사로 묶어 두었지만, 사본은 결국
  비용이다. 모의고사까지 브라우저로 옮기면 파이썬은 CLI 전용이 된다 — 그때 남길지
  정하는 것이 좋겠다.
- **`Math.round` 와 파이썬 `round` 는 .5 에서 다르게 반올림한다**(JS 는 올림, 파이썬은
  짝수로). 문단 여백 계산(`unit()`)에 쓰이는데 지금 표본에서는 차이가 나지 않았다.
  값이 정확히 .5 로 떨어지는 여백을 새로 넣으면 1 HWPUNIT(=1/7200인치) 어긋날 수 있다.
- 표는 여전히 실물 대조를 못 했다(파이썬 때부터 있던 한계다 — `append_table` 주석 참고).
