### 2026-09-27 — Claude Opus 5.5 독립 검토: **부분 동의 · B6 전 보완 2건**

범위: U0 §3-1·4-1·5, 저장 계약 §6, 레일 D1~D4 행. 사용자 답(D2② 숫자 TTL 없음·종료≠삭제·
결과 그림 독립, D4 목록 먼저+기억+설정)은 **빠짐없이 보존**됐다. B3 set CAS를 느슨하게 하는 문장은 없다.
guest↔계정 자동 이동 금지는 현재 앱과 일치한다(`index.html:2800` guest 칸은 로그인 때 옮겨지지 않는다).

**B6 전에 고칠 것 (미합의 — 작성자가 §5에 반영)**

1. **원문을 지켜 주는 근거가 '연결 레코드'뿐이라, 연결 없이 원문을 가리키는 문제집이 생긴다.**
   §5-1은 "보존 근거는 연결 레코드다", 권 연결은 `(owner, setId, sourceId)`다. 그런데 새 setId로
   문항을 통째로 옮기는 기존 경로가 셋 있다 — 문제집 복제(`index.html:5858`),
   B4 충돌 사본 `(내 사본)`(`index.html:4337` `ensureConflictCopies`), 백업 되돌리기
   (`restorePedagogyBackup`). 반례: A권을 복제해 B권을 만든다 → A권 삭제 = 마지막 연결 해제로
   판정 → '원문도 삭제' → B권 문항의 원본 대조가 끊긴다. 사용자는 B가 같은 원문을 쓰는 걸 봤는데도
   '영향 범위'에 B가 안 나온다.
   **요구**: (a) 문항별 출처(sourceId·쪽 목록)는 연결 레코드가 아니라 **문항 메타데이터**(§3 `intake`)에
   둔다 — 복제·사본·Undo·백업을 그대로 따라간다. (b) 마지막 연결 판정·삭제 영향 범위는 연결 레코드와
   **이 owner의 실제 로컬 문제집·충돌 기록 snapshot의 출처 참조**를 합쳐 계산하거나, 위 세 경로
   각각이 연결을 만들도록 명시한다. 어느 쪽이든 §7 'B6 공통 원문' 수용 증거에 복제·충돌 사본·
   백업 되돌리기를 더한다.
2. **문제집 삭제는 되돌릴 수 있는데, 마지막 연결 해제 질문을 삭제 순간에 하면 되돌리기와 어긋난다.**
   반례: 권 삭제 → '원문도 삭제' 선택 → 되돌리기로 권 복원 → 원문은 이미 삭제 세대가 올라가 복구 불가.
   '모든 문제집 삭제'(백업 남김·복구 가능)도 같다.
   **제안**: 권 삭제·모든 문제집 삭제는 원문을 `unlinked`로만 두고 알림만 준다. '원문도 삭제' 질문은
   **명시적인 '원본 연결 해제'** 동작과 설정의 원문 목록에서만 묻는다. 되돌리기로 권이 돌아오면
   `unlinked` → `available`. (사용자 답 "마지막 연결 해제 시 범위 표시·명시 선택"과 충돌하지 않는다 —
   질문 시점만 되돌릴 수 있는 삭제 뒤로 옮긴다.)

**B6을 막지 않음 (해당 게이트에서 닫을 것)**

3. §3-1 **역참조 목록이 정의되지 않았다.** "서버에서 확인한 참조 목록"·"참조 없음이 서버에서 확인"을
   요구하지만, 참조는 set 문서의 `problems` 배열 속 맵이라 Firestore 쿼리로 찾을 수 없고 Rules도
   검증할 수 없다. 공유 문항 쪽 역참조(예: `sharedProblems/{id}/refs/{setId}`)와 그것을 set 참조 CAS와
   같은 transaction으로 갱신하는 규칙이 필요하다. D1 연동 활성화 게이트의 필수 항목으로 적을 것.
4. §5-2 **브라우저가 원문을 지우는 조건을 구체화할 것.** D2②는 장기 보관이 전제인데 [통설] 사파리/iPadOS는
   한동안 방문하지 않은 사이트의 IndexedDB를 지울 수 있다. `navigator.storage.persist()` 요청·거부 시
   설정 화면의 안내를 계약에 넣는다. 조건은 재현 전이므로 [통설]로 표시한다(CLAUDE.md: ITP 조건 주장이 틀린 전례).
5. §4-1 "설정에서 언제든 **해제**" → 사용자 답은 "설정에 가서 **바꿀** 수" — 켜기·끄기 둘 다.
