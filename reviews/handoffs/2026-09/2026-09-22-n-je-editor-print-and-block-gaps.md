## 1. 선지 넘침 — **실제 결함이다** (`REV-2026-104` · P1)

명세와 실측표는 그 이슈 파일에 있다. 여기에는 **다시 알아내는 값이 큰 것**만 남긴다.

⚠️ **`minmax(0,1fr)` + `min-width:0` 인 그리드 컨테이너는 칸을 절대 넘지 않는다.**
그래서 컨테이너를 재는 넘침 판정은 **언제나 false** 다. 넘치는 것은 셀 내용이고
`overflow-x:hidden` 이 그것을 조용히 자른다. 실측: 보정 전 잘린 선지 50 → 보정 후 50 ·
`choices--wrap` 적용 0건 · 제안 판정(`.choice .text`)은 10/10 을 잡는다.

⚠️ **같은 이유로 (1-b) 개별 축소도 죽어 있었다** — 신고에 없던 것이다. `.text` 가
`overflow:hidden` 인 flex 아이템이라 자동 최소 크기가 0 이 되어 `.choice` 도 안 넘친다.

⚠️ **`choices--wrap`(`auto-fit,minmax(34mm,1fr)`)은 2단 시험지에서 항상 2열이다**
(단 84.5mm). 실측 높이가 `cols2` 와 **정확히 같다**(130px). 3열이면 87px 로 끝나는
문항이 매번 2열로 떨어져 **블록당 43px** 를 버린다 → 사다리(5→3→2→세로)로 간다.

⚠️ **`paired` 의 넘침은 재현되지 않았다.** 긴 적분식 12칸에도 68.2px 여유가 남았다.
소스 주석의 "`paired` 는 가로로 넘치기 더 쉽다" 는 **근거 없는 통설**이고,
게다가 `paired` 는 flex 라 `choices--wrap` 이 애초에 듣지 않는다. **재현이 없으므로
고치지 않는다.**

### 2. `⋮` — 신고보다 고칠 곳이 많다

`isEllipsisLine()` 은 `(중략)(하략)(전략)` 만 잡고 `passage`·운문에서만 쓰인다.
**`⋮`·`…` 를 목록에 더하는 것만으로는 끝나지 않는다.**

⚠️ `statement`·`boxed` 는 `processText(text)` 에 통째로 넘긴다. 그런데 `processText` 는
`\n` 을 **문단이 아니라 `<span class="vspace" style="height:6pt">` 간격**으로 바꾼다
— **가운데 정렬할 상자 자체가 없다.** 그래서 `blockHTML` 의 그 두 갈래에서 줄을 갈라
**특수행만 `.psg-mid` 로 내고 나머지 줄 묶음은 지금처럼 `processText` 에 통째로** 넘겨야
한다(줄마다 따로 렌더하면 기존 줄 간격이 달라진다).
⚠️ `$$…$$` 안의 `\n` 에서 쪼개면 표시 수식이 깨진다 — 이미 있는 `splitParagraphs()` 의
'`$$` 밖에서만 자른다' 규칙을 재사용할 것.
⚠️ 판정은 **한 줄이 통째로** 그 기호일 때만. 넓게 잡으면 기존 데이터의 뜻이 바뀐다.

### 4. `pair` 개명 — 하지 않는다

⚠️ **UI 는 이미 실제 뜻을 말하고 있다.** `SPAN_HINT.pair` =
「다음 문제와 한 단에 나란히 들어갑니다.」(`index.html:7449`). 오해를 부르는 것은
힌트가 아니라 **세그먼트의 짧은 라벨('묶음')** 이다.
저장된 데이터의 값을 바꾸면 이관과 이중 호환이 따라붙는데, 얻는 것은 내부 이름뿐이다.
**고칠 것이 있다면 라벨 문구이지 데이터의 값이 아니다.**

### 5. 이미지 자유 % — 최소 안전 형태

⚠️ 이 값은 `style="width:…"` 로 들어가고 `IMG_SIZES` 화이트리스트가 **유일한 방어선**이다.
자유 문자열을 받으면 가져온 `.json` 하나로 임의 CSS 가 섞인다.

- 원시 CSS 문자열을 **저장하지 않는다.** `widthPct` 같은 **숫자 전용 필드**를 새로 둔다.
- `normBlock` 에서 `Number()` → `Number.isFinite()` → 정수화 → **10..100 범위 고정**.
  벗어나면 기존 `size` 또는 100 으로 떨어뜨린다.
- `%` 는 **렌더가 붙인다**(출처의 `–`, 각주의 `*` 와 같은 규칙). 사용자가 넣은
  `%`·`;`·`calc()` 를 그대로 `style` 에 넣지 않는다.
- 기존 `size:full|large|medium|small` 은 계속 읽고, `widthPct` 가 있을 때만 우선한다.
- ⚠️ 필드가 늘어도 `firestore.rules` 의 `hasOnly` 는 **최상위 키만** 보므로 영향 없다
  (`REV-2026-103` 에서 확인한 사실이다).
