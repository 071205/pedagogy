## 왜 지금 이것인가

레일의 남은 단계는 전부 막혀 있다 — OPS-8 은 문서가 **"데이터가 없으면 대기, 요약기·대시보드를
임의 추가하지 않는다"** 고 못 박았고, OPS-9·10 은 그 분포가 있어야 하며, REL-11~15 와 출시 게이트
여덟은 가격·PG·법무 같은 **사용자 결정**이 입력이다. 막히지 않은 것은 감수서 대조가 남긴
*"기존 검사 재사용. 최신 실행/skip·실기기 증거는 따로 확인"* 하나였다.

## 알아낸 것 ① — 자동 경로가 없던 검사 여섯, 그중 진짜는 하나

검사 스크립트 30개를 `package.json`·CI 워크플로와 전수 대조했다.

| 스크립트 | 판단 |
|---|---|
| `check:launch` | 의도된 제외 — 출시 전 게이트라 지금 빨간불이 정상 |
| `test:hwpx-parity` | 의도된 제외 — 글꼴 실측이라 CI 에서 깜빡인다(문서에 근거) |
| `test:hwpx-opens` | 불가 — 맥 + 한글 + 손쉬운 사용 권한 |
| `test:all` | 묶음 자체(`check:fast` + `check:rules` + `test:visual`) |
| `check:review-copy` | 검토용 사본을 만드는 주문형 도구 |
| **`check:review-hygiene`** | **진짜 구멍** — 의존성 없는 순수 Node 인데 아무 데도 안 걸려 있었다 |

`check:fast` **맨 앞**에 걸었다. 즉시 끝나고, 기록이 어긋나면 10분짜리 묶음을 기다리기 전에 멈춘다.
⚠️ 깨보기로 확인했다 — 없는 이슈를 INDEX 표에 심으니 `check:fast` 가 **첫 단계에서** 빨간불을
내고 뒤로 가지 않았다. 되돌리니 통과.

## 알아낸 것 ② — `check:fast` 가 **아무것도 검사하지 않고 초록불**을 낼 수 있다

이번 실행에서 `check:fast` 는 exit 0 이었는데 로그에는 이렇게 찍혀 있었다:

```
lxml 이 없어 HWPX 검사를 건너뜁니다
틀 읽기 대조를 건너뜁니다 — 파이썬 쪽을 돌리지 못했습니다
브라우저↔파이썬 대조를 건너뜁니다 — lxml 이 없습니다
```

⚠️ **같은 세션 안에서 결과가 갈렸다.** 앞에서는 같은 명령이 12건을 실제로 돌려 통과했다.
원인은 PATH 다 — `lxml` 은 이 컴퓨터에서 **`/opt/anaconda3/bin/python3` 에만** 있고, PATH 앞에
다른 파이썬(`/usr/bin/python3`)이 오면 셋이 통째로 건너뛴다.

- **CI 는 안전하다** — 별도 `hwpx` 작업이 venv 에 의존성을 깔고 `HWPX_REQUIRE=1` 로 돌려
  건너뜀을 실패로 만든다.
- **위험한 것은 로컬**이다. 초록불을 보고 "HWPX 도 검증됐다" 고 믿는 것.
- 확실히 하려면 `HWPX_PYTHON=/opt/anaconda3/bin/python3 npm run test:hwpx`.

이 함정을 `CLAUDE.md` 의 Testing 절에 적었다(다시 알아내는 값이 크다).

## 하지 않은 것 (이유 포함)

- **OPS-8 분석 도구를 미리 만들지 않았다.** 레일이 "데이터 대기 · 요약기를 임의 추가하지
  않는다" 고 명시한다. 데이터가 생긴 뒤에 만드는 것이 맞다.
- **출시 게이트 여덟을 건드리지 않았다.** 전부 사용자가 정할 값(지원 이메일·약관 버전·결제
  포털·사업자 정보·플랜 한도·App Check site key)이거나 production 설정 변경이다.
- **`check:review-copy` 를 러너에 걸지 않았다.** 브라우저를 띄우고 사본 폴더를 만드는
  주문형 도구라 상시 게이트로 둘 이유가 없다.
