## 변경 내용

모의고사를 **한글(HWP) 파일로 조판**할 수 있는지 확인하는 실험을
`experiments/hwp-export/` 에 격리해 만들었다. **제품 코드는 한 줄도 바꾸지 않았다**
(`index.html`·`mock-exam-editor.html`·`serve.py`·`worker/` 무변경, `git diff` 로 확인).
이 폴더를 통째로 지워도 제품은 그대로 돌아간다.

동기는 글꼴 라이선스다. 실물 시험지 파일을 조사한 결과 **글꼴이 파일에 포함돼 있지 않고
이름으로만 참조**된다(글꼴 스트림 자체가 없음). 따라서 우리가 낸 `.hwp` 도 글꼴을 담지
않고, 사용자가 자기 한글로 열면 자기 컴퓨터의 글꼴로 조판된다 — 우리가 글꼴을 배포하지
않으므로 `FONT-LICENSE.md` 의 문제가 구조적으로 사라진다.

- `hwpdoc.py` — 본문 스트림을 '문단' 단위로 분해·조립하는 최소 계층.
  jakal-hwpx 는 `replace_paragraph_text_same_length()` 처럼 **길이가 같은 교체**까지만
  지원해서(레코드 크기·글자수 필드를 다시 쓰지 않는다), 그 계층만 직접 만들었다.
- `selfcheck.py` — 한글 없이도 돌릴 수 있는 구조 검사 14종.
- `make_probe.py` — 아래 '남은 질문' 을 사람이 한 번 열어 보면 판정되도록 만든 실험 파일 생성기.
- `.gitignore` 에 `*.hwp`/`*.hwpx`/`experiments/hwp-export/out/` 추가.
  실물 시험지는 저작물이고, 생성물도 원본의 틀·그림을 그대로 품는다.
  기존에 `*.pdf` 를 막아 둔 것과 같은 이유이며, `.hwp` 는 빠져 있어 실수로 커밋될 수 있었다.

핵심 발견 — `PARA_HEADER` 는 12바이트가 아니라 **24바이트**이고 뒤쪽에 **직계 자식
레코드 개수**가 들어 있다(`b[12:14]`=글자모양 구간 수, `b[16:18]`=줄 수). '직계' 가
핵심으로, 표 안 문단의 레코드는 세지 않는다. 처음에 12바이트만 쓰도록 짰다가 실물 749문단
대조로 발견해 고쳤다. 이 개수를 갱신하지 않고 문단을 고치면 한글이 문단을 잘못 읽는다.

## 위험과 검토 요청

**이 방향의 성패를 가르는 질문에 아직 답하지 못했다: 한글이 문서를 열 때 줄 나눔을
다시 계산해 주는가?** `PARA_LINE_SEG` 는 조판 캐시라서 내용을 새로 쓰면 반드시 틀어지는데,
정확한 줄 나눔은 조판 엔진만 계산할 수 있다. 이 컴퓨터에 한글이 설치돼 있지 않아
기계적으로 확인할 수 없어, 사람이 열어 보면 판정되는 파일 2종을 냈다.
**이 답이 나오기 전에는 제품에 연결하지 말 것.**

`hwpdoc.py` 가 확인한 레코드 규칙은 실물 파일 1개(3구역·749문단) 관찰에서 나온 것이지
공식 규격서를 대조한 것이 아니다. 다른 과목·다른 연도 파일에서 깨질 수 있다.

표·수식·그림 삽입과 한 문단 안 서식 구간(굵게/밑줄) 경계는 손대지 않았다.

## 검증

- 실행한 명령 또는 수동 절차:
  - `python3 selfcheck.py` (실물 `평가원 국어 양식.hwp` 대상)
  - `python3 make_probe.py`
  - `npm run check:fast`, `git diff -- index.html mock-exam-editor.html serve.py worker/`
- 결과:
  - 자체 검사 **14 / 14 통과**. 분해→재조립이 3개 구역 전부 **바이트까지 동일**,
    원본 749문단이 불변식을 지킴, 길이가 다른 글로 교체해도 앞뒤 문단·개수 보존,
    본문을 통째로 새로 조판(492문단 → 12문단)해도 용지·단·머리말 틀(secd) 보존.
  - **검사가 실제로 실패하는 것도 확인했다** — 문단의 글자수 필드를 일부러 7 어긋나게
    바꾸자 `글자수 329 != 본문 322` 로 잡아냈다.
  - 실험 파일 2종 생성, 둘 다 불변식 위반 0건.
  - 제품 테스트 전부 통과, 제품 파일 diff 없음.
- 아직 실행하지 못한 검증과 이유:
  - **한글에서 실제로 열어 보는 확인.** 이 컴퓨터에 한컴오피스가 설치돼 있지 않다.
    사용자가 `out/probe-A-*.hwp`, `out/probe-B-*.hwp` 를 열어 판정해야 한다.
  - 인쇄 결과의 서체·자간 육안 대조 역시 한글이 필요하다.

## 다음 검토자에게

`experiments/hwp-export/README.md` 를 먼저 읽으면 배경·발견·미해결 질문이 정리돼 있다.
코드는 `hwpdoc.py` 의 `make_para_header()` 주석(24바이트 필드 배치)과 `selfcheck.py` 의
`para_problems()` 불변식부터 보면 된다. 실물 `.hwp` 는 커밋하지 않았으므로 검사는
자기 파일 경로를 인자로 넘겨 돌린다(`python3 selfcheck.py 경로.hwp`). 파일이 없으면
검사를 건너뛴다.

한글 확인 결과가 '다시 계산함' 이면 다음 단계는 표·수식 삽입과 모의고사 상태 → HWP
변환기다. '캐시를 믿음' 이면 이 접근 자체를 접고 Typst 경로에 남는다.
