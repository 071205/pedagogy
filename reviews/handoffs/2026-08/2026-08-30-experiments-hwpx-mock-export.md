## 변경 내용

`experiments/hwp-export/` 에서 **모의고사 편집기 JSON → 한글 시험지(HWPX)** 흐름을 끝까지
완성했다. **제품 코드는 여전히 한 줄도 바꾸지 않았다**(`index.html`·`mock-exam-editor.html`·
`serve.py`·`worker/` diff 없음, `npm run check:fast` 통과).

- `tex_to_hwp.py` — LaTeX → HWP 수식 스크립트 변환기. 대응표는 실물 시험지의 수식 522개에서
  유도했다. 모르는 명령은 **예외를 던진다**(조용히 버리면 시험지에 수식이 빠진 채 인쇄된다).
- `mock_to_hwpx.py` — 편집기가 내보내는 `.json` 을 그대로 받아 시험지를 만든다.
  편집기의 `probUnits()` 를 옮겨 유닛 순회를 맞췄다.
- `make_math_probe.py` / `make_e2e_probe.py` — 실물 규격(272×394mm, 2단, 단 간격 11.7mm)
  재현본과 LaTeX 끝-에서-끝 확인본.
- `samples/editor-seed.json` — 편집기에서 그대로 뽑은 예제 문항 6개. 손으로 지어내지 않았다.

한글에서 열어 확인한 결과: 문장 중간 수식이 한 줄로 이어지고, 별행 수식·선지 `①②③④⑤`·
배점·조건 `(가)(나)`·선분 윗줄이 모두 실물처럼 조판된다.

## 위험과 검토 요청

`mock_to_hwpx.py` 의 유닛 순회는 편집기 `probUnits()` 를 **손으로 옮긴 사본**이다.
편집기 쪽이 바뀌면 여기도 같이 고쳐야 하고, 어긋나면 화면과 시험지가 달라진다.
제품에 붙일 때는 `paintProblem()` + 팔레트 구조로 들어가는 것이 옳다.

수식 변환기는 **모의고사에 실제로 쓰이는 범위만** 다룬다. LaTeX 전체가 아니다.
`NOOP` 목록(조판 힌트 무시)에 뜻이 있는 명령을 넣으면 수식이 조용히 틀려지므로,
추가할 때는 '없어도 뜻이 같은가' 를 반드시 확인해야 한다.

그림·조건 상자 테두리·머리말은 아직 자리표시 수준이다(README 의 '아직 손대지 않은 것').

## 검증

- 실행한 명령 또는 수동 절차:
  - `python3 test_tex_to_hwp.py`, `python3 selfcheck.py`
  - `python3 mock_to_hwpx.py samples/editor-seed.json out/mock.hwpx`
  - 한컴오피스 한글 12.30 에서 결과 파일을 열어 화면으로 확인
  - `npm run check:fast`, 제품 파일 `git diff`
- 결과:
  - 수식 변환 검사 **20 / 20 통과**(4건은 실물 수식과 직접 대조), 구조 자체 검사 **14 / 14**.
  - 편집기 예제 6문항·수식 59개가 **경고 없이** 변환되고 한글에서 정상 조판됨.
  - `\left` 공백 수정을 되돌리면 검사가 실제로 빨간불이 되는 것을 확인했다.
  - 제품 테스트 통과, 제품 파일 diff 없음.
- 아직 실행하지 못한 검증과 이유:
  - 실제 인쇄물 대조. 상용 글꼴(`신명 중명조` 등)이 이 컴퓨터에 없어 화면 조판까지만 확인했다.
  - 30문항 전체·그림 포함 시험지. 예제 데이터에 그림 파일이 없다.
