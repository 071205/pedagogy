# 변경 인계 — 선지에 그림 넣기 (교과서 그래프 문항)

- ID: `HANDOFF-2026-045`
- 날짜: `2026-09-06`
- 작성자: `Claude`
- 상태: `ready-for-review`
- 영향 영역: `index.html`, `regression-test.html`, `scripts`, `test-fixtures`, `docs`
- 계기: 교과서 문제집(`pedagogy-textbook-set`) 작업 중 **그래프 이동 문항의 선지가 그림**
  이어야 하는 경우가 나왔다.

## 무엇을 했나

문제집 편집기(`index.html`)의 선지 블록이 **선지마다 그림**을 가질 수 있게 했다.
배치는 3+2 다.

## 근거가 없는 곳을 밝혀 둔다

⚠️ **실물 평가원 수학에는 그림 선지가 없다.** `2025학년도 수능 수학 문제.hwp` 를 읽어
확인했다 — 선지 문단 안의 개체 165개가 **전부 수식(`eqed`)** 이고, 문서 전체에도
`$pic` 은 없다(그래프는 본문의 `gso` 65개). 선지는 **한 줄 5개**가 실물이다.

그래서 이 기능의 배치·크기는 **실물에서 잰 값이 아니라 정한 값**이다. 이 저장소의
다른 조판 값들과 성격이 다르므로 문서와 CSS 주석에 그렇게 적어 두었다. 교과서 실물이
확보되면 다시 잴 것.

## 계약 — `items` 는 건드리지 않았다

`choices.data` = `{ items:string[5], images:string[5], layout }`.

⚠️ **`items` 를 `{text,img}` 객체 배열로 바꾸지 않았다.** `convertBlock`(조건↔보기↔선지)이
문자열을 옮겨 담고, `blockExcerpt`·`setHasContent` 도 문자열을 가정한다 — 대화문 `items`
가 객체라서 겪은 사고(문항 목록이 통째로 죽고, 내용 없음으로 오판해 병합에서 빠짐)와
같은 종류가 난다. 그래서 그림은 **같은 자리끼리 짝을 이루는 별도 배열**이다.
⚠️ 두 배열은 **늘 함께 움직인다.** 한쪽만 `splice` 하면 그림이 옆 선지로 옮겨간다 —
정규화에서 길이를 5로 못 박고, 편집기의 삭제 단추도 둘을 함께 지운다.

## 3+2 는 새 배치를 만들지 않았다

이미 있는 **`cols3` 이 그대로 3+2 다**(5개를 3열에 넣으면 3 + 2). `CHOICE_LAYOUTS` 를
늘리면 인쇄 넘침 보정·정규화·편집 단추까지 네 곳이 함께 늘어나는데, 얻는 것이 없다.

## 고친 곳

1. **계약** — `normBlock` 이 `images` 를 받고 **주소마다 `safeUrl()`** 을 태운다.
   못 믿을 주소는 버리고 `normDropped.images` 로 센다(그림 블록과 같은 처리).
   `blankBlockData` 도 빈 배열 다섯을 준다.
2. **그림 수명** — `blockImageUrls(blk)` 를 새로 두고 `releaseBlockImages()` 와 종류 변경
   경로가 **둘 다 그것을 쓴다.**
   ⚠️ 예전엔 정리 코드가 `image` 블록만 알고 있어서, 선지 그림을 넣었다면 지워도
   Storage 원본이 영영 남았을 것이다(CLAUDE.md 가 경고한 자리).
   종류를 바꿀 때는 **바뀐 뒤에도 쓰이는 주소는 빼고** 지운다.
3. **렌더** — 그림이 있는 선지에 `choice--img`, 블록에 `choices--img`. 라벨은 그림 위 줄.
   글과 그림을 함께 넣으면 그림 아래에 글이 붙는다.
4. **편집 UI** — 선지마다 그림 단추. 붙인 뒤에는 **썸네일**을 보여 준다(그래프 다섯을
   다룰 때 어느 자리에 무엇이 붙었는지 보여야 한다). 단추에 컬러 이모지를 쓰지 않고
   `.icon-image` SVG 를 새로 만들었다 — 이 저장소가 예전에 전부 걷어냈고 검사가 본다.
5. **`setHasContent`** — 그림만 있는 선지도 '내용 있음' 으로 센다.

## ⚠️ 화면을 봐야 보인 것 둘

- **라벨이 그림 옆에 붙었다.** `.choice--img{display:block}` 을 `.choice{display:flex}`
  **앞**에 두었더니 같은 점수(클래스 하나)라 나중 규칙이 이겼다. **마크업도 계산된
  스타일도 정상**이라 인쇄물을 보고서야 알았다. 그 CSS 는 반드시 `.choice` 뒤에 온다.
- **세로 배치에서 그림이 단을 통째로 먹었다.** 칸이 단 폭 전체라 그림 하나가 100% 를
  차지해 선지 다섯이 몇 쪽을 넘겼다. 3열 칸과 같은 몫(34%)으로 묶었다.
  ⚠️ **%로 묶어야** 미리보기와 인쇄가 같다 — mm 로 묶으면 화면(px)과 갈라진다.

## 배치를 언제 바꾸는가 — 편집기만, 한 번만

그림을 **처음 붙일 때** 배치가 5열이면 3열로 옮긴다(5열에 그림 다섯이면 한 칸이 20mm
남짓이라 그래프를 알아볼 수 없다).
⚠️ **`normBlock` 은 배치를 건드리지 않는다.** 저장된 값은 사용자의 결정이라, 정규화에서
바꾸면 일부러 5열을 고른 사람의 설정이 열 때마다 되돌려진다.

## 검증

- **인쇄·미리보기·편집 UI 셋을 다 그림으로 봤다.** 두 렌더가 같다.
- 경계도 그림으로 확인했다 — 글+그림 혼합(그림 아래 글) · 5열(좁지만 안 깨진다) ·
  세로(묶은 뒤 정상) · 일부 선지만 그림.
- 브라우저 회귀 **112/112**(새 검사 3건). 넷을 되돌려 빨간불 확인 —
  `safeUrl()` 제거 / CSS 를 `.choice` 앞으로 / 정리 코드가 선지를 모름 / 길이를 5로 안 박음.
- 시각 회귀 표본 `07-math-image-choices` 신설. **7건 통과** · `check:fast` 통과.
  다른 기준본은 건드리지 않았다.

## 남은 것 — 교과서 스킬은 아직 그림을 못 만든다

`pedagogy-textbook-set` 의 `scripts/build_set.py` 에 있는 `choices(items, layout)` 은
**그림을 받지 않고**, 그 스킬에는 그림 블록 빌더 자체가 없다. 편집기는 이제 받을 수
있으니 스킬 쪽에서 이렇게 내보내면 된다:

```python
def choices(items, layout="horizontal", images=None):
    arr = list(items)
    while len(arr) < 5: arr.append("")
    imgs = list(images or [])
    while len(imgs) < 5: imgs.append("")      # items 와 길이가 같아야 한다
    return {"type": "choices",
            "data": {"items": arr[:5], "images": imgs[:5], "layout": layout}}
```

그림은 `data:image/png;base64,…` 로 넣는다(편집기의 `safeUrl()` 이 Storage 주소와
`data:image` 만 받는다). **그림이 있으면 `layout="cols3"` 로 보낼 것** — 정규화는 배치를
건드리지 않으므로, 5열로 보내면 5열로 조판된다.

⚠️ 그 스킬 파일은 이 저장소 밖(플러그인 세션 폴더)에 있어 **고치지 않았다** — 세션마다
다시 풀리는 사본이라 여기서 고치면 사라진다. 스킬 원본에서 고쳐야 한다.
