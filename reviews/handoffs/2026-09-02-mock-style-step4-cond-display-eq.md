## 무엇을 했나

조건 상자(`conditions`) 안에서 **한 줄이 통째로 `$…$` 이면 별행(디스플레이) 수식**으로
조판한다. 발문(`statement`)이 이미 쓰던 규칙을 상자 안으로 넓힌 것이고, 세 경로
(화면 미리보기 · Typst 정본 · 한글 HWPX)가 함께 움직인다.

```
(가) 모든 자연수 $n$에 대하여
$a_{n+1}=\dfrac{1}{2}a_n+\sum_{k=1}^{n}k$     ← 이 줄
이다.
```

| 경로 | 전 | 후 |
|---|---|---|
| 화면 미리보기 | 인라인 크기(∑ 첨자가 옆에) | 디스플레이 크기 · 상자 왼쪽 끝 |
| Typst 정본 | `#mi(…)` 인라인 | `#condeq[#mitex(…)]` — 디스플레이 · 왼쪽 |
| 한글 HWPX | `21 박스(테두리)` 문단에 인라인 | `21 박스(테두리) 별행` 문단 |

## 설계에서 달라진 것 — **새 유닛으로 만들지 않았다**

설계(§4.1)는 `condeq` 를 새 유닛 종류로 두자고 했다. 그렇게 하면 **상자가 쪼개진다**
(`cond` 유닛 하나가 상자 하나라, 수식 줄을 따로 내면 상자가 셋이 된다).
대신 `cond` 유닛 안에서 줄마다 종류를 표시한다:

```js
{ k:'cond', items:['(가) …','$…$','이다.'], kinds:['text','eq','text'] }
```

⚠️ **`items` 는 문자열 배열 그대로 뒀다.** 원소를 객체로 바꾸면 블록 내용을 훑는 곳이
조용히 터진다 — 본체의 `dialogue` 에서 이미 겪은 방식이다(CLAUDE.md). `kinds` 를 모르는
코드는 지금까지와 똑같이 동작한다.

## 실물에서 확인한 것 (추측 아님)

`평가원 수학 양식.hwpx` 22번 조건 (가)를 뜯어 봤다.

1. **실물은 `<hp:lineBreak/>` 로 한 문단 안에서 줄을 나눈다.** 우리는 편집기의
   `items[]` 가 줄 단위라 **문단 셋**으로 낸다. 한글에게 좌표를 물어 차이를 쟀다 —
   **문단 하나 늘 때마다 약 1.4mm**(우리 8.2·18.5mm vs 실물 6.7·17.1mm), 이 상자는
   실물보다 2.9mm 높다.
   **합치지 않은 이유**: 어느 줄이 한 조건에 속하는지 우리 모델은 모른다. 라벨
   (`(가)`)로 짐작해 묶으면 라벨 없는 조건에서 틀린다 — 설계 원칙 3.
2. **`21 박스(테두리) 별행`(pPr 17)은 `21 박스(테두리)`(18)와 자리가 같다.**
   표의 들여쓰기 −16.5mm 는 실제 적용되는 `HwpUnitChar` 분기(−8.26mm)와 왼쪽 여백
   (8.0mm)이 상쇄돼 0 이다. 한글이 쓴 `linesegarray` 로 확인: **두 스타일 모두
   x=8.0mm · 폭 99.2mm**. 다른 것은 탭 정지점(24·48mm)뿐이다.
   → 그래서 이 단계의 눈에 보이는 성과는 HWPX 가 아니라 **미리보기·Typst 의 수식
     크기**다. 우리가 만든 파일의 그 줄 높이는 **14.4mm 로 실물과 같다.**
3. **상자 안 별행 수식에는 탭이 없다**(실물 22번 (가) 확인) → 우리도 넣지 않는다.

⚠️ **곁가지로 찾은 것 — 발문의 별행 수식에는 탭이 빠져 있다(고치지 않았다).**
실물은 `21 문제다음 별행` 문단마다 폭 2850(10.05mm) 탭 **하나**로 수식을 14.1mm 에서
시작시킨다(9개 전부). 우리 `emit_display_eq()` 는 탭 없이 4.1mm 에서 시작한다.
**상자 안은 반대로 탭이 없는 것이 맞아** 이번 범위에서 뺐다. 발문 쪽만 따로 볼 것.

## Typst 에서 걸린 함정

**`#align(left)` 로는 별행 수식을 왼쪽에 붙일 수 없다.** Typst 의 블록 수식은 스스로
가운데로 간다 — `#align(left)[…]` · `#align(left, …)` · `#block(width:100%)[…]` ·
`#set align(left)` 넷 다 가운데로 나왔다(실제로 렌더해서 확인). `show` 규칙이라야 한다:

```typst
#let condeq(body) = { show math.equation: set align(left); body }
```

`#box(…)` 로 싸도 왼쪽에 붙지만 그러면 줄바꿈을 잃는다.

## 검토 요청

- `kinds` 를 `items` 밖에 둔 선택이 맞는지(객체 배열로 바꾸는 쪽이 나은지).
- 문단을 합치지 않아 생기는 **줄당 1.4mm** 를 받아들일지, 아니면 라벨로 묶는 규칙을
  넣을지. 지금은 '모르는 것은 넣지 않는다' 로 두었다.
- 발문 별행 수식의 빠진 탭(14.1mm)을 별도 이슈로 열지.
