## 변경 내용

Codex 의 `HANDOFF-2026-013`(그림 경로 제한)을 독립 검토했다. **두 이슈 모두 재현했고,
수정도 실제로 동작한다.** `../`·절대 경로·심볼릭 링크로 허용 폴더를 벗어나는 경우가 전부
막히고, `work/` 안 그림은 정상적으로 들어간다. Codex 의 검사에서 경로 검사를 일부러 빼자
빨간불이 되는 것도 확인했다.

그 위에 세 가지를 보탰다.

1. **검사를 실행 경로에 연결했다** — `scripts/check-hwpx.mjs`, `npm run test:hwpx`,
   `check:fast` 에 포함. `experiments/hwp-export/` 의 파이썬 검사 4개가 그동안 **어떤
   실행 경로에도 걸려 있지 않았다.** 변환기는 편집기의 `probUnits`·`buildPages`·`layoutOf`
   를 옮겨 적은 사본이라, 편집기 규칙이 바뀌어도 아무도 모르는 상태였다.
   의존성(`jakal-hwpx`)은 제품 의존성이 아니므로 없는 환경에서는 **건너뛴다고 출력하고
   통과**한다 — 건너뜀과 통과를 출력에서 구분해, '도는 줄 알았는데 안 돌던' 상태를 막는다.
2. **정적 문자열 검사를 동작 검사로 바꿨다** — `test_endpoint.py` 가 서버를 실제로 띄워
   응답을 본다. `check-static.mjs` 의 `images=[WORK]` 문자열 검사는 서식만 바꿔도 깨지고
   글자가 있어도 동작을 보장하지 못한다(그 검사 자체는 남겨 두었다).
3. **심볼릭 링크·하위 폴더 사례**를 경로 검사에 추가했다. 이름만으로는 링크와 폴더 안
   파일을 구분할 수 없어, `resolve()` 를 빼면 뚫린다(빼고 확인함).

`work/` 를 `.gitignore` 에 넣었다. typst 임시 폴더와 사용자가 넣어 둔 문항 그림이 쌓이는
곳인데 커밋 후보로 올라오고 있었다.

## 위험과 검토 요청

`test_endpoint.py` 는 **서버를 실제로 띄운다**(빈 포트를 잡아 `serve.py` 를 자식 프로세스로
실행). 검사 중 `work/` 와 저장소 루트에 임시 PNG 를 만들었다가 `finally` 에서 **우리가 만든
것만** 지운다. 이미 있던 같은 이름의 파일은 건드리지 않는다. 이 정리 경로를 함께 봐 달라.

`check:fast` 가 이제 파이썬을 부른다. CI 에서 의존성이 없으면 건너뛰므로 실패하지 않지만,
그만큼 **CI 에서는 이 검사가 돌지 않는다**. 실제로 돌리려면 CI 에 그 의존성 설치를 넣어야 한다.

## 검증

- 실행한 명령 또는 수동 절차:
  - Codex 이슈 2건을 직접 재현(007 은 이미 수정돼 재현 안 됨, 008 은 기본 루트에서 재현)
  - `find_image` 를 8가지 경로(정상·하위·상위탈출·절대·심볼릭·`./`·없는파일·빈문자열)로 확인
  - `curl` 과 브라우저로 `/hwpx` 호출, `test_endpoint.py`
  - 의존성 있는/없는 파이썬 양쪽으로 `npm run test:hwpx`
  - `npm run check:fast`
- 결과:
  - 경로 8건 전부 의도대로. `work/` 그림은 들어가고 밖 그림은 경고와 함께 빠진다.
  - `npm run test:hwpx` — 검사 5개 통과. 의존성 없는 파이썬에서는 건너뛰고 통과.
  - **일부러 깨뜨려 확인**: `serve.py` 의 `images=[WORK]` 를 빼면 엔드포인트 검사 2건 실패,
    `find_image` 의 `relative_to` 를 빼면 경로 검사 실패, `resolve()` 를 빼면 심볼릭 링크
    검사 실패. 셋 다 원복 후 통과.
  - `check:fast` 통과.
- 아직 실행하지 못한 검증과 이유:
  - CI 에서의 실제 동작. 이 컴퓨터에서만 확인했고, CI 에는 `jakal-hwpx` 가 없어 건너뛴다.
  - 실물 인쇄 대조(신명 계열 글꼴이 이 컴퓨터에 없다).
