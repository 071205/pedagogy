## 변경 내용

같은 문제집의 두 번째 보기 **'지면 배치'** 를 넣었다. PDF 를 뽑지 않고 전체 지면을 보고, 문항을 골라 배치를 바꾼다.

- `buildPrintDoc(hideAnswers, wrap=$("#printDoc"))` · `fitPrintDoc(wrap=$("#printDoc"))` — 그릇만 인자로 받는다.
  기본값이 그대로라 **인쇄 경로는 바뀌지 않았다.** 인쇄 문항에 `data-qid` 를 심고, 잘림 결과에 `qids` 를 더했다.
- 지면 보기: `#sheetBuild`(화면 밖, `#printDoc.measuring` 과 같은 조건)에서 조립 → 글꼴 → 그림 → 보정 → `#sheetStage` 로 노드 이동.
  화면 맞춤은 그 뒤 바깥 틀 `transform` 으로만. '맞춤 ↔ 100%'.
- 낡음: 내용 지문이 다르면 즉시 '반영 대기/중' 상태와 덮개. 세대 번호로 늦은 조립을 버린다. 선택만 바뀌면 다시 조립하지 않는다.
- 확인할 문항 N개: 잘림(인쇄 경고와 같은 판정) · 문항 축소 · 수식/표/선지 일부 축소 · 못 받은 그림. 누르면 그 문항 선택.
- 오른쪽 '선택한 문항': 사유, 배치 셋(묶기/한 단/한 쪽 + 작은 예시), '이 문항 편집하기'. 배치 변경은 `historyStep` 으로 ⌘Z 한 번.
- 위치: 넓은 화면은 문항 목록 칸 위 '문항 편집 / 지면 배치', 좁은 화면은 탭 '지면'. 쪽 이동은 이전/다음 + 쪽 목록.
  문항은 Tab·Enter/Space 로 고른다. 정답 표시 토글(기본 끔). 인쇄 매체에서는 이 칸과 조립 그릇이 숨는다.

## 하지 않은 것 (U1 남은 범위)

라이브러리 시작 두 경로·전역/문제집/문항 조작 정리, 쪽 축소판(지금은 쪽 목록), 글꼴 준비 실패 표시(감지 못 함).
별도 조판기·WYSIWYG·새 mm 여백·N제 HWPX 는 지시대로 넣지 않았다. 기본 보기는 기존대로 문항 편집이다.

## 검증

- 새 검사 `npm run test:sheet`(`scripts/check-sheet-view.mjs`, `check:fast` 에 연결) — 실제 크로미움, 외부 요청 차단.
  ① 지면 = 인쇄 조립(쪽·칸·문항·보정 배율 서명이 같다) ② 잘림 → 확인할 문항 → 선택·사유 ③ 한 쪽 배치 → 다시 그림 → ⌘Z 한 번
  ④ 지면→편집→지면 같은 문항·화면 안 ⑤ 바뀐 직후 낡음 표시·반영 뒤 최신 ⑥ 목록에서 선택만 바꾸면 다시 조립 안 함
  ⑦ 키보드 선택 · 인쇄 매체 숨김 · 768/375 탭 전환·가로 넘침 없음. **깨보기 5종**(보정 건너뛰기·qid 제거·낡음 표시 제거·
  선택 때 재조립·좁은 화면 탭 훅 제거)이 각각 대응 항목을 빨간불로 만든다(결과는 아래 '검증 결과').
- 300문항(150쪽) 지면 첫 조립: 로컬 크로미움 약 1.9초(정보 출력, 상한 20초).
- `test:public`(CSP 해시) · `check:static` · `check:review-hygiene` 통과.
- 눈으로: 1440 밝게/어둡게 · 768 · 375 스크린숏 확인(종이는 어두운 테마에서도 흰색).

## 검토 요청 (Codex GPT-6 Sol medium)

1. 지면이 인쇄와 갈라질 수 있는 경로 — 화면 밖 측정 → 노드 이동, `.sheet-stage` 의 잘림 조건, 화면 맞춤 transform.
2. 낡음/세대 처리의 반례(조립 중 계정 전환·문제집 전환·편집 모드로 나감·인쇄 동시 실행).
3. `renderPreview`·`saveSets`·`setActivePane` 에 건 훅이 편집 모드 성능·동작을 바꾸지 않는지.
4. 접근성(선택 표시가 색만이 아닌지, 포커스 순서), 터치(44px 규칙은 `#appMain button` 으로 이미 걸림).

## 검토 기록

### 2026-10-03 — Codex GPT-6 Sol medium 1차

- 결함 주장: 그림 대기 중 내용이 바뀌면 다음 조립 예약(220ms) 전에 옛 조립이 끝나 옛 지면을 `ok` 로 게시한다.
  **Claude 확인: 화면에 보이는 '거짓 ok' 는 재현되지 않았다** — 옛 조립은 `ok` 를 쓴 같은 동기 구간에서 키를 다시 보고
  곧바로 '반영 대기' 로 바꾼다(예약을 5초로 늘려 경합을 강제해도 5ms 표본에 한 번도 안 잡혔다). **실제로 일어난 것은
  옛 조립 결과가 덮개 밑에 한 번 더 올라가는 헛일**이었다 → 예약 시점에 진행 중 조립을 무효화하도록 고쳤다
  (`sheetBuildingKey` · 같은 내용이면 무효화하지 않음). 검사 ⑤-b 가 '바뀐 뒤 지면 교체 1회' 를 본다.
- 검사 지적 둘 다 반영: ① 에 문항별 실제 크기·내용 해시를 더했다(그 과정에서 인쇄 쪽 크기를 `measuring` 을 뗀 뒤 읽어
  전부 0 이던 검사 자체의 결함도 고쳤다). ⑤-b(그림 대기 경합) · ⑤-c(조립 중 편집으로 나감) 추가. 깨보기 7종 전부 빨간불.

### 2026-10-03 — Codex GPT-6 Sol medium 2차

- 동의: 화면에 보이는 거짓 `ok` 는 없다. 예약 시 무효화는 옛 조립을 지면에 다시 올리는 헛일을 막는다. ⑤-b 가 그 효과를 확인한다.
- 지적 1건(검사): ⑤-c 가 10ms 만에 나가 조립이 시작되기 전이라 헛돌 수 있다 → **반영**. 검사가 붙잡힌 그림으로 조립이 실제로
  '그림 확인' 에 머무는 것을 확인한 뒤 나가고, 그림을 놓아 늦은 결과가 안 올라가는지 본다. 깨보기 '보기에서 나가도 늦은 결과를 올린다'
  (`live()` 에서 `sheetVisible()` 제거)가 ⑤-c 를 빨간불로 만든다.
