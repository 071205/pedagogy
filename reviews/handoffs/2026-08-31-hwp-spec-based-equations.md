# 변경 인계 — 한컴 공개 규격서 확보, 수식 변환기를 추측에서 규격 기반으로

- 작성자: `Claude`
- 상태: `ready-for-review`
- 영향 영역: `server`, `tests`, `docs`

## 배경

"자칼(jakal-hwpx)을 베끼지 말고 처음부터 우리 것으로 만들자"는 방향에서 출발했다.
그런데 **베낄 필요도, 추측할 필요도 없었다 — 규격이 공개돼 있다.**

- HWPX(OWPML) 문서 구조는 **KS X 6101:2011 국가표준**이다. 한컴 독자 포맷이 아니다.
- 한컴이 **수식·차트·배포용 문서** 규격서를 무료로 배포한다.

받는 곳과 우리가 쓰는 범위는 [`docs/HWP-SPEC.md`](../../docs/HWP-SPEC.md)에 정리했다.

## 변경 내용

수식 규격서(revision 1.3, 33쪽)를 받아 `tex_to_hwp.py` 와 대조했다. **추측으로 만든 것이
실제로 틀린 곳이 네 군데 있었다.**

| 규격서 절 | 고치기 전 | 고친 뒤 |
|---|---|---|
| 1.2 | `\begin{vmatrix}` → `vmatrix{...}` | 한글에 **`vmatrix` 명령이 없다.** 세로줄 행렬은 `dmatrix` |
| 1.1.2.3 | 긴 낱말을 그대로 냄 | **9자를 넘는 낱말은 `" "` 로 묶는다** (안 묶으면 한글이 두 항으로 쪼갠다) |
| 1.2.1 | 글자 장식 6개 | acute·grave·check·arch·under 추가 |
| 1.2.4 | 그리스 문자 일부 | 대문자(GAMMA 등)·var 계열·oint·partial·nabla 등 추가 |

⚠️ **9자 규칙이 가장 위험한 종류다.** 변환은 성공하고 경고도 안 뜨는데 한글에서 조판된
모양만 달라진다. 표본 시험지 수식 214개에는 걸리는 것이 없어(수학 기호는 짧다) 그동안
드러나지 않았다. `\mathrm{Probability}` 같은 긴 낱말에서 터진다.

### 배포 조건을 소스에 기재했다

수식 규격서의 저작권 조항은 참고해 만든 결과물에
**"본 제품은 한글과컴퓨터의 한글 문서 파일(.hwp) 공개 문서를 참고하여 개발하였습니다."**
를 유저인터페이스·매뉴얼·도움말·소스에 **모두** 기재하도록 요구한다.
`tex_to_hwp.py` 첫 주석에 넣었다. **제품으로 낼 때 화면과 매뉴얼에도 넣어야 한다**
(`docs/HWP-SPEC.md` 에 미완으로 적어 뒀다).

같은 조항이 "결과물의 모든 저작권은 개발한 개인 또는 단체에 있다"고 명시한다 —
**우리 코드는 우리 것이다.** 이것이 "안심하고 쓴다"의 근거다.

### 규격서 PDF 는 저장소에 넣지 않았다

저작권 조항이 배포본은 "한컴에서 제공하는 스펙의 **최신 버전**을 포함하고 있어야 한다"고
요구한다. 낡은 사본을 저장소에 두면 오히려 그 조건에서 벗어난다. 주소만 기록했다.

## 실물 확인 완료 (2026-09-01)

`scripts/check-hwpx-opens.mjs` 로 열리는 것을 확인하고, 한글 화면에서 눈으로 대조했다.
**규격서를 보고 고친 것이 전부 실물에서 맞았다.**

| 항목 | 화면에서 확인한 것 |
|---|---|
| `vmatrix` → `dmatrix` | 양옆에 **세로줄**이 그려진다(행렬식) ✅ |
| 9자 규칙 | `Probability=0.5` 가 **한 낱말로 붙어** 나온다(쪼개지지 않음) ✅ |
| 글자 장식 | acute·grave·check·arch·under 다섯 개 모두 제 모양 ✅ |
| 새 기호 | ∮(oint)·Γ(GAMMA)·ε(varepsilon)·∂(partial)·∇(nabla) ✅ |
| 회귀 | 기존 시그마 합·분수 수식 그대로 ✅ |

`이차함수-학습정리.hwpx`(제목·소제목·인라인 수식·별행 수식·표·목록·인용문)도 다시 열어
정상 확인했다.

## 위험과 검토 요청

- **9자 규칙의 적용 지점.** 사용자 낱말에만 적용하고 명령 이름(`varepsilon` 은 10자다)은
  건드리면 안 된다. 지금은 원문에서 `[A-Za-z0-9]+` 런을 잡을 때만 적용하고, `SIMPLE`/
  `ACCENT` 로 나가는 명령 이름은 그 경로를 타지 않는다. 검사에 경계값(9자/10자)과
  "명령 이름은 안 묶인다"를 넣었지만 한 번 더 봐 달라.
- ~~`vmatrix` → `dmatrix` 실물 미확인~~ → **확인 완료**(위 표).
- ~~새 기호들의 한글 쪽 이름 미확인~~ → **확인 완료**(위 표).

## 이어서 — 실물 한글 열기 검사 (`scripts/check-hwpx-opens.mjs`)

규격서로도 "한글이 이 파일을 열어 주는가"는 알 수 없다. 그래서 실제로 열어 보는 검사를
만들었다. `npm run test:hwpx-opens -- 파일.hwpx`.

한컴 한글은 **AppleScript 사전도 CLI 도 제공하지 않는다**(확인함). 그래서 파일을 연 뒤
System Events 로 **창이 생겼는지**를 읽어 판정한다. 손쉬운 사용 권한이 필요하고,
없으면 건너뛴다(종료코드 2, 러너가 `⏭` 로 구분해 찍는다). CI 에는 걸 수 없다.

**동작을 확인했다**: 정상 파일 ✅ / 고의로 깨뜨린 파일(`styles itemCnt` 불일치) ❌ 로
정확히 갈렸다.

⚠️ **만들면서 한글을 망가뜨렸다.** 처음에는 판정 사이에 앱을 껐다 켰는데, 종료가 끝나기
전에 다음 파일을 열게 되고 몇 번 반복하니 **한글이 창을 아예 못 띄우는 상태**가 됐다.
그 뒤로는 멀쩡한 파일까지 전부 ❌ 로 나왔다(`kill -9` 로 되살리려다 더 나빠졌다).
지금은 앱을 한 번만 띄우고 문서만 닫는다. 전부 실패면 파일이 아니라 한글을 의심하라고
스크립트가 안내한다. 한글 파일 이름의 자모 분해(NFD) 문제도 함께 고쳤다.

## 검증 계층 재설계

실물 열기 검사를 만들면서 **기존 참조 검증이 틀렸다는 것도 드러났다.**

- `REV-2026-012` 에서 "참조표(`fontfaces`·`borderFills`·`tabProperties`)가 없어서 안 열린다"
  고 진단했는데 **틀렸다.** 자칼이 만든 파일은 그 셋이 전부 없어도 한글이 연다(확인함).
  그 검사는 **정상 문서를 거부하는 버그**였다.
- **진짜 원인은 `itemCnt` 와 실제 개수의 불일치였다.** `<styles itemCnt="1"/>` 라고
  선언해 놓고 안이 비어 있었고, 본문은 `styleIDRef="0"` 으로 그 없는 스타일을 가리켰다.

그래서 셋으로 나눴다:
- `item_count_errors()` — 선언과 내용 불일치. **오류**(저장 차단). 오늘의 진짜 원인.
- `reference_validation_errors()` — 존재하는 표 안에서 없는 id 를 가리킴. **오류**.
- `reference_warnings()` — 표가 통째로 없음. **경고만**(한글이 실제로 받아 준다).

## KS X 6101 확보와 그 결과 (2026-09-01)

**국가표준 원문을 확보했다.** e-나라표준인증의 '기계가독 원문' 이 무료다
(`docs/HWP-SPEC.md` 에 받는 명령을 적어 뒀다). 14.7MB · 521개 절 · 최종개정 2024-10-30.
⚠️ **저장소에 넣지 않았다** — 한컴 공개 문서와 달리 KS 표준은 재배포를 허락하지 않는다.

### 규격으로 잡은 것

**9.3.2.1 — `itemCnt` 는 positiveInteger(1 이상)** 다. 즉 **빈 표(`itemCnt="0"`)는 규격
위반**이다. `REV-2026-012` 에서 참조표를 채우며 "안 쓰지만 자리는 있어야겠지" 하고
`numberings itemCnt="0"` 을 넣었는데 그게 규격 위반이었다 — 두 번째 실패의 유력한 원인이다.
`item_count_errors()` 가 이제 규격 조항과 함께 잡는다.

`refList` 하위 요소 전체 목록도 규격으로 확정했다(우리가 모르던 `bullets`·
`memoProperties`·`trackChanges` 가 더 있다).

### 실험: 골격을 코드로 만들 수 있는가 → **아니다**

규격을 전부 지켜 코드로 골격을 만들었으나 **한글이 열지 못했다.** `fontfaces` 제거 /
`type="HFT"` / 자칼과 같은 최소 헤더 — 세 변형 모두 실패. 원인은 `refList` 안이 아니라
그 밖이다. 자세한 것과 다시 시도할 때 볼 곳은 `docs/HWP-SPEC.md` 참고.

**결론: 골격은 계속 실물 파일에서 가져온다.**

### 자동 열기 검사의 거짓 통과를 고쳤다

이 실험 중에 `check-hwpx-opens.mjs` 가 **거부당한 파일을 ✅ 로 보고**했다. 창 개수가
늘었는지로 판정했는데 **오류 대화상자도 창으로 세어졌기 때문**이다. 거짓 통과는 검사가
없는 것보다 나쁘다. 이제 대화상자의 글("파일을 읽거나 저장하는데 …")을 직접 읽어 판정한다.

대화상자 닫기도 `keystroke return` 이 안 먹어 오류가 쌓였고, 그 뒤 파일이 전부 거짓
실패로 나왔다. 버튼을 직접 클릭하도록 고치고, **닫지 못하면 남은 파일을 판정하지 않고
멈춘다**(거짓 결과보다 낫다).

⚠️ **한글을 `quit` 시킨 뒤 다시 띄우면 파일을 못 여는 상태가 된다**(여러 번 재현). 검사는
한글을 끄지 않는다. 검사 전에 한글이 정상인지(빈 문서가 열리는지) 먼저 볼 것.
