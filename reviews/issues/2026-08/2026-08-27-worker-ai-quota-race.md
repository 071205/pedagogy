# 동시 요청으로 AI 일일 한도를 넘길 수 있음

- ID: `REV-2026-002`
- 날짜: `2026-08-27`
- 보고자: `Codex`
- 상태: `resolved`
- 심각도: `P1`
- 영향 영역: `worker`
- 관련 인계: `HANDOFF-2026-001`

## 요약과 영향

AI 호출 한도는 Cloudflare KV의 읽기와 쓰기를 별도 단계로 처리한다. 같은 사용자가 병렬로
요청하면 모두 같은 이전 카운터를 읽어 한도 검사를 통과하고 AI 공급자 호출을 시작할 수 있다.
결국 실제 AI 호출 수는 한도를 넘지만 KV에는 더 작은 값만 기록되어 비용 보호 장치가 우회된다.

## 재현 절차

1. 일일 한도를 `1`, 해당 사용자의 KV 값을 `0`으로 둔다.
2. 같은 Firebase ID 토큰으로 POST 요청 두 개를 동시에 보낸다.
3. 두 요청 모두 `checkQuota()`에서 `0 < 1`을 읽고 AI 호출 단계로 진행한다.
4. 두 `consumeQuota()`도 이전값 `0`을 읽어 각각 `1`을 기록한다.

## 기대 결과 / 실제 결과

- 기대: 한도가 1이면 동시에 요청해도 최대 한 건만 AI 호출을 시작한다.
- 실제: 무해한 메모리 KV로 현재 읽기→확인→읽기→쓰기 순서를 동시에 실행한 결과,
  요청 두 건이 모두 `accepted`이고 최종 저장 카운터는 `1`이었다.

## 근거

- `worker/index.js:68-71` — 코드 주석도 KV가 원자적이지 않아 병렬 요청이 상한을 넘는다고
  명시한다.
- `worker/index.js:78-92` — `checkQuota()`와 `consumeQuota()`이 서로 분리된 `get()`/`put()`
  연산이다.
- AI 호출은 `checkQuota()` 뒤, `consumeQuota()` 전에 실행된다.

## 제안 (선택)

사용자·날짜별 Durable Object처럼 요청을 직렬화하는 저장소에서 먼저 원자적으로 예약한다.
공급자 실패 때만 같은 예약 ID를 해제하거나 만료시키면, 성공 호출만 비용으로 세려는 요구와
한도 우회를 함께 처리할 수 있다. 단순 KV 비교·증가만으로는 해결되지 않는다.
