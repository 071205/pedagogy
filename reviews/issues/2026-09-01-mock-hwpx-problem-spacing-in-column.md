# 한 단 안의 문항이 실물처럼 벌어지지 않는다

- ID: `REV-2026-016`
- 날짜: `2026-09-01`
- 보고자: `해리` (사용자 · 실물 한글에서 눈으로 발견)
- 상태: `fixed`
- 심각도: `P2`
- 영향 영역: `server`, `index`
- 관련 인계: `HANDOFF-2026-027`, `HANDOFF-2026-030`

## 요약과 영향

"2번 문제가 1번과 떨어져 있어야 한다."

한 단에 문항 둘이 들어갈 때, 우리 출력은 **빈 문단 하나**만 두고 둘을 위쪽에 붙여 놓는다.
단 아래쪽이 통째로 비고 문항 둘이 서로 붙어 보인다. 실물은 그렇지 않다.

내용이 사라지지는 않는다 — 순서도 번호도 맞다. **보기가 나쁘다.**

## 실물은 어떻게 하는가 (재어 본 값)

`평가원 수학 양식.hwpx` 의 `linesegarray`(한글이 저장한 실제 줄 정보)로 단마다 줄 수와
각 문항이 시작하는 줄을 셌다.

| 단 | 단 전체 줄 수 | 문항이 시작하는 줄 |
|---|---|---|
| 0 | 21 | 1번 → 0줄 · 2번 → **18줄** |
| 1 | 21 | 3번 → 0줄 · 4번 → **17줄** |
| 2 | 23 | 5번 → 0줄 · 6번 → **21줄** |
| 4 | 23 | 8번 → 0줄 · 9번 → **19줄** |
| 11 | 25 | 16번 → 1줄 · 17번 → **23줄** |
| 12 | 23 | 18번 → 0줄 · 19번 → **19줄** |

⚠️ **이 표를 처음에 잘못 읽었다.** '둘째 문항이 단 맨 아래에 붙는다' 고 봤는데, 줄 수를
세는 방법이 틀렸다 — `linesegarray` 가 없는 문단을 1줄로 세어 단 전체를 21줄로 봤다.
본문은 11.5pt · 줄간격 165% 라 한 줄이 **6.694mm** 이고, 단 295.43mm 는 **44줄**이다.
그러면 2번이 시작하는 18줄째는 44줄의 41% — **단의 절반쯤**이다.

즉 실물은 **단을 균등하게 나눠 각 문항을 자기 칸 맨 위에 둔다.** 편집기도 똑같다:

```
CSS   : .slots{grid-template-rows:repeat(n,1fr)}  +  .slot{align-self:start}
Typst : rows: (1fr,) * n        // "단: 높이를 균등 분할해 각 문항을 자기 칸 상단에 고정"
```

## 무엇이 막고 있었나

빈 문단을 **몇 개** 넣을지는 앞 문항이 **몇 줄을 차지하는지** 알아야 정해진다. 그런데
그 값을 아는 쪽이 지금 아무도 없다.

- 파이썬 변환기는 글꼴 실측을 못 한다. `_text_mm`/`_math_mm` 은 선지 배치용 어림이고,
  줄 수 추정에 쓰면 오차가 쌓인다.
- 편집기의 `buildPages()` 도 **높이를 재지 않는다.** `perCol` 개씩 단으로, 두 단씩 쪽으로
  나눌 뿐이고, 단 안의 분배는 CSS 그리드가 한다.

⚠️ **어림으로 넣으면 지금보다 나쁠 수 있다.** 빈 문단을 하나라도 많이 넣으면 둘째 문항이
다음 단으로 밀려 **배치 전체가 어긋난다.** 모자라면 지금처럼 조금 붙어 보일 뿐이다.
'모양이 틀린 것을 넣으면 없는 것보다 나쁘다' 는 이 저장소의 기준을 그대로 적용했다.

## 수정

선지 배치에서 이미 쓴 방식을 그대로 썼다 — **편집기가 재서 보낸다.**

- 편집기 `measureProblemHeights()` 가 문항마다 렌더 높이(mm)를 재어 `hwpxPayload()` 가
  `heightMm` 으로 싣는다. 미리보기 모드와 무관하게 **화면 밖에 따로 그려** 재므로
  '이 문항' 모드에서도 된다(30문항에 26ms, 화면은 건드리지 않는다).
  ⚠️ `.slots` 의 균등 분할(`1fr`)을 꺼야 한다. 켜 두면 칸 높이가 나오지 문항 높이가
  나오지 않는다.
- 변환기 `pad_lines()` 가 `칸 높이 − 문항 높이` 를 빈 문단 수로 바꾼다. 단 높이는
  편집기 Typst 정본과 같은 값(`COL_H_FIRST_MM` 295.43 · `COL_H_NEXT_MM` 319.90)이고,
  한 줄 높이는 **틀에서 읽는다**(`template.read_body_line_mm()` — 박아 두면 틀을 바꿀 때
  어긋난다).
- ⚠️ **높이가 없으면 벌리지 않는다.** CLI·손으로 쓴 JSON 은 그대로 예전처럼 동작한다.
  어림으로 넣으면 하나만 많아도 다음 단으로 밀려 배치가 통째로 어긋난다.
- ⚠️ **내림으로 자르고, `emit_problem()` 이 늘 붙이는 빈 문단 한 줄을 뺀다.** 올림하거나
  그 한 줄을 잊으면 칸을 넘긴다.
- ⚠️ **단의 마지막 문항 뒤는 벌리지 않는다.** 벌리면 그 단이 넘쳐 다음 단으로 밀린다.

## 검증

`test_page_layout.py` 에 '문항 간격' 검사를 더했다(`npm run test:hwpx` 에 걸려 있다).

- 높이를 주면 벌어진다 · 높이가 없으면 안 벌어진다 · 단이 바뀌는 자리는 안 벌린다
- 벌린 양이 `칸 − 문항` 과 같다 · 벌려도 칸을 넘기지 않는다(147.2mm ≤ 147.7mm)
- 문항이 칸보다 크면 벌리지 않는다
- **일부러 되돌려 빨간불 확인**(`pad_lines` 를 0 으로) — 그것도 검사 안에 넣었다

실물 표본으로 만든 시험지에서 2번이 문단 21째(≈141mm)에서 시작한다 — 칸 경계 147.7mm 와
맞는다. 실물은 같은 자리에서 16~19개를 벌리고 우리는 17~21개다(문항 내용이 다르다).
**실물 한글에서 열린다**(`npm run test:hwpx-opens`).
