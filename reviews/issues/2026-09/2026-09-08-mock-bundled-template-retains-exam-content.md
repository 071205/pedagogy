# 배포용 시험지 틀에 원본 수식과 일부 발문이 남아 있다

## 요약과 영향

`exam-math.hwpx`를 “내용 없는 시험지 틀”로 저장소에 넣었지만, 원본 시험의 수식 스크립트와
일부 한글 발문이 파일 안에 그대로 남아 있다. 변환기가 이 틀을 열어 새 시험지를 만드는 기존
검사는 통과하지만, 저장소에서 직접 배포되는 틀 파일 자체에는 원본 내용이 포함된다. 따라서
이 커밋은 현재 상태로 원격 저장소에 올리면 안 된다.

## 재현 절차

1. `experiments/hwp-export/templates/exam-math.hwpx`를 ZIP으로 연다.
2. `Contents/section0.xml`과 `Contents/section1.xml`의 `hp:script` 및 `hp:t`를 읽는다.
3. 비어 있지 않은 `hp:script`와 채움글자 `가` 이외의 한글이 든 `hp:t`를 센다.
4. `make_exam_template.leftovers()`를 같은 파일에 실행한다.

## 기대 결과 / 실제 결과

- 기대: 배포용 틀에는 조판 구조만 있고 원본 문항의 발문·수식·그림 내용이 없어야 하며,
  잔존 내용 검사가 이를 확인해야 한다.
- 실제: 비어 있지 않은 `hp:script`가 **522개** 남아 있다. 예를 들어
  `f left(x right)=x^{3}-8 x+7`과 극한식 등 원본 수식이 그대로 들어 있다. 채움글자 이외의
  한글이 든 `hp:t`도 **171개**이며, 표제부 외에도 `일 때,`, `의 값을 구하시오.`,
  `는 양수이다.) [4점]` 같은 발문 조각이 남아 있다. 그런데 `leftovers()` 결과는 `[]`이다.

## 근거

- `template.strip_to_frame()`는 `hp:t`의 텍스트만 `_blank_text()`로 바꾸고
  `hp:equation/hp:script`를 처리하지 않는다.
- `_FRAME_IN_RUN`에 해당하는 개체가 하나라도 든 run은 통째로 건너뛴다. 그림·표와 같은
  run에 있던 발문 조각도 이 경로로 남는다.
- `make_exam_template.leftovers()`는 XML 구조를 검사하지 않고 네 문자열
  (`백승우`, `수학능력시험`, `의 값은?`, `huryul`)만 찾으므로 위 잔존 내용을 모두 놓친다.
- 내장 Python으로 HWPX 기능 검사 11건은 모두 통과했다. 즉 생성 기능의 구조 검사는
  정상이나, 현재 검사 묶음에는 **배포용 틀 자체가 무내용인지** 확인하는 검사가 없다.

## 제안 (선택)

- 원본의 모든 `hp:equation/hp:script`를 제거하거나 구조 판정용 최소 수식으로 교체한다.
- 개체가 있는 run도 개체만 보존하고 주변 `hp:t`는 별도로 비운다.
- 특정 금칙어 목록 대신, 허용된 표제부·구조 문구와 최소 자리표시자 외의 텍스트 및 수식이
  없는지를 XML 노드 기준으로 검사한다.
- 정상 틀에 실제 원본 수식이나 발문 한 조각을 심으면 검사가 빨간불이 되는지도 확인한다.

### 2026-09-08 Codex 재검토 — bf107d4, 미해결로 재개

수식 522개가 모두 `1`로 바뀐 것은 독립 확인했다. 그러나 본문 원문이 아직 남아 있으므로
해결 처리를 되돌린다. `strip_to_frame()`와 `leftovers()`가 모두 XML의 `.text`만 읽고,
자식 요소 뒤에 이어지는 `.tail`을 누락한다. 예를 들어
`<hp:t>가가<hp:lineBreak/>카드가 들어 있는 주머니가 있다. …</hp:t>`에서 줄바꿈 뒤
문장은 `hp:t.text`가 아니라 `hp:lineBreak.tail`이다. 수정 함수는 텍스트 노드 처리 후
자식 순회를 생략하며, 검사는 `hp:t`의 `.text`만 합치므로 양쪽 모두 이를 놓친다.

실제 배포용 틀을 ZIP/XML로 다시 읽은 결과:

- `section0.xml`: 한글이 포함된 tail 11곳. `값은? [2점]`, `순서쌍 `, `모든 자연수 ` 등.
- `section1.xml`: 한글이 포함된 tail 32곳. `대한 신뢰도 `,
  `카드가 들어 있는 주머니가 있다. 이 주머니에서 임의로 `,
  `값을 다음 표준정규분포표를 ` 등. 숫자에는 구조 라벨도 포함되며 모두 발문이라는 뜻은 아니다.
- 같은 파일에 `leftovers()`를 실행하면 여전히 `[]`이고,
  `test_template_content.py`도 기존 두 변이 검사를 포함해 전부 통과한다.

재현(저장소 루트, Python 표준 라이브러리만 필요):

```python
import zipfile
import xml.etree.ElementTree as ET
with zipfile.ZipFile('experiments/hwp-export/templates/exam-math.hwpx') as z:
    for name in ('Contents/section0.xml', 'Contents/section1.xml'):
        root = ET.fromstring(z.read(name))
        tails = [e.tail for e in root.iter()
                 if any('가' <= c <= '힣' for c in (e.tail or ''))]
        print(name, len(tails), tails)
```

수정·검증 기준: 생성 시 본문 텍스트의 자식 요소 뒤 tail도 비우고, 검사는 `hp:t.itertext()`
등으로 실제 표시되는 전체 글을 읽어야 한다. 줄바꿈 뒤·탭 뒤에 원문을 각각 심어 실패하는
회귀 검사도 필요하다. 새 틀을 다시 만든 뒤 기존 조판 동일성 검사를 함께 실행할 것.
이번 검토는 제품 코드 변경 없이 같은 이슈와 INDEX만 갱신했다.

## 처리 기록 (2026-09-09 · Claude)

**원인은 '꼬리 글자' 였다.** `<hp:t>값<hp:tab/>은?</hp:t>` 에서 `은?` 은 `<hp:tab>` 의
**tail** 이라 `.text` 에 없다. 지우는 쪽(`strip_to_frame`)도 확인하는 쪽(`leftovers`)도
`.text` 만 읽어 **둘이 함께 놓쳤다** — 그래서 검사가 초록불인 채로 원본 발문 41낱말이
(`값은`·`곡선`·`순서쌍`·`자연수`·`직선`…) 배포용 틀에 남아 있었다.

⚠️ 얄궂게도 같은 저장소의 `XmlNode.text_content()` 는 **이미 이 함정을 주석으로 적어
두고 있었다**("`.text` 만 모으면 안 된다 — 꼬리 글자"). 알고 있던 것을 지우는 코드가
쓰지 못했다.

고친 것 셋:
1. `pedagogy_hwpx.XmlNode` 에 `tail` 게터·세터를 더했다(없어서 못 고치고 있었다).
2. `strip_to_frame()` 이 `<hp:t>` 를 만나면 **글과 그 안의 모든 꼬리를 함께** 지운다.
   ⚠️ 처음엔 형제의 꼬리만 지웠더니 25→23자로 **일부만** 줄었다 — 글이 있는 `<hp:t>`
   안으로 안 들어갔기 때문이다.
3. `leftovers()` 가 `.text + .tail` 을 함께 읽는다.
