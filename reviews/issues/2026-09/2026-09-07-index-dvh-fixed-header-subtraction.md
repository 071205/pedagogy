## 요약과 영향

4단계에서 `vh` 뒤에 `dvh`를 추가했지만 `#mockView`와 `#editorView`의 높이는 여전히
`100dvh - 60px`이다(`index.html:248`, `index.html:254`). 좁은 화면의 `.topbar`는 여러
줄로 접히며 실제 높이가 60px보다 훨씬 커진다. 그 결과 모의고사 iframe의 높이는 새로 보이는
영역에 맞아도 시작점 앞의 상단 바 높이를 잘못 빼서 아래쪽이 뷰포트 밖으로 밀린다.

모의고사 화면은 외부 페이지와 iframe이 동시에 세로로 움직이는 구조가 되고, 바닥을 보려고
바깥 페이지를 스크롤하면 iframe 위쪽이 고정 상단 바 아래로 들어간다. `dvh`를 넣은 목적과
달리 한 화면 안에 편집 영역이 맞지 않는다.

## 재현 절차와 실측

Chromium을 `hasTouch:true`로 열고 모의고사 버튼을 눌러 `.topbar`와 `#mockView`의 실제
사각형을 측정했다.

| 뷰포트 | 상단 바 높이 | 모의고사 높이 | 모의고사 아래쪽 | 전체 세로 넘침 |
| --- | ---: | ---: | ---: | ---: |
| 375×812 | 215px | 752px (=812−60) | 967px | 155px |
| 768×1024 | 165px | 964px (=1024−60) | 1129px | 105px |
| 1024×768 | 113px | 708px (=768−60) | 821px | 53px |

`npm run check:fast`은 이 상태에서 모두 통과했다. 정적 검사는 `vh`와 `dvh`의 존재·순서만
확인하고, 교차 플랫폼 검사는 상단 바와 모의고사 영역 높이의 합을 확인하지 않는다.

## 기대 결과 / 실제 결과

- 기대: 모의고사 영역은 현재 뷰포트 높이에서 **실제 렌더된 상단 바 높이**를 뺀 만큼이고,
  바깥 문서에 불필요한 세로 넘침이 생기지 않는다.
- 실제: 모든 좁은 터치 화면에서 60px만 빼므로 상단 바가 늘어난 만큼 아래로 넘친다.

## 수정·검증 기준

- 고정 `60px` 대신 레이아웃 자체가 남은 공간을 차지하도록 구성하거나, 실제 상단 바 높이를
  신뢰성 있게 반영한다. CSS 전체 페이지 flex 배치처럼 상수 중복이 없는 방식을 우선한다.
- 375×812, 768×1024, 1024×768에서 모의고사 모드 전환 후
  `topbar.height + mockView.height <= innerHeight + 허용오차`를 검사한다.
- 상단 바를 강제로 두 줄 이상 늘렸을 때 검사가 빨간불이 되는 자기검사를 추가한다.
- `#editorView`도 같은 60px 가정을 공유하므로 모바일 전환 탭과 스크롤 정책에 맞춰 별도로
  전체 높이를 확인한다.

## 처리 기록

재현했다. 보고서의 표와 **같은 값**이 나왔다(375×812 에서 215+752=967>812 등).
⚠️ **이 결함은 내가 만든 것이다** — 3단계에서 손가락용 44px 규칙을 넣어 상단 바가
훨씬 높아졌는데, 높이를 빼는 상수 `60px` 은 그대로 뒀다. 4단계에서 `dvh` 를 덧붙일 때도
**상수 자체를 의심하지 않았다.**

- 원인: `#editorView`·`#mockView` 가 `calc(100dvh - 60px)` 로 **상단 바 높이를 상수로**
  들고 있었다. 1280px 밑에서 상단 바는 `height:auto` 로 줄바꿈하는데(그 규칙의 주석에도
  "예전엔 height:60px 고정이라 버튼이 잘렸다" 고 적혀 있다) **높이를 쓰는 쪽만 안 고쳤다.**
- 수정: 보고서 제안대로 **상수를 없앴다.** 문서를 세로 flex 로 만들고
  (`body{display:flex;flex-direction:column}`) 본문이 `flex:1` 로 **남는 만큼** 가진다.
  빼는 값이 아예 없으므로 상단 바가 몇 줄이 되든 어긋나지 않는다.
  ⚠️ `@media print` 에서 `body{display:block}` 으로 되돌린다 — flex 아이템 안에서는
  `page-break-after` 가 제대로 먹지 않는다.
- 검사: `test:cross` 에 **375×812 · 768×1024 · 1024×768** 세 화면에서
  `상단 바 + 본문 ≤ 창 높이` 를 라이브러리·모의고사 두 화면에 대해 본다.
- ⚠️ **깨보기가 두 번 헛돌았다.** ① 상수만 되돌리고 ② 상단 바를 강제로 300px 로 늘려도
  **둘 다 통과**했다 — 새 flex 배치가 `flex-shrink` 로 알아서 맞춰 주기 때문이다.
  **flex 구조와 상수를 함께 되돌려야** 빨간불이 났고, 그때 나온 숫자가 보고서의 표와
  글자까지 같았다. 구조로 고친 것은 **구조를 되돌려야** 깨진다.
- 결과: 회귀 128/128 · `check:fast` · `test:cross` 세 엔진 · `test:visual` 7세트 통과.

세로 flex 구조가 실제 상단 바 높이와 무관하게 남은 공간을 정확히 채우고, 인쇄 규칙에서
`body{display:block}`으로 화면용 flex를 끄는 것도 확인했다. 빠른 전체 검사, 브라우저 회귀
128/128, 인쇄 시각 회귀 7세트가 통과했다. 따라서 이 이슈는 해결된 것으로 확인한다.
