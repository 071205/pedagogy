# 터치 목표 검사가 버튼처럼 쓰는 링크와 문서 편집기 조작을 제외한다

- 보고자: `Codex`
- 상태: `resolved`
- 심각도: `P2`
- 영향 영역: `index`, `document`, `tests`
- 관련 인계: `HANDOFF-2026-056`

## 요약과 영향

3단계는 “보이는 조작 요소를 전부” 44px 이상으로 만들고 검사한다고 기록했지만, 실제 CSS와
검사는 주로 `button`·`select`·`input`만 대상으로 한다. 버튼처럼 쓰는 링크·라벨과 문서
편집기의 조작은 대상 밖이라 손가락용 크기보다 작아도 전체 검사가 통과한다.

사용자가 누르는 요소의 태그가 `button`이 아니라는 이유로 터치 기준에서 빠지면 같은 기능이
화면마다 서로 다른 크기가 된다. 특히 인앱에서 유일한 탈출 경로인 문서 편집기의
`밖에서 열기`도 이번 검사에서는 위치만 확인하고 크기는 확인하지 않는다.

## 재현 절차

Chromium을 `hasTouch:true`, 375×812로 열어 현재 배포 코드의 실제 사각형을 측정했다.

- 본체의 `<a class="btn">AI 문서 β</a>`: `52×21px`
- 문서 편집기의 `#openOutsideBtn`: `89×34px`
- 문서 편집기의 `#loginBtn`: `64×34px`
- 문서 편집기의 `#themeBtn`: `36×36px`

그 상태에서 `npm run check:fast`의 `터치 목표 44px 이상`은 초록불이다.

## 원인

- 손가락용 CSS(`index.html:1092-1107`)는 `button`·`select`·`input`과 일부 클래스만 고른다.
  본체 상단의 `a.btn`, 편집기의 `label.btn` 같은 버튼 역할 요소는 포함하지 않는다.
- 검사(`scripts/check-cross-platform.mjs:174-190`)도 거의 같은 선택자를 써서 CSS와 함께
  같은 대상을 놓친다.
- 문서 편집기 인앱 검사(`scripts/check-cross-platform.mjs:308-347`)는 탈출 버튼이 화면
  안에 있는지만 보고 44px 기준은 적용하지 않는다.

## 기대 결과 / 실제 결과

- 기대: 손가락으로 누르는 모든 실제 조작이 정한 44px 기준을 충족하거나, 예외라면 근거와
  별도 기준이 기록된다. 검사는 태그명이 아니라 실제 조작 가능 요소를 대상으로 한다.
- 실제: 위 요소가 21~36px인데도 터치 검사가 통과한다.

## 수정·검증 기준

- 본체에서 버튼 역할을 하는 `a`·`label` 등 실제 조작 요소를 CSS와 검사에 포함한다.
- 문서 편집기는 다음 반응형 단계에서 별도 터치 검사를 적용하되, 인앱 탈출 버튼은 사용자
  복구 경로이므로 최소한 같은 44px 기준을 즉시 확인한다.
- 44px 미만의 버튼형 링크와 문서 탈출 버튼을 각각 심어 검사가 빨간불이 되는지 확인한다.
- 단순히 CSS 선택자와 검사 선택자를 똑같이 복사하지 말고, 접근 가능한 조작 요소 목록을
  독립적으로 구성해 양쪽이 같은 항목을 함께 놓치지 않게 한다.

## 처리 기록

재현했다. 375px 에서 본체의 `<a class="btn">AI 문서 β</a>` 가 **52×21**, 문서 편집기의
`#openOutsideBtn` 89×34 · `#loginBtn` 64×34 · `#themeBtn` 36×36 인데 검사는 초록불이었다.

- 원인: **CSS 선택자와 검사 선택자가 같은 목록이었다.** 둘 다 `button`·`select`·`input`
  만 골라, 버튼처럼 쓰는 `a`·`label` 을 **함께** 놓쳤다. 우리 목록을 우리 목록으로 검사한
  꼴이고, 보고서의 마지막 항목이 정확히 이 점을 짚었다.
- 수정 ①(검사): **태그가 아니라 동작으로** 고른다 — 의미상 조작 요소이거나 **계산된
  `cursor: pointer`** 인 것. `cursor` 는 CSS 규칙 목록과 무관한 신호라 양쪽이 같은 것을
  함께 빠뜨릴 수 없다. 조상이 이미 조작 요소면 건너뛴다(단추 안의 아이콘·svg·path 가
  `cursor` 를 상속받아 전부 잡히던 것).
  ⚠️ `[tabindex]` 를 통째로 넣었더니 **구글 로그인 SDK 의 1×1 숨김 iframe**(`tabindex="-1"`)
  까지 잡혔다 — **webkit 에서만** 나타났다. `-1` 과 `iframe` 을 뺐다.
- 수정 ②(본체 CSS): `a.btn`·`label.btn`·`[role=button]`·`.brand` 를 44px 대상에 넣었다.
- 수정 ③(문서 편집기): 그 화면에는 **손가락용 규칙이 아예 없었다.** 본체와 같은 44px
  기준의 `@media (pointer: coarse)` 블록을 두었다(`button,.button,select,input,.brand`).
- 수정 ④(검사): 인앱 탈출 단추는 **위치만 보고 크기를 안 봤다.** 44px 판정을 더했다 —
  인앱에서 유일한 복구 경로다.
- 검증: 고치기 전 검사가 `brandBtn 129×33, .btn 52×21` 을 잡는 것을 먼저 확인했다(보고서의
  값과 같다). 고친 뒤 세 엔진 · 두 터치 뷰포트 전부 통과.
  회귀 128/128 · `check:fast` · `test:visual` 7세트 통과.
