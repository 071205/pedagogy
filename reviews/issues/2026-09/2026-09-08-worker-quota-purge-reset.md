# 인증된 사용자가 DELETE로 일일 AI 한도를 초기화할 수 있다

- ID: `REV-2026-031`
- 날짜: `2026-09-08`
- 보고자: `Codex`
- 상태: `resolved`
- 심각도: `P1`
- 영향 영역: `worker`
- 관련 인계: `HANDOFF-2026-066`
- 분석 기준: `cbd951e`의 격리 사본. 2026-09-08 최신 `ae5740e`에서도 같은 결함 재현.
  아래 코드 줄 번호는 최초 분석 기준이며 최신 코드에서는 함수 이름으로 찾는다.

## 요약과 영향

유효한 자기 계정 토큰만 가진 사용자가 같은 날 한도를 반복 초기화해 AI 비용 제한을 무력화할 수 있다. 인증 우회나 다른 사용자 토큰이 필요한 문제가 아니다.

## 재현 절차

로컬 createWorker에 고정된 테스트 사용자 인증과 가짜 AI만 주입하고 실제 DailyQuota를 연결한다. 한도를 1로 두고 같은 사용자로 POST → POST → DELETE → POST를 호출한다.

## 기대 결과 / 실제 결과

- 기대: 일반 사용자 토큰으로 활성 계정의 비용 카운터를 초기화할 수 없게 한다.
- 실제: 응답이 200 → 429 → 204 → 200이며 AI가 두 번 실행된다. 계정은 삭제하지 않았다. DELETE는 계정 삭제 완료나 서버 전용 권한을 확인하지 않고 현재 일자 카운터까지 비운다.

## 근거

`worker/index.js:255` 및 `DailyQuota.fetch()`의 purge 처리. 재현 도구: `reviews/audits/2026-09-08/audit-repro.mjs / QUOTA_RESET`.
인증·DB·AI·Storage 외부 경계는 모의 구현이며 운영 계정·사용자 데이터는 사용하지 않았다.
전체 범위와 제한은 [종합 보고서](../../audits/2026-09-08/REPORT.md)를 참조한다.

## 수정 설계

일반 사용자 토큰으로 활성 계정의 비용 카운터를 초기화할 수 없게 한다. 계정 삭제는 신뢰할 수 있는 백엔드 워크플로에서 시작·완료·재시도를 관리하고, 삭제 진행 계정의 새 AI 요청을 차단한다. 재인증이나 CORS 강화만으로는 이 문제를 해결하지 못한다. 삭제 기록과 비용 제한 상태를 분리하는 대안도 제품 정책과 함께 검토한다.

## 완료 판단에 필요한 검사

한도 도달 → 사용자 DELETE 또는 임의 경로 DELETE → 재호출은 계속 거절. 정상 계정 삭제의 재시도 및 삭제와 AI 호출이 겹치는 경우를 별도 검증.
