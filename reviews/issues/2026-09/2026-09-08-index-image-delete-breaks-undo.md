## 요약과 영향

블록 삭제·이미지 교체를 되돌려도 그림이 깨질 수 있다. Storage 삭제 후 복구 가능성은 운영 버킷 설정에 달려 있으며 현재 클라이언트의 Undo에는 원본 복구 경로가 없다.

## 재현 절차

이미지 블록 삭제 후 실제 releaseImage를 실행하고, Undo에 해당하는 이전 이미지 주소 복원을 수행한다. Storage 삭제는 가짜 구현으로 기록하며 실제 파일을 삭제하지 않는다.

## 기대 결과 / 실제 결과

- 기대: 편집 동작에서 즉시 물리 삭제하지 않고 삭제 후보를 기록한다.
- 실제: 문항에 URL이 복원된 후에도 예약된 삭제가 실행된다. releaseImage는 현재 sets만 검사하고 undo/redo·백업에 남은 참조를 보지 않는다. 히스토리는 이미지 바이트 없이 URL만 저장한다.

## 수정 설계

편집 동작에서 즉시 물리 삭제하지 않고 삭제 후보를 기록한다. 유예 기간과 서버 기준 참조 검사를 둔 GC로 이동하고 복제·다른 기기·Undo·백업 복구 정책을 포함한다. 단순히 현재 탭 undoStack만 검사하는 것은 다른 기기 참조를 해결하지 못한다.

## 완료 판단에 필요한 검사

삭제→Undo→Redo, 이미지 교체 후 Undo, 같은 URL의 복제 문제집, 다른 탭 참조, 백업 복원, 클라우드 저장 실패 중 삭제를 확인한다.
