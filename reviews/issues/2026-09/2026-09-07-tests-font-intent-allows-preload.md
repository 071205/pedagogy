# 글꼴 의도 검사가 부팅 중 최대 두 벌의 대용량 글꼴을 허용한다

- ID: `REV-2026-029`
- 날짜: `2026-09-07`
- 보고자: `Codex`
- 상태: `resolved`
- 심각도: `P2`
- 영향 영역: `tests`, `index`
- 관련 인계: `HANDOFF-2026-058`

## 요약과 영향

5단계의 핵심 목표는 인쇄하지 않는 방문자에게 인쇄용 글꼴 파일을 내려보내지 않는 것이다.
하지만 `runFontIntent()`는 URL에 `font-kopub|KoPubBatang|KaTeX_`가 들어간 모든 응답을 한
숫자로 세고, 인쇄 의도 전 요청이 3건 이하이면 통과시킨다
(`scripts/check-cross-platform.mjs:336-356`).

현재 정상적인 1건은 `font-kopub` CSS이고 실제 글꼴 파일은 아니다. 이 허용치를 요청 종류와
무관하게 3까지 열어 두었기 때문에, 약 2.5MB인 KoPub WOFF 두 벌이 부팅 중 다시 내려가도
`CSS 1 + WOFF 2 = 3`으로 “방문만 하면 인쇄용 글꼴을 받지 않는다” 검사가 초록불이다.
5단계가 제거한 낭비의 상당 부분(약 5MB)이 되돌아와도 회귀가 잡히지 않는다.

## 재현 근거

현재 독립 실측에서 인쇄 의도 전 응답은 아래 CSS 1건뿐이었다.

```text
https://cdn.jsdelivr.net/npm/font-kopub@1.0/kopubbatang.min.css
```

인쇄 의도 뒤에는 `KoPubBatang-Light.woff`, `Medium.woff`, `Bold.woff`와 KaTeX WOFF2가
추가됐다. 현재 판정식에 다음 값을 대입하면 두 항목이 모두 통과한다.

- 방문 전: CSS 1건 + KoPub WOFF 2건 = `3`; `3 <= 3` → 통과
- 인쇄 의도 뒤: 나머지 글꼴이 추가돼 `18`; `18 > 3 + 5` → 통과

즉 약 5MB를 미리 받아도 검사 출력은 정상과 같다.

## 기대 결과 / 실제 결과

- 기대: 인쇄 의도 전에는 실제 `font` 리소스가 0건이어야 하고, CSS처럼 글꼴 정의만 담은
  스타일시트는 별도로 취급한다.
- 실제: 응답 URL만 한데 세어 실제 글꼴 파일 두 벌까지 허용한다.

## 수정·검증 기준

- `response.request().resourceType()==="font"` 또는 확장자·정확한 URL 분류로 실제 글꼴
  파일을 별도로 세고, 인쇄 의도 전에는 0건을 요구한다.
- 인쇄 의도 뒤에는 KoPub 300·400·700과 필요한 KaTeX 글꼴이 시작됐는지 확인한다.
- 부팅 때 KoPub WOFF 한 벌과 두 벌을 각각 강제로 받게 해 검사가 모두 빨간불인지 확인한다.
- 단순 요청 건수뿐 아니라 가능하면 전송량도 기록해 성능 목표가 회귀했을 때 원인을 바로
  알 수 있게 한다.

## 처리 기록

지적이 맞다. 정상값 1건은 **CSS** 였고 실제 글꼴은 0건이므로, 허용치 3은
**2.5MB 짜리 WOFF 두 벌(≈5MB)** 을 통과시켰다.

- 수정: URL 로 뭉뚱그려 세던 것을 브라우저가 알려 주는
  **`response.request().resourceType()==="font"`** 로 바꿔 **실제 글꼴 파일만** 세고,
  인쇄 의도 전에는 **0건**을 요구한다. 전송량도 함께 찍는다.
  인쇄 의도 뒤에는 **KoPub 세 굵기(Light·Medium·Bold)** 를 이름으로 확인한다 —
  건수만 보면 어느 벌이 빠졌는지 모른다. KaTeX 도 따로 본다.
- ⚠️ 처음 고쳤을 때 **화면 글꼴 Pretendard(서브셋 10개 0.25MB)** 가 걸려 빨간불이 났다.
  그건 부팅 때 받는 것이 **맞다** — 여기서 묻는 것은 '인쇄용' 글꼴이다.
  `resourceType` 위에 KoPub·KaTeX 만 고르고, Pretendard 는 정보로만 찍는다.
- 검증: 요구대로 **한 벌·두 벌을 각각 부팅 때 받게 해** 확인했다.
  · 한 벌 → `❌ 1개 · 2.52MB (KoPubBatang-Light.woff)`
  · 두 벌 → `❌ 2개 · 5.14MB (KoPubBatang-Light.woff, KoPubBatang-Bold.woff)`
  정상 상태의 출력: `인쇄용 글꼴 — 방문만 0MB / 인쇄 의도 뒤 7.83MB · 화면 글꼴 0.25MB`
