# Firestore 가 선지 `cells`(중첩 배열)를 거부해 문제집 클라우드 저장이 통째로 막힌다

- ID: `REV-2026-098`
- 날짜: `2026-09-21`
- 보고자: `Claude / Opus 5`(사용자 신고에서 출발 — 화면에 `⚠ 저장 실패`)
- 상태: `in-progress`
- 심각도: **`P1`** — 사용자에게 도달하는 저장 실패다
- 영향 영역: `index.html`, `pedagogy-normalize.js`
- 관련: `HANDOFF-2026-156`(B1 크기 방어 — **같은 증상, 다른 원인**)

## 요약과 영향

**Firestore 는 배열 안에 배열을 저장하지 못한다.** 그런데 선지 블록의 `cells` 는
`string[][]` 다. 그런 문제집이 하나라도 저장 묶음에 끼면 **그 batch 가 통째로 거절되어
같이 올라가던 멀쩡한 문제집까지 못 올라간다.**

사용자 계정에서 실제로 일어나고 있었다 — 배포본 화면에 `⚠ 저장 실패` 가 떠 있었다.

⚠️ **두 갈래다. 두 번째가 더 크다.**

| | 증상 | 범위 |
|---|---|---|
| (가) **흔적** | `layout` 은 `horizontal` 인데 `cells` 가 남아 있다 | 사용자에게서 실제로 발생 |
| (나) **기능 자체** | `layout:"paired"` 는 **항상** `cells:string[][]` 를 만든다 | ⚠️ **짝 배치를 쓰는 문제집은 애초에 클라우드 저장이 불가능하다** |

(나)는 `layout:"paired"`(`HANDOFF-2026-103`·`-111`)가 들어온 뒤로 **한 번도 클라우드에
저장된 적이 없다**는 뜻이다. 기존 클라우드에 `cells` 가 든 문서는 있을 수 없다(전부 거절됐다) —
**이관할 옛 데이터가 없다.**

## 재현 절차

1. 아무 문항의 선지 블록에서 배치를 **`짝 (A)(B)`** 로 바꾼다 → `data.cells` 가 생긴다.
2. (가) 를 재현하려면 배치를 **`5열`** 로 되돌린다. (나)는 짝인 채로 둔다.
3. 로그인 상태에서 저장을 기다린다.

## ② 저장 경로에 **모양 가드** — 먼저 할 것 (작고, 즉시 값이 있다)

**목표**: Firestore 가 못 받는 문서가 섞여도 **그것만 빠지고 나머지는 올라간다.**
B1 이 크기에 대해 한 것을 **모양**으로 넓히는 것이다.

**자리**: `index.html` 의 `writeCloudSnapshot()` — B1 이 만든 `ready`/`tooBig` 분리 **그 줄**.
크기 판정 바로 옆에서 같은 이유로 본다. **다른 곳에 두지 말 것**(근거는 계약 §1-1).

**할 일**
1. `docBytes()` 옆(같은 관심사: '이 문서가 Firestore 로 갈 수 있는가')에 헬퍼를 둔다.
   중첩 배열의 **첫 위치를 경로 문자열로** 돌려주고, 없으면 빈 문자열.
   배열 안의 배열만 찾으면 된다(객체 안의 배열은 정상이다).
2. `dirty` 를 `ready` / `tooBig` / `badShape` 로 가른다. **`ready` 만 batch 에 넣는다.**
3. `badShape` 는 **문제집 이름과 찾은 경로**를 함께 말한다. ⚠️ 조용히 빠뜨리면 사용자는
   계정에 있다고 믿는다. 문구는 `tooBig` 의 것과 같은 결로 —
   "…이 기기에는 저장돼 있습니다" 를 반드시 넣는다.
4. ⚠️ **재시도 조건에서 빼야 한다.** B1 의 `oversize` Set 과 같은 이유다 —
   빼지 않으면 `flushToCloud` 가 **끝없이 자기를 다시 부른다**. `tooBig` 과 합쳐
   하나의 '건너뛴 것' 집합으로 다루는 편이 낫다.
5. ⚠️ **초과본을 `cloudSynced` 로 표시하지 않는다**(B1 과 같다).
6. **반복 토스트 억제**도 B1 의 `setsOversizeKey` 와 같은 방식으로.

**검사** — `scripts/check-sets-cloud-size.mjs` 를 **그대로 늘린다**(새 파일 만들지 말 것).
그 하네스가 이미 가짜 Firestore·가짜 토스트를 갖고 있다.
- 중첩 배열이 든 문제집 + 정상 문제집을 섞어 → **정상만 batch 에 들어간다**
- 토스트가 **문제집 이름**을 말한다
- `flushToCloud` 재호출 **0회**
- `cloudSynced` 에 **정상만** 들어간다
- ⚠️ **깨보기**: 가드를 지우면 빨간불이 나야 한다. `SETS_SIZE_RED=1` 이 옛 커밋을
  서빙하는 방식을 그대로 쓰면 된다.

## ③ `paired` 를 클라우드에 저장 가능하게 — ②보다 큼

**목표**: `layout:"paired"` 문제집도 클라우드에 저장된다.

⚠️ **화면·조판 쪽 모델(`cells:string[][]`)을 바꾸지 말 것.** `HANDOFF-2026-111` 이 그 모양을
고른 이유가 있다(구분자 이스케이프보다 낫다). 렌더·편집기·HWPX 내보내기·파이썬 사본까지
번진다.

▶ **권하는 방향: 전송 경계에서만 바꾼다.** `setToDoc()`(쓰기) ↔ `docToSet()`(읽기) 가
이미 그 경계다. 거기서만 Firestore 가 받는 모양으로 바꿨다 되돌린다.
- 예: `cells:[["a","b"],["c","d"]]` → **평평한 배열** `cellsFlat:["a","b","c","d"]`.
  `pairs` 가 이미 블록에 있으므로 읽을 때 그것으로 끊으면 복원된다. **중첩이 아예 없다.**
- ⚠️ `docToSet` 은 `lossless:true` 로 기존 자료를 보존하는 **복구 경로**다. 거기서
  **자르거나 버리면 안 된다**(계약 §1-1 과 같은 이유).

⚠️ **확인된 사실 — 이관할 옛 데이터가 없다.** `cells` 가 든 문서는 전부 거절됐으므로
클라우드에 존재할 수 없다. 단방향 전환으로 충분하다.
⚠️ **Rules 는 건드릴 필요가 없다.** `hasOnly` 는 문제집 문서의 **최상위 키만** 본다
(`firestore.rules:54` · 코덱스가 §15-2 에서 확인). `cells` 는 `problems[]` 안쪽이다.

**검사**
- 짝 배치 문제집이 실제로 batch 에 들어가고, **읽어 되돌리면 `cells` 가 원래대로**인지
  (왕복 대조). `scripts/check-sets-cloud-size.mjs` 또는 `check-audit-safety.mjs` 의
  `setToDoc`/`docToSet` 샌드박스가 자리다.
- ⚠️ ②의 모양 가드가 **짝 배치를 더 이상 걸러내지 않는지**도 함께 본다(③이 되면 통과해야 한다).

## 하지 말 것

- ⚠️ **`cells` 를 `items` 에 `|` 로 도로 합치지 말 것** — 낱말에 `|` 가 들어가면 깨진다
  (코덱스가 이미 기각했다 · `HANDOFF-2026-111` §2).
- ⚠️ **②를 건너뛰고 ③만 하지 말 것.** ②가 없으면 **다음에 또 다른 모양**이 같은 방식으로
  저장 전체를 죽인다. ②는 원인이 아니라 **폭발 반경**을 막는 것이다.
