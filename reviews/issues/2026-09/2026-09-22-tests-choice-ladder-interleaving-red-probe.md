# 선지 사다리 검사가 요소별 읽기·쓰기 교차를 놓친다

- ID: `REV-2026-107`
- 날짜: `2026-09-22`
- 보고자: `Codex / Sol medium`
- 상태: `resolved`
- 심각도: `P2`
- 영향 영역: `tests`
- 관련 인계: `HANDOFF-2026-163`

## 요약과 영향

R4.5 계약은 선지 사다리의 단계별 일괄 읽기·쓰기를 요소별 읽기→쓰기로 되돌리면 회귀 검사가
실패해야 한다고 명시한다. 그러나 현재 추가된 네 검사는 최종 배치와 잘림만 확인하며 실행
순서를 관찰하지 않는다. 실제 코드를 요소별 사다리 루프로 바꿔도 `test:audit-browser`가
`162/162`로 통과했다.

현재 `index.html` 구현은 계약대로 단계별 일괄 처리되어 있다. 문제는 이후 리팩터링이 과거의
300문항 약 1.6초 경로를 되살려도 자동 검사가 막지 못하고, 이번 인계가 필수 깨보기를 통과한
것처럼 기록했다는 점이다.

## 재현 절차

1. `index.html`의 `fitPrintDoc()` 사다리 루프를 임시 응답에서만 바꾼다. 배치별로 모든 블록을
   읽고 쓰는 현재 루프 대신, 각 `.choices` 블록을 잡아 그 블록 하나를
   `horizontal→cols3→cols2→vertical` 끝까지 읽고 쓰게 한다.
2. CSP가 임시 변형 응답을 막지 않도록 그 응답에서만 CSP 메타를 제거하고
   `regression-test.html`을 Chromium으로 실행한다.
3. 실패 목록과 전체 검사 수를 확인한다.

재현용 임시 스크립트는 실행 뒤 삭제했으며 저장소 파일은 바꾸지 않았다.

  검출하는 검사가 적어도 하나 실패해야 한다.

## 근거

- `tests/regression-test.html:834-960`의 새 네 검사는 잘림 0, 3열 유지, 비상향, 단일 클래스만
  확인한다. 레이아웃 읽기와 클래스 쓰기의 순서는 계측하지 않는다.
- `reviews/issues/2026-09/2026-09-22-print-choice-overflow-guard-measures-wrong-element.md`의 검사 6은
  요소별 루프로 되돌렸을 때 읽기·쓰기 교차 검사가 빨간불이어야 한다고 명시한다.
- 독립 검토의 정상 실행은 `npm run test:audit-browser` 162/162 통과였다. 같은 하네스에 요소별
  루프를 주입한 실행도 실패 0건이었다.

## 제안 (선택)

실제 `fitPrintDoc()`을 실행하면서 `scrollWidth`/`clientWidth` 읽기와 배치 클래스 변경 순서를
관찰하거나, 사다리 실행부를 작은 주입 가능 함수로 분리해 이벤트 순서를 단언한다. 시간 임계값
하나만으로 판정하지 말고 구조 깨보기가 정확히 그 단언을 실패시키는지도 확인한다.
