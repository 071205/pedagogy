# Codex 와 왕복하기

계약은 [`CLAUDE.md`](../../../CLAUDE.md) 의 'Claude → Codex 협업' 절이 정답표다. **거기부터 읽는다.**
이 스킬은 그 계약을 **어떻게 밟는가**와, 2026-09-20~21 에 값을 치르고 알아낸 것들이다.

⚠️ **한 에이전트만 구현하고 다른 쪽이 검토한다.** 설계를 같이 하고 구현을 혼자 하는 것은
계약대로다 — 다만 **구현 뒤 검토를 받는 것까지가 계약**이다. 핸드오프만 써 두고 넘어가지 말 것.

## ⓪ **먼저 역할을 고른다** — 누가 설계하고 누가 구현하고 누가 검토하나

계약은 `CLAUDE.md` 의 '누가 주도하고 누가 검토하는가' 표가 정답표다. 요약 —

| 이 일이 | 이렇게 간다 |
|---|---|
| **저위험**(UX·인쇄 외형·문구·화면 조율) | Claude 설계·구현 → **Codex 검토** |
| **고위험 불변조건**(인증·권한·데이터 손실·저장/병합·동시성·멱등성·스키마) | **Codex 가 1차에 불변조건과 실패 모델을 먼저 판정** → 구현자 한 명 → **비구현자 검토** |

⚠️ **검토자는 반드시 구현하지 않은 쪽이다.** Codex 가 구현했으면 **내가** 코드·diff·검사를
직접 본다 — Codex 에게 자기 구현을 다시 검토시키면 독립성이 사라진다.
⚠️ **연속 레일의 구현자를 중간에 바꾸지 않는다.** 지금 R4/B1~B3 저장 레일은 **Codex** 다.
⚠️ Codex 구현을 고르는 기준 세 가지(전부 만족해야 한다)는 `CLAUDE.md` 에 있다.
**"백엔드라서" 는 기준이 아니다.**

## ① 경로를 고른다 — **기본은 래퍼다**

| | **`scripts/ask-codex-readonly.mjs` 래퍼** | `codex:codex-rescue` 서브에이전트 |
|---|---|---|
| 언제 | **일반 협업의 기본 경로**(설계 판정·독립 검토는 거의 다 이쪽) | **보안·데이터 손실·최종 아키텍처 게이트**의 `--effort high` |
| 내 컨텍스트에 실리는 양 | **최종 답변 파일 하나**(4.9~9.2KB 실측) | **74,145 토큰**(한 왕복 실측) |

| **사용자가 직접 치는 `/codex:review`·`/codex:adversarial-review`** | **보조 최종 게이트**(아래) |

⚠️ **비용이 150배 갈린다.** 그래서 기본이 래퍼다 — 서브에이전트를 습관처럼 쓰지 말 것.
⚠️ **"독립 검토는 거의 다 래퍼" 는 내가 구현한 변경에 한한다.** Codex 가 구현한 변경의
검토자는 **나**다(위 ⓪).

### 보조 게이트 — 내가 못 부른다. 사용자에게 **권해야** 한다

⚠️ 둘 다 `disable-model-invocation: true` 라 **Claude 가 호출할 수 없다**(실제로 확인했다).
`/codex:adversarial-review` 는 결함이 아니라 **"이 방향 자체가 맞는가" 를 공격**한다 —
래퍼 검토와 역할이 다르다. 권하는 조건과 `--wait` 강제는 `CLAUDE.md` 에 있다.
⚠️ 사용자가 친 것도 실제 모델 호출이다(비용이 든다).
⚠️ 같은 범위를 래퍼가 이미 검토했으면 **권하지 않는다**(중복).
⚠️ **raw `codex exec` 는 PreToolUse 훅이 차단한다.** 우회하지 말 것 — 예전에 그렇게 써서
4분에 282KB 혼합 로그를 만들었고, 그래서 훅이 생겼다.
⚠️ **background 금지 · foreground 로 부른다.** 실제 Codex 턴은 `interrupted` 인데 Bash 대기만
남은 사례가 있었다. 긴 검토는 **질문 1~2개씩 여러 번**으로 쪼갠다.

### 호출 횟수 — 제한 없음 (2026-09-24 해리 결정)

예전의 '사용자 한 턴 합산 3회' 는 **폐지됐다.** 필요한 만큼 왕복한다. 다만 비용은 그대로 든다:
- 매 왕복은 **새로 남은 이견과 필요한 근거만** 보낸다. 합의한 것을 다시 논하지 않는다.
- 각 왕복은 `합의 / 미합의 / 근거 / 다음 행동`으로 닫는다.
- Codex에게 Claude를 다시 부르라고 시키지 않는다(중첩 호출 금지). Claude가 답을 **검증한 뒤** 후속 질문한다.
- 상대가 usage limit 에 걸리면 재시도로 풀리지 않는다 — 시각을 알리고 멈춘다.

```bash
node scripts/ask-codex-readonly.mjs \
  --prompt /private/tmp/pedagogy-codex/ask.txt \
  --output /private/tmp/pedagogy-codex/final.md \
  --progress /private/tmp/pedagogy-codex/progress.log \
  --model gpt-5.6-sol --effort medium \
  --timeout-seconds 600
```
모델·effort는 레일 배정을 따른다. 위는 일반 독립 검토 예시이고 설계 판정은
`--model gpt-6-astra --effort high` 등으로 바꾼다. 성공하면 **`final.md`와 진행 로그의
`model:`·`reasoning effort:` 실행 메타데이터만 읽는다.** 나머지 진행 로그는 실패했을 때만 본다.

## ② 첫 질문을 짠다 — 이 스킬의 핵심

**문서를 옮겨 적지 않는다. 파일을 지목한다.** Codex 는 저장소를 읽을 수 있다.

```
READ-ONLY. 파일을 만들거나 고치거나 커밋하지 마라. 판정만 답해라.

# 단계            ← 지금 무엇의 어느 칸인가 (레일 단계·이슈 ID)
# 읽을 파일 (이것만)   ← 경로 목록. 5~6개를 넘기지 않는다
# 확정된 입력       ← 이미 정해진 것. 다시 논하지 말라고 못박는다
# 미결 쟁점        ← 한 문단
# 완료 조건        ← 무엇이 고정되면 이 칸이 닫히는가
# 질문 (1~2개만)
# 형식
각 질문에 **동의/부분 동의/반대**를 먼저 쓰고 **파일:줄**로 근거를 대라.
마지막에 **합의 / 미합의 / 근거 / 다음 행동** 네 줄로 닫아라.
```

⚠️ **질문을 5개 넣으면 138,763 토큰이 나간다**(실측). 2개면 84k~95k 다.
⚠️ **내가 모르는 사실을 프롬프트에 단정하지 말 것.** `docBytes` 가 어디 있는지 확인도 없이
적었다가 Codex 가 첫 줄에서 바로잡았다 — **먼저 `grep` 하고 쓴다.**
⚠️ **내 의심을 함께 적는다.** "나는 A 라고 보는데 맞나" 가 "A 인가" 보다 훨씬 나은 답을 받는다.
틀렸을 때 **어디가 틀렸는지**를 짚어 주기 때문이다.

## ③ 2회차부터 — **새로 남은 이견만**

⚠️ 합의한 것과 문서 전체를 **다시 보내지 않는다.** 1차 합의는 **한 줄로** 언급하고
"그 합의는 다시 논하지 않는다" 라고 못박는다.

## ④ 답을 받으면 — **검증하고 보고한다**

⚠️ **Codex 의 주장을 그대로 옮기지 말 것.** [`reviews/README.md`](../../../reviews/README.md) 가
요구하는 것이기도 하고,
실제로 값을 한다 — 하루에 양쪽이 서로의 오류를 **여섯 번** 잡았다.

1. **근거로 댄 `파일:줄` 을 직접 열어 본다.** 특히 내 판단과 **다른** 곳.
2. 내 주장이 깨졌으면 **기록을 고친다**(지우지 말고 "틀렸다" 로 표시한다).
3. 사용자에게는 **동의/반대와 그 이유**를 갈라서 보고한다.

## ⑤ 어디에 적나

| 무엇 | 어디 |
|---|---|
| 설계 판정·논박 | 그 주제의 `docs/*-DESIGN.md` 나 계약 문서에 **절을 더한다** |
| 단계 현황 | [`docs/DEV-TOKEN-ROADMAP.md`](../../../docs/DEV-TOKEN-ROADMAP.md) 의 '현재 위치' |
| 이번 왕복이 한 일 | [`reviews/handoffs/`](../../../reviews/handoffs) — **일회용이다** |
| 다시 알아내는 값이 큰 사실 | `docs/` 나 `CLAUDE.md` — **오래 사는 곳** |

## ⑥ 하지 않는 것 — 밖에서 흔히 보이지만 우리는 안 한다

| 밖의 방식 | 우리가 안 하는 이유 |
|---|---|
| 공식 **Stop review gate**(`--enable-review-gate`) | `decision:"block"` 으로 **종료를 실제로 막는다**(`stop-review-gate-hook.mjs:169`). 이 저장소의 훅은 **막지 않고 알리기만** 한다. 기본값이 꺼짐이므로 **켜지 않는 것**이 결정이다 |
| **Codex 4개 병렬 fan-out** | 같은 판단이 넷으로 갈라져 합치는 비용이 더 크다 |
| 멀티 에이전트 파이프라인 | "한 에이전트로 값어치를 증명하기 전에 다단 조율에 투자하지 말 것" — 우리는 래퍼 한 경로로 이미 값을 보고 있다 |
| 자동 fix→review 반복 루프 | 검증 없이 Codex 말을 따르게 된다. ④ 가 요구하는 **근거 확인**이 사라진다 |

## 마무리

⚠️ 왕복이 길어지면 질문이 잘못 쪼개진 것일 수 있다. 매 왕복마다 새
핸드오프를 만들지 말고, 최종 합의·재현 결함·다음 세션 상태만 한 번 기록한다.

## 겪은 함정들 — 되돌리지 말 것

- ⚠️ **Codex 도 사용량 한도에 걸린다.** `You've hit your usage limit ... try again at HH:MM` 가
  나오면 **재시도하지 않는다**(한도는 재시도로 안 풀린다). 사용자에게 시각을 알리고 멈춘다.
- ⚠️ **진행 로그와 최종 답변을 한 파일로 합치지 말 것.** 래퍼가 갈라 주는 이유가 있다 —
  합치면 수백 KB 가 컨텍스트로 들어온다.
- ⚠️ **프롬프트를 인자로 넘기지 말 것**(`codex exec "$(cat ...)"`). stdin 대기에 걸린다.
  래퍼가 stdin 으로 보내고 즉시 닫는다.
- ⚠️ **"부분 동의" 를 "동의" 로 읽지 말 것.** 오늘 네 번 중 세 번이 부분 동의였고, 단서에
  실제 결정이 들어 있었다("배치" 가 Gemini Batch API 가 아니라는 것 등).
- ⚠️ **Codex 가 내 전제를 깨면 그게 최고의 산출물이다.** 억지로 방어하지 말 것 —
  오늘 `firestore.rules` `hasOnly`·`users/{uid}` 소유권·토큰 감소 원인 셋이 그렇게 뒤집혔다.
